## 1. 壁打ち（Phase 0）の詳細

### 5W1H + 制約テンプレート

| 観点 | 質問 | 回答 |
|------|------|------|
| Who | 誰が使う？ |  |
| What | 何ができる？ |  |
| Why | なぜ必要？現状の課題は？ |  |
| Where | どのシステム・画面に関わる？ |  |
| When | いつ使う？トリガーは？ |  |
| How | 既存のどの技術・テーブルと関わる？ |  |
| **Constraints** | **やらないこと・制約条件** |  |

### 壁打ちの姿勢

**やること:**
- ユーザーの発言を整理し、構造化して返す
- 「なぜそう思うか」を掘り下げる問いを投げる
- 「こういう方法もありますが、どう思いますか？」と代替案を提示する
- 壁打ちの途中経過をこまめに整理する
- 最後に「漏れている観点はありますか？」を自問する

**やらないこと:**
- ユーザーに代わって判断を下す
- 壁打ちの全体を一度に進めようとする（1ステップずつ進める）
- 実装の詳細に踏み込みすぎる（この段階では全体像を把握することに集中）

## 2. ユビキタス言語整理（Phase 1）の詳細

### 2層構造

| 層 | ファイル | スコープ |
|---|---------|---------|
| core | `docs/ubiquitous_language_core.md` | プロジェクト横断。全コンテキストで同じ意味の用語 |
| コンテキスト固有 | `docs/ubiquitous_language.md` | 各プロジェクト内。コンテキスト固有の用語 |

### 用語定義のフォーマット

7カテゴリに分類する:

1. **エンティティ**: IDで識別、ライフサイクルを持つ
2. **バリューオブジェクト**: 値で同一性を判断、不変
3. **アクション**: 業務上の操作・処理
4. **ステータス**: 業務上の状態
5. **ロール**: 役割・権限
6. **外部システム・連携先**: 連携する外部システム
7. **業界専門用語**: 業界固有の用語

各用語に定義すべき項目:
- 正式名称（日本語）
- 英語名（PascalCase）
- 定義（1〜3文）
- 構成要素（バリューオブジェクトのみ: 型、単位、値域）
- 使用しない表現
- 境界コンテキスト
- 補足

### ID採番ルール

- エンティティ: E-001, E-002, ...
- バリューオブジェクト: V-001, V-002, ...
- アクション: A-001, A-002, ...
- ステータス: S-001, S-002, ...
- ロール: R-001, R-002, ...
- 外部システム: SYS-001, SYS-002, ...
- 業界専門用語: T-001, T-002, ...

## 4. Design Level Event Storming（Phase 2.5）の詳細

### イベントストーミングの構成要素

| 要素 | 色（付箋） | 意味 | 表現形式 |
|------|----------|------|---------|
| ドメインイベント | オレンジ | 業務上起きた出来事 | 過去形（「〜された」「〜が完了した」） |
| コマンド | 青 | イベントを引き起こすアクション | 命令形（「〜する」） |
| アクター | 黄（小） | コマンドを実行する人・ロール | 名詞（「担当者」「管理者」） |
| 集約 | 黄（大） | コマンドを受けて処理するまとまり | 名詞（「注文」「在庫」） |
| ポリシー | 紫 | イベントに反応する自動処理 | 「〜の場合、〜する」 |
| 外部システム | ピンク | 連携する外部システム | システム名 |

### イベントフロー図のフォーマット

```
[アクター] → (コマンド) → [集約] → <<ドメインイベント>>
                                        ↓
                                   {ポリシー}
                                        ↓
                                   (次のコマンド) → ...
```
