# ドメイン層 分析ガイド

## Entity の判定と分析

### 判定基準（優先順）
1. `IAggregateRoot` / `IEntity` インターフェースを実装している
2. `Id` / `*Id` プロパティを持つ `class`
3. クラス名がビジネス概念の名詞（例: `InventoryItem`, `Product`, `Warehouse`）

### 抽出する情報
```
- クラス名（= エンティティ名）
- プロパティ: 名前・型・アクセシビリティ
- コンストラクタ: 引数（= 生成に必要な情報）
- パブリックメソッド: ビジネスルールのシグネチャ
- privateセッター: 不変条件の有無
- 継承元 / 実装インターフェース
```

---

## Value Object の判定と分析

### 判定基準（優先順）
1. `readonly struct` + `IEquatable<T>` 実装（このプロジェクトの標準パターン）
2. `record` / `record struct`
3. 値同士の比較が意味を持つ小さなオブジェクト（例: `AreaNo`, `ProductCode`）

### 抽出する情報
```
- 型名（= Value Objectの概念名）
- 内包する値の型・名前（例: string Value, int Number）
- バリデーション: コンストラクタ内のガード節
- 用途: どのEntityやUseCaseで使われているか
```

---

## Domain Service の判定と分析

### 判定基準
- `*Service` サフィックス かつ ドメイン層フォルダに存在
- 複数のEntityにまたがるビジネスルールを持つ
- `static` メソッドを持つ場合も多い

### 抽出する情報
```
- クラス名
- 各パブリックメソッドの責務（1〜2行の概要）
- 依存している Entity / Value Object
```

---

## Specification の判定と分析

### 判定基準
- `*Specification` サフィックス
- `IsSatisfiedBy(T entity)` メソッドを持つ
- ビジネスルールの判定条件をカプセル化

### 抽出する情報
```
- 仕様名
- 判定条件の説明（コメントまたはメソッド名から推測）
- どのユースケースで使われるか
```

## よくある命名パターンと対応

| C# クラス名パターン | ドメイン概念 |
|---|---|
| `*Entity` | エンティティ（明示的） |
| `*Vo` / `*ValueObject` | バリューオブジェクト（明示的） |
| `*Aggregate` | 集約ルート |
| `*Factory` | ファクトリ（生成の複雑さを隠蔽） |
| `*Policy` / `*Rule` | ドメインポリシー |
| `*Converter` / `*Mapper` | ドメイン → インフラ変換（インフラ層寄り） |
| `I*Repository` | リポジトリインターフェース（ドメイン定義） |

## アノテーション読み取り

`[DataAnnotations]` 等があれば制約の手がかりになる：

| アノテーション | 意味 |
|---|---|
| `[Required]` | 必須項目 |
| `[MaxLength(n)]` | 最大文字数制約 |
| `[Range(min, max)]` | 数値範囲制約 |
| `[RegularExpression]` | フォーマット制約 |

---

## 分析時の注意点

- **`[推定]` タグ**: コードから意図を推測した箇所に必ず付与
- **`[要確認]` タグ**: ビジネスルールが不明確な箇所に付与
- **コメント優先**: XMLドキュメントコメント（`///`）があれば最優先で採用
- **テストから逆引き**: ドメインに対応するテストクラスがあれば読んで補完する
