# スキルテスト手順書

## 目的

作成したスキルが意図通りに動作するかを検証するための標準手順。
新規スキル作成時・スキル修正時にこの手順に従ってテストを実施する。

---

## 1. テスト準備

### 1.1 スキルの配置

スキルファイルをClaude Codeのプロジェクトに配置する。

```
.claude/skills/{skill-name}/
├── SKILL.md
└── references/（ある場合）
    └── *.md
```

### 1.2 テストプロンプトの作成

各スキルに対して、以下の4種類のテストプロンプトを最低各2つ用意する。

| 種類 | 目的 | 例 |
|------|------|-----|
| **正常トリガー** | 意図したプロンプトでスキルが起動するか | 「SDDで開発して」 |
| **類似トリガー** | 言い換えや曖昧な表現でも起動するか | 「壁打ちから始めたい」 |
| **非トリガー** | 関係ないプロンプトでは起動しないか | 「バグを直して」 |
| **境界ケース** | 複数スキルが競合しうるプロンプトで正しい方が起動するか | 「設計のレビューをして」 |

### 1.3 テストプロンプトの記録フォーマット

```markdown
# スキルテスト: {skill-name}

テスト日: YYYY/MM/DD
テスト者:
スキルバージョン:

## テストプロンプト一覧

| # | 種類 | プロンプト | 期待結果 | 実際結果 | 判定 |
|---|------|----------|---------|---------|------|
| 1 | 正常トリガー | | スキルが起動する | | |
| 2 | 正常トリガー | | スキルが起動する | | |
| 3 | 類似トリガー | | スキルが起動する | | |
| 4 | 類似トリガー | | スキルが起動する | | |
| 5 | 非トリガー | | スキルが起動しない | | |
| 6 | 非トリガー | | スキルが起動しない | | |
| 7 | 境界ケース | | 正しいスキルが起動する | | |
| 8 | 境界ケース | | 正しいスキルが起動する | | |
```

## 2. テスト実施

### 2.1 Phase 1: トリガーテスト

**目的**: スキルが正しいプロンプトで起動し、誤ったプロンプトでは起動しないことを確認する。

**手順**:

1. Claude Codeを起動する
2. テストプロンプトを1つずつ入力する
3. 以下を確認する:
   - [ ] 正常トリガーのプロンプトでスキルが起動するか
   - [ ] 類似トリガーのプロンプトでもスキルが起動するか
   - [ ] 非トリガーのプロンプトではスキルが起動しないか
   - [ ] 境界ケースで正しいスキルが起動するか
4. 結果を記録する

**判定基準**:
- 正常トリガー: 100%起動 → PASS
- 類似トリガー: 80%以上起動 → PASS
- 非トリガー: 0%起動 → PASS
- 境界ケース: 正しいスキルが起動 → PASS

**問題が発生した場合**:
- トリガーされない → SKILL.mdのdescriptionを修正する
- 誤ったスキルがトリガーされる → 競合するスキルのdescriptionを修正する
- Skill Creatorのdescription最適化を検討する

### 2.2 Phase 2: reference読み込みテスト

**目的**: SKILL.mdからreferenceファイルが正しく読み込まれることを確認する。

**対象**: references/フォルダを持つスキルのみ

**手順**:

1. referenceの読み込みが必要な状況を作るプロンプトを入力する
   - 例（implement-review-l1）: 「Swiftプロジェクトの実装レビューをお願い」
2. 以下を確認する:
   - [ ] 正しいreferenceファイルが読み込まれるか（例: swift-rules.md）
   - [ ] 誤ったreferenceファイルが読み込まれないか（例: django-rules.md）
   - [ ] referenceの内容がレビュー結果に反映されているか
3. 結果を記録する

**判定基準**:
- 正しいreferenceが選択される → PASS
- referenceの内容が出力に反映される → PASS

### 2.3 Phase 3: 出力品質テスト

**目的**: スキルの出力が期待通りのフォーマット・内容であることを確認する。

**手順**:

1. スキルを実際の（または模擬的な）入力データで実行する
2. 以下を確認する:

**フォーマットの確認**:
- [ ] 出力形式がSKILL.mdで定義されたフォーマットに沿っているか
- [ ] テーブル、見出し、セクション構成が正しいか
- [ ] レビュー系スキルの場合: サマリー、検出事項一覧、総合判定が含まれるか

**内容の確認**:
- [ ] チェック項目がすべて検査されているか（漏れがないか）
- [ ] OK/警告/NGの判定が妥当か
- [ ] 修正案が具体的で実行可能か
- [ ] ユビキタス言語集を参照している場合、正しく照合されているか

**プロセスの確認**:
- [ ] 関連文書（strategic_design.md、ubiquitous_language.md等）を読み込んでいるか
- [ ] 承認ゲートで止まるべきところで止まるか（SDDスキルの場合）
- [ ] 次のステップへの案内が含まれているか

3. 結果を記録する

**判定基準**:
- フォーマットが正しい → PASS
- チェック項目に漏れがない → PASS
- 判定が妥当 → PASS

### 2.4 Phase 4: エッジケーステスト

**目的**: 異常な入力や想定外の状況でスキルが適切に振る舞うことを確認する。

**テストケース**:

| # | ケース | 期待される振る舞い |
|---|--------|------------------|
| 1 | 引数なしでスキルを実行 | ユーザーに対象ファイルを質問する |
| 2 | 存在しないファイルパスを指定 | エラーを報告し、正しいパスを質問する |
| 3 | strategic_design.mdが存在しない | 該当する観点をスキップし、その旨を記載する |
| 4 | ubiquitous_language.mdが存在しない | 用語チェックをスキップし、その旨を記載する |
| 5 | 対象ファイルが空 | レビュー不可の旨を報告する |
| 6 | 非常に長いファイルを指定 | 重要な部分を優先してレビューする |

## 4. 問題発生時の対応

### 4.1 トリガーの問題

| 問題 | 原因 | 対応 |
|------|------|------|
| スキルが起動しない | descriptionのキーワード不足 | descriptionにトリガーワードを追加 |
| 誤ったスキルが起動 | descriptionが他のスキルと曖昧に重複 | descriptionを具体化して区別を明確にする |
| 毎回起動してしまう | descriptionが広すぎる | 「〜の場合は使用しない」を追加 |

### 4.2 reference読み込みの問題

| 問題 | 原因 | 対応 |
|------|------|------|
| referenceが読み込まれない | SKILL.mdにReadの指示がない | 「Read ツールで読み取ること」の指示を追加 |
| 誤ったreferenceが選択される | 判断ロジックが不明確 | CLAUDE.mdの技術スタックとの照合方法を明記 |
| referenceのパスが見つからない | パスの記述が誤っている | 相対パスを確認し修正 |

### 4.3 出力品質の問題

| 問題 | 原因 | 対応 |
|------|------|------|
| フォーマットが崩れる | SKILL.mdの出力形式の記述が曖昧 | 具体的なテーブルフォーマットを明記 |
| チェック項目が漏れる | チェックリストが不完全 | 漏れた項目を追加 |
| 判定が不適切 | 判定基準が曖昧 | NG/警告/OKの基準を具体化 |

## 5. Skill Creatorによるdescription最適化（オプション）

トリガーテスト（Phase 1）で問題が発生した場合に実施する。

### 5.1 前提条件

- Claude Code CLIが利用可能であること（`claude -p` コマンド）

### 5.2 手順

1. トリガー評価セットを作成する:

```json
{
  "queries": [
    {"text": "SDDで開発して", "should_trigger": true},
    {"text": "スペック駆動開発で進めて", "should_trigger": true},
    {"text": "壁打ちから始めたい", "should_trigger": true},
    {"text": "バグを修正して", "should_trigger": false},
    {"text": "コードを書いて", "should_trigger": false},
    {"text": "設計レビューをして", "should_trigger": false}
  ]
}
```

2. 最適化ループを実行する:

```bash
python -m scripts.run_loop \
  --eval-set trigger-eval.json \
  --skill-path .claude/skills/{skill-name} \
  --max-iterations 5 \
  --verbose
```

3. 結果の `best_description` でSKILL.mdのdescriptionを更新する

### 5.3 注意点

- description最適化はトリガーの精度のみを改善する。スキルの中身の品質は手動テストで確認する
- 最適化後に再度Phase 1のトリガーテストを実施して改善を確認する

## 7. テスト実施の推奨タイミング

| タイミング | 実施するPhase |
|-----------|-------------|
| スキル新規作成時 | Phase 1〜4 すべて |
| スキルのdescription修正時 | Phase 1（トリガーテスト）のみ |
| スキルの本体修正時 | Phase 3（出力品質テスト） |
| referenceの追加・修正時 | Phase 2（reference読み込みテスト） |
| 他のスキルを追加した時 | Phase 1の境界ケース（競合チェック） |
