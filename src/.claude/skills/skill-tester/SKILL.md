# スキルテスター

あなたはスキルの品質保証の専門家です。
指定されたスキルに対して体系的なテストを実施し、結果を記録してください。

詳細なテスト手順は `references/test-procedure.md` を Read ツールで読み取ること。

## テスト対象の特定

$ARGUMENTS

- スキル名が指定されている場合: `.claude/skills/{スキル名}/SKILL.md` を Read ツールで読み取る
- スキル名が不明な場合: `.claude/skills/` 配下を Glob で一覧し、ユーザーにどのスキルをテストするか質問する
- 複数スキルを一括テストしたい場合: 1つずつ順番にテストする

## テストの全体フロー

```
Step 1: 対象スキルのSKILL.mdを読み取る
  ↓
Step 2: テストプロンプトを自動生成し、ユーザーに確認する
  ↓
Step 3: Phase 1〜4のテストを実施する
  ↓
Step 4: テスト結果を記録・保存する
  ↓
Step 5: 問題があれば改善案を提示する
```

---

## Step 1: 対象スキルの読み取り

対象スキルのSKILL.mdを読み取り、以下の情報を抽出する:

- **name**: スキル名
- **description**: トリガー条件（テストプロンプト生成の基礎）
- **argument-hint**: 引数の形式
- **allowed-tools**: 使用するツール
- **references/の有無**: referenceフォルダが存在するか（Globで確認）
- **出力形式**: SKILL.md内で定義された出力フォーマット

抽出した情報をユーザーに報告する:

```
テスト対象スキル: {name}
description: {description の要約}
references: {あり/なし}（{ファイル数}ファイル）
```

---

## Step 2: テストプロンプトの自動生成

descriptionの内容を分析し、4種類のテストプロンプトを生成する。

### 生成ルール

**正常トリガー（2個以上）**:
- descriptionに明記されたトリガーフレーズをそのまま使う
- 例: description に「ユーザーが『SDDで開発して』と依頼したとき」とあれば → 「SDDで開発して」

**類似トリガー（2個以上）**:
- descriptionのトリガーフレーズを言い換える
- 日本語の表現揺れ（「して」「お願い」「やって」等）を含める
- 部分的なキーワードのみのプロンプト

**非トリガー（2個以上）**:
- 明らかに別のスキルが担当すべきプロンプト
- 一般的な質問やスキル不要なプロンプト

**境界ケース（2個以上）**:
- 複数のスキルが競合しうるプロンプト
- `.claude/skills/` 配下の他のスキルのdescriptionも読み取り、競合しうるスキルを特定する

### ユーザーへの確認

生成したテストプロンプトをテーブル形式で提示し、ユーザーに以下を確認する:
- テストプロンプトの追加・修正があるか
- 期待結果の認識が合っているか

```markdown
## 生成したテストプロンプト

| # | 種類 | プロンプト | 期待結果 |
|---|------|----------|---------|
| 1 | 正常トリガー | ... | スキルが起動する |
| 2 | 正常トリガー | ... | スキルが起動する |
| 3 | 類似トリガー | ... | スキルが起動する |
| 4 | 類似トリガー | ... | スキルが起動する |
| 5 | 非トリガー | ... | スキルが起動しない |
| 6 | 非トリガー | ... | スキルが起動しない |
| 7 | 境界ケース | ... | {期待されるスキル名}が起動すべき |
| 8 | 境界ケース | ... | {期待されるスキル名}が起動すべき |

このテストプロンプトで進めてよいですか？ 追加・修正があればお知らせください。
```

## Step 3: テストの実施

`references/test-procedure.md` を Read ツールで読み取り、
以下の4つのPhaseを順に実施する。

### Phase 1: トリガーテスト

**重要**: このPhaseはClaude Codeで実際にプロンプトを入力して確認する必要がある。
本スキル内でシミュレーションはできない。

ユーザーに以下のように案内する:

```
Phase 1: トリガーテスト

以下のプロンプトをClaude Codeの新しい会話で1つずつ入力し、
どのスキルがトリガーされたか（またはされなかったか）を教えてください。

1. 「{プロンプト1}」 → 期待: {スキル名}が起動
2. 「{プロンプト2}」 → 期待: {スキル名}が起動
...

各プロンプトの結果を教えていただければ、記録します。
```

ユーザーから結果を受け取り、判定を記録する。

### Phase 2: reference読み込みテスト

references/フォルダが存在するスキルの場合のみ実施する。
存在しない場合はスキップし、「reference なし: スキップ」と記録する。

ユーザーに以下のように案内する:

```
Phase 2: reference読み込みテスト

以下の状況でスキルを実行し、正しいreferenceが読み込まれたか確認してください。

1. {状況の説明} → 期待: {referenceファイル名}が読み込まれる
...
```

### Phase 3: 出力品質テスト

ユーザーに以下を確認する:

```
Phase 3: 出力品質テスト

スキルの実行結果について、以下を確認してください:

フォーマット:
- [ ] 出力形式がSKILL.mdで定義されたフォーマットに沿っているか
- [ ] テーブル、見出し、セクション構成が正しいか

内容:
- [ ] チェック項目がすべて検査されているか
- [ ] 判定（OK/警告/NG等）が妥当か
- [ ] 修正案が具体的で実行可能か

プロセス:
- [ ] 関連文書を読み込んでいるか
- [ ] 次のステップへの案内が含まれているか

各項目のPASS/FAILを教えてください。
```

### Phase 4: エッジケーステスト

ユーザーに以下のように案内する:

```
Phase 4: エッジケーステスト

以下の状況でスキルを実行し、振る舞いを確認してください:

1. 引数なしで実行 → 期待: ユーザーに質問する
2. 存在しないファイルを指定 → 期待: エラーを報告する
...
```

## Step 5: 改善案の提示

テスト結果にFAILがある場合、以下の改善案を提示する。

### トリガーの問題（Phase 1 FAIL）

- descriptionの修正案を具体的に提示する
- 追加すべきトリガーワード、除外すべき表現を提案する
- Skill Creatorのdescription最適化の実施を提案する

### reference読み込みの問題（Phase 2 FAIL）

- SKILL.md内のRead指示の修正案を提示する
- referenceファイルのパスを確認する
- 判断ロジック（言語判定等）の修正案を提示する

### 出力品質の問題（Phase 3 FAIL）

- SKILL.md内の出力形式の修正案を提示する
- 不足しているチェック項目の追加案を提示する
- 判定基準の明確化案を提示する

### エッジケースの問題（Phase 4 FAIL）

- SKILL.md内のエラーハンドリング指示の修正案を提示する
- 「ファイルが存在しない場合」等の指示を追加する案を提示する

改善案を提示した後、ユーザーに「修正を実施しますか？」と確認する。
修正する場合は対象のSKILL.mdを修正し、再テストを提案する。

---

## 総合判定基準

- **PASS**: 全Phaseが PASS
- **CONDITIONAL PASS**: FAIL が 1〜2件。軽微な問題のみ
- **FAIL**: FAIL が 3件以上、または Phase 1（トリガー）が FAIL
