# CLAUDE.md 生成スキル

プロジェクト固有のCLAUDE.mdをテンプレートから生成する。

## 重要な前提

**CLAUDE.mdは一度に完成させるものではなく、プロジェクトの進行とともに段階的に育てるもの。**

```
Step1: プロジェクト開始時 → Project Overview + 開発環境の最低限の情報
Step2: 戦略的設計の後 → strategic_design.md への参照を追加
Step3: 最初の機能の設計後 → アーキテクチャの要点・依存方向の禁止事項を追加
Step4: 最初の機能の実装後 → 実践で確認された命名規則・規約の要点を追加
Step5: 以降、開発を重ねるたびに更新
```

## テンプレートの構成

`references/claude-md-template.md` を Read ツールで読み取ること。

テンプレートは以下の構成を持つ:

```
1. Project Overview              ← プロジェクト依存（ユーザーが記入）
2. プロジェクト固有の設定          ← プロジェクト依存（最小限の要点のみ。段階的に育てる）
   ─────────────────────────
3. 絶対ルール                     ← プロジェクト非依存（テンプレートのまま。変更禁止）
4. SDD（スペック駆動開発）ルール    ← プロジェクト非依存（テンプレートのまま。変更禁止）
5. Task Documentation            ← プロジェクト非依存（テンプレートのまま。変更禁止）
```

**セクション3〜5はテンプレートの内容をそのまま使用する。一切変更しないこと。**

## 動作フロー

### 状況の判断

$ARGUMENTS を確認し、以下のどのパターンかを判断する:

**パターンA: 新規プロジェクト（CLAUDE.mdが存在しない）**
→ テンプレートからセクション1を埋めて生成する

**パターンB: 既存プロジェクトの移行（CLAUDE.mdが既にある）**
→ 既存CLAUDE.mdからセクション1-2の情報を抽出し、テンプレートに統合する

**パターンC: 既存CLAUDE.mdの更新（プロジェクト進行中）**
→ 現在のステップ（Step1〜5）を確認し、追記すべき内容をガイドする

---

### パターンA: 新規プロジェクト

1. `references/claude-md-template.md` を Read ツールで読み取る（存在しない場合は「エラーハンドリング」の節を参照）
2. Dockerファイルやその他の設定ファイルより技術スタック（言語、フレームワーク、DB等）を取得する。
   - 設定ファイルが見つからない、または情報が不足している場合は、取得できなかった旨を伝えた上でユーザーに直接技術スタックを質問する
3. ユーザーに以下を質問する:
   - 「プロジェクト名と概要を教えてください」
   - 取得した技術スタックを表示して「使用する技術スタック（言語、フレームワーク、DB等）は正しいですか？」
   - 「関連する外部システムはありますか？」
4. 回答をもとにセクション1（Project Overview）を埋める
5. セクション2はコメントのみの状態で残す（まだ書くことがないため）
6. セクション3〜5はテンプレートのまま
7. ユーザーに確認し、承認後にファイルを保存する

**セクション2について**: 「プロジェクト固有の設定は、開発が進むにつれて追記していきます。最初の機能の設計・実装が完了した段階で、アーキテクチャや命名規則の要点を追加することを推奨します。」とユーザーに伝える。

---

### パターンB: 既存プロジェクトの移行

1. `references/claude-md-template.md` を Read ツールで読み取る（存在しない場合は「エラーハンドリング」の節を参照）
2. $ARGUMENTS で指定された既存CLAUDE.mdのパスを Glob ツールで確認する
   - ファイルが存在しない場合: 指定パスが見つからない旨を報告し、正しいパスをユーザーに確認する。推測で処理を進めない
3. 既存のCLAUDE.mdを Read ツールで読み取る
4. 既存CLAUDE.mdから以下の情報を抽出する:
   - Project Overview（プロジェクト名、概要、技術スタック、関連システム）
   - プロジェクト固有のクリティカルなルール（依存方向の禁止事項等）
5. 抽出した情報をテンプレートのセクション1-2に埋める
6. セクション2には**最小限の要点のみ**（3〜5行程度）を記載する:
   - 既存CLAUDE.mdにアーキテクチャの依存方向が書いてあれば → 要点として記載
   - 既存CLAUDE.mdにimport禁止ルールがあれば → 要点として記載
   - 既存CLAUDE.mdにTDD採用が書いてあれば → 要点として記載
   - 詳細な命名規則・コーディング規約・開発コマンドは → セクション2には書かない
7. セクション3〜5はテンプレートのまま
8. ユーザーに以下を確認する:
   - 「既存CLAUDE.mdから以下の情報を抽出しました。過不足はありますか？」
   - 「詳細な命名規則・コーディング規約はCLAUDE.mdには含めず、設計レビュースキルのreferenceとして管理することを推奨します。よろしいですか？」
9. 承認後にファイルを保存する

**既存CLAUDE.mdから移行しない情報**:
以下の情報は設計レビュースキル（design-review-l1/l3）のreferenceとして管理すべきもの。CLAUDE.mdには含めない:
- 詳細なアーキテクチャ定義（フォルダ構成等）
- 詳細な命名規則テーブル
- 詳細なコーディング規約（docstring書式、import規約、ログ出力規約等）
- 開発コマンドの詳細

これらの情報を移行したい場合は、ユーザーに「これらの詳細ルールを設計レビュースキルのreferenceとして保存しますか？」と提案する。

---

### パターンC: 既存CLAUDE.mdの更新

1. 現在のCLAUDE.mdを Read ツールで読み取る
2. セクション2の現在の状態を確認し、どのStepにいるか判断する:
   - セクション2がコメントのみ → Step1（プロジェクト開始直後）
   - Project Overviewのみ → Step2へ進むべき
   - アーキテクチャの要点あり → Step4へ進むべき
   - 命名規則・規約の要点あり → Step5（継続改善フェーズ）
3. 現在のStepに基づき、追記すべき内容をガイドする

**ガイドの例**:

Step2の場合:
「戦略的設計が完了していれば、`docs/strategic_design.md` への参照をセクション2に追加しましょう。」

Step3の場合:
「最初の機能の設計が完了したので、アーキテクチャの要点を追記しましょう。例: 依存方向の禁止事項（3行程度）」

Step4の場合:
「最初の機能の実装が完了したので、実践で確認された命名規則の要点を追記しましょう。」

---

## チェックリスト

生成・更新後、以下を確認すること:

- [ ] セクション1（Project Overview）がプロジェクトに合っている
- [ ] セクション2（プロジェクト固有の設定）が最小限の要点のみになっている（3〜5行以内）
- [ ] セクション3（絶対ルール）がテンプレートから変更されていない
- [ ] セクション4（SDDルール）がテンプレートから変更されていない
- [ ] セクション5（Task Documentation）がテンプレートから変更されていない
- [ ] 改善ログの日付が正しい

## エラーハンドリング

以下の異常系では、推測で処理を進めず、必ずユーザーに報告して指示を仰ぐ。

| 状況 | 対応 |
|------|------|
| `references/claude-md-template.md` が見つからない | 「テンプレートファイルが見つかりません。スキルのインストールが壊れている可能性があります」と報告し、処理を停止する |
| $ARGUMENTS で指定されたCLAUDE.mdが存在しない | 「指定されたパス `{path}` にファイルがありません。正しいパスを教えてください」と質問する |
| Dockerfile等の設定ファイルから技術スタックが取得できない | 取得できなかった旨を伝えたうえで、ユーザーに技術スタック（言語、フレームワーク、DB、アーキテクチャ）を直接質問する |
| 既存のCLAUDE.mdが空、または壊れている | 「既存ファイルから情報を抽出できませんでした。新規プロジェクト扱い（パターンA）で進めてよいですか？」と確認する |

## 生成後のイメージ（パターンA）

パターンAで生成されるCLAUDE.mdは、おおむね以下のような状態になる:

- **セクション1（Project Overview）**: ユーザー回答に基づきプロジェクト名・概要・技術スタック表・関連システムが記入されている
- **セクション2（プロジェクト固有の設定）**: コメント行のみ。「段階的に育てる」旨のコメントが残る
- **セクション3〜5**: テンプレートそのまま（1文字も変更されていない）
- **改善ログ**: 1行目に「初版作成」「テンプレートから新規生成（Step1）」が記録されている

パターンBでは、セクション2に既存CLAUDE.mdから抽出した3〜5行の要点が追記されている点だけがパターンAと異なる。

## 保存

- 保存先: プロジェクトルートの `CLAUDE.md`
- 既存ファイルがある場合: 「上書きしますか？ バックアップを作成しますか？」と確認する
- バックアップ: `cp CLAUDE.md CLAUDE.md.backup.{YYYY-MM-DD}`
