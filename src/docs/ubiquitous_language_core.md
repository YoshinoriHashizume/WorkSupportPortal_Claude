# ユビキタス言語集

文書ID: UL-CORE-2026-001
作成日: 2026-07-21
更新日: 2026-07-30
対応文書: [アプリケーション仕様書.md](../../Document/アプリケーション仕様書.md)（SPEC-APP-2026-001）、[ドメイン駆動設計.md](../../Document/ドメイン駆動設計.md)

本書は WorkSupportPortal（業務支援ポータル）における業務用語の **定義と表記の正** である。
コードの命名・画面表示・仕様書の記述は本書に従う。**「使用しない表現」は文書・UI・コードのいずれでも使わない。**

### 「使用しない表現」の適用範囲

「使用しない表現」は **業務用語として用いる場合** を禁止する。同一の語が業務概念と無関係な技術用語として現れる場合は対象外とし、対象外である旨を各用語の **適用範囲** に明記する。判断に迷う場合は「その語を業務担当者が業務の話として使うか」を基準とする。

初版は [アプリケーション仕様書.md](../../Document/アプリケーション仕様書.md) のL1レビューで抽出した用語を収録する。各アプリ固有の用語は `src/application/{app_name}/docs/ubiquitous_language.md`（コンテキスト固有言語集）に定義する。本書には **2 つ以上の境界コンテキストで共有する用語のみ** を置く。

## 1. エンティティ

### E-001: 利用申請

- **英語名**: `UserAccessRequest`
- **定義**: 初回ログインで作成されたユーザーが、ポータルの利用許可を得るために登録される申請。管理者が権限ロールとメニューグループを指定して許可または拒否する。
- **使用しない表現**: 「アクセス申請」「利用登録」「承認リクエスト」
- **境界コンテキスト**: アイデンティティ／アクセス
- **補足**: 拒否時も削除せず、申請状態を保持する（監査・再申請のため）。アプリケーション仕様書 `REQ-F-012`〜`REQ-F-014`。

### E-002: お気に入りメニュー

- **英語名**: `UserFavoriteMenu`
- **定義**: ログインユーザーが自分用に登録したメニューへのショートカット。ユーザー、メニューキー、表示順を保持し、メニュー画面にカード形式で表示される。
- **使用しない表現**: 「ブックマーク」「ショートカット」「マイメニュー」
- **境界コンテキスト**: 全社（ポータル基盤）
- **補足**: アプリケーション仕様書 7.5、`REQ-F-024`・`REQ-F-025`。

### E-003: お知らせ

- **英語名**: `PortalNotice`
- **定義**: 管理者が登録する運用メッセージ。タイトル・本文・公開状態を持ち、公開中のもののみメニュー画面に作成日時の降順で表示される。
- **使用しない表現**: 「通知」「アナウンス」「掲示」
- **境界コンテキスト**: 全社（ポータル基盤）

### E-004: スナップショット

- **英語名**: `SummarySnapshot`
- **定義**: 取込時または更新実行時に集計結果を凍結して保存したデータ。一覧表示はスナップショットを参照し、基幹 Oracle への都度問い合わせを行わない。
- **使用しない表現**: 「キャッシュ」「集計結果テーブル」「サマリ」（単独で用いる場合）
- **適用範囲**: 集計結果の保存を指す場合に限る。以下は **対象外**。
  - HTTP レスポンス・ブラウザ・Django セッションによる一時保持を指す「キャッシュ」（例: 資産棚卸結果の突合結果セッション保持）。ただし集計結果の凍結保存であれば「突合結果スナップショット」等と表記する
  - 複合語としての「件数サマリ」「サマリ行」（画面上の集計表示を指す UI 用語）
- **境界コンテキスト**: 生産管理（在庫発注アラート）、営業（出荷トレンド一覧）、総務（資産棚卸結果）
- **補足**: 複数アプリ横断で使用する概念。実装は `InventoryOrderAlertSummarySnapshot`・`ShipmentTrendSummarySnapshot` など、アプリごとに別モデルとして持つ。

## 2. バリューオブジェクト

### V-001: 社員番号

- **英語名**: `EmployeeNumber`
- **定義**: 社内利用者を一意に識別する番号。ポータルにおける **ユーザー同一性の正** であり、Django ユーザーの `username` に一致する。
- **構成要素**: 文字列。desknet's NEO のログイン ID と同一。
- **使用しない表現**: 「社員コード」「ユーザーID」「従業員番号」
- **境界コンテキスト**: 全コンテキスト（core）
- **補足**: 認証基盤を desknet's NEO から Microsoft Entra ID へ切り替えても、社員番号による紐づけを継続する（`REQ-F-004`・`REQ-F-006`）。

### V-002: メニューグループ

- **英語名**: `MenuGroup`
- **定義**: 左メニュー第1階層の単位であり、かつユーザーに割り当てる **利用権限の単位**。全社・人事・総務・財務・営業・生産管理・品保・管理の 8 区分。
- **構成要素**: `group_key`（英語キー）と表示名の対。`company` / `hr` / `general-affairs` / `finance` / `sales` / `production` / `quality` / `management`。
- **使用しない表現**: **「部門区分」「権限グループ」「部署グループ」「部署」**（いずれも過去版で混在した表記）
- **境界コンテキスト**: 全コンテキスト（core）
- **補足**: 権限ロール（R-001・R-002）とは **別軸** である。実装は `PortalMenuGroupAccess`。`group_key` は英語キーを正とし、旧データの日本語タイトルは読み取り時に正規化する。アプリケーション仕様書 7.2・7.4、`REQ-F-011`。

### V-003: 比較基準年

- **英語名**: `BaselineFiscalYear`
- **定義**: 出荷トレンド一覧において、変動数・変動率を算出する際の比較元となる暦年。既定はデータ初年度（自動）で、得意先×内作品番ごとに手動で上書きできる。
- **構成要素**: 4 桁の暦年（整数）。候補は出荷実績のある暦年かつ集計基準年以下。
- **使用しない表現**: 「初年度」（手動設定された場合はデータ初年度（V-007）と一致しないため）、「基準年度」
- **境界コンテキスト**: 営業（出荷トレンド一覧）
- **補足**: 手動設定は **全ユーザー共通** で、「自動（データ初年度）に戻す」で自動へ復帰する。既定値は データ初年度（V-007）。実装は `ShipmentTrendBaselineYear`。

### V-004: 得意先

- **英語名**: `Customer`
- **定義**: 出荷・検収の相手先となる取引先。基幹 Oracle の得意先マスタ（`M_CUST`）を正とする。
- **構成要素**: 得意先コードと得意先名。**得意先コードに桁数制約はない**（基幹 Oracle の得意先マスタ `M_CUST.CUST_CD` の値をそのまま用いる）。
- **使用しない表現**: **「客先」「取引先」**（いずれも過去版で混在した表記。ただし「購買取引先」「子取引先」は別概念として存続する）
- **境界コンテキスト**: 生産管理（5年9組・検収書比較）、営業（出荷トレンド一覧）
- **補足**: 本用語は改称が繰り返された経緯があり（アプリケーション仕様書 13 章 版1.32〜1.54）、表記の統一を特に厳格に扱う。
  検収書比較の支給品で用いる **子取引先** コードは **4 桁**（`M_VEND_CTRL.VEND_CD`。実装 `receipt_comparison/infrastructure/oracle/client.py` の `^\d{4}$` 判定）。得意先コード自体に桁数制約を課してはならない。

### V-005: 得意先品番

- **英語名**: `CustomerItemCode`
- **定義**: 得意先が採番し、得意先との受発注・出荷・受領のやり取りに用いる品番。基幹 Oracle の `T_SHIP.CUST_ITEM_CD` / `M_CUST_ITEM.CUST_ITEM_CD` を正とする。
- **構成要素**: 文字列。TRIM 後の値で突合する。
- **使用しない表現**: **「得意先品目」「品番」（単独）「客先品番」**（いずれも過去版で混在した表記）
- **適用範囲**: 「品番」（単独）の禁止は、**本用語または 内作品番（V-006）のいずれかを指す語として業務用語で用いる場合** に限る。以下は **対象外**。
  - **外部データの列名・項目名**（受領書 CSV の `品番` 列、SLIMS 在庫 CSV の `WSHOCD`、desknet's の `生産品番⑧コード` 等）。取込元の名称をそのまま記述する
  - **どちらを指すかが比較区分・処理経路で変わるため単一の正式名称が存在しない場合の総称**。この場合は各コンテキスト固有言語集で総称として定義し、実体の対応表を必ず併記する（例: 検収書比較 UL-RECEIPT-COMPARISON-2026-001 V-106「品番」＝完成品は本用語、支給品は内作品番）
- **境界コンテキスト**: 全コンテキスト（core）
- **補足**: 社内で採番する品番は 内作品番（V-006）として区別する。SLIMS 在庫 CSV の商品コード（`WSHOCD`）は本用語と完全一致で突合する。

### V-006: 内作品番

- **英語名**: `InternalItemCode`
- **定義**: 社内で採番する品番。BOM 展開・入荷実績の参照キーとなる。得意先品番（V-005）から `M_CUST_ITEM` を経由して解決する。
- **構成要素**: 文字列（`ITEM_CD`）。
- **使用しない表現**: 「社内品番」「自社品番」「naisaku」
- **境界コンテキスト**: 生産管理（5年9組・在庫発注アラート）、営業（出荷トレンド一覧）
- **補足**: 解決規則は VBA `NAISAK_GET` 準拠（複数行時は最終行の `ITEM_CD` を採用）。解決できない場合は `NAISAK_NOT_FOUND` として扱う。

### V-007: データ初年度

- **英語名**: `DataFirstFiscalYear`
- **定義**: 当該得意先×内作品番で **最初に出荷があった暦年**。自動算出であり変更できない。比較基準年（V-003）の既定値となる。
- **構成要素**: 4 桁の暦年（整数）。
- **使用しない表現**: **「初年度」（単独）**（比較基準年と混同するため、必ず「データ初年度」と表記する）
- **境界コンテキスト**: 営業（出荷トレンド一覧）
- **補足**: 比較基準年が手動設定されている場合、データ初年度とは一致しない。両者を区別せず「初年度」と呼んではならない。

### V-008: 基準日

- **英語名**: `AsOfDate`
- **定義**: マスタの有効期間判定・BOM 展開・集計の基準となる日付。**どの日付を基準日とするかは境界コンテキストごとに異なる** ため、各コンテキスト固有言語集で決定方法を定義する。
- **構成要素**: 日付（`yyyy/mm/dd`）。コンテキストごとの呼称と決定方法は次のとおり。

  | コンテキスト | 呼称 | 決定方法 |
  |---|---|---|
  | 生産管理（5年9組） | **対象日付** | 利用者が画面で指定する（既定は当日） |
  | 生産管理（在庫発注アラート） | **BOM 基準日** | SLIMS 在庫 CSV の取込日（サーバ暦日）。スナップショットに固定保存する |
  | 営業（出荷トレンド一覧） | **集計基準日** | データ更新の実行日（サーバ暦日）。スナップショットに固定保存する |

- **使用しない表現**: 「as of 日付」「基準年月日」
- **適用範囲**: **本用語名「基準日」は上表の3呼称をまとめる抽象概念の総称であり、本項および用語集の対応表でのみ用いる。** 個々の仕様書・画面・コードで具体的な日付を指すときは、必ず上表のコンテキスト呼称（対象日付／BOM 基準日／集計基準日）を用いる。「基準日」を単独で具体的な日付の意味で用いてはならない。
- **境界コンテキスト**: 全コンテキスト（core）
- **補足**: 呼称が3通りに分かれているのは決定方法が異なるためであり、統一しない。ただし **同一の抽象概念** であることを本項で明示する。集計基準年（T-002）は集計基準日が属する暦年である。

## 3. アクション

### A-001: 許可

- **英語名**: `Approve`
- **定義**: 管理者が利用申請に対し、権限ロールとメニューグループを指定して利用を認めること。
- **使用しない表現**: 「承認」「認可」（認可は認可制御そのものを指すため区別する）
- **境界コンテキスト**: アイデンティティ／アクセス

### A-002: 拒否

- **英語名**: `Reject`
- **定義**: 管理者が利用申請を却下すること。ユーザーと申請は削除せず、付与済みメニューグループを外して申請状態を保持する。
- **使用しない表現**: 「却下」「否認」
- **境界コンテキスト**: アイデンティティ／アクセス

### A-003: データ更新

- **英語名**: `Refresh`
- **定義**: 基幹 Oracle または取込ファイルから集計し直し、スナップショット（E-004）を作り直すこと。
- **使用しない表現**: 「再集計」「リフレッシュ」「同期」
- **適用範囲**: 集計のやり直しを指す場合に限る。**URL クエリ・DOM・ブラウザ表示を現在の状態に合わせて書き換えることを指す「同期」は対象外**（例: `history.replaceState` による URL 同期）。
- **境界コンテキスト**: 生産管理（在庫発注アラート）、営業（出荷トレンド一覧）

## 4. ステータス

### S-001: 申請状態

- **英語名**: `AccessRequestStatus`
- **定義**: 利用申請（E-001）が取り得る状態。**承認待ち** / **許可** / **拒否** の 3 値。
- **構成要素**: `PENDING`（承認待ち）/ `APPROVED`（許可）/ `REJECTED`（拒否）
- **使用しない表現**: 「未承認」「保留」「承認済み」
- **境界コンテキスト**: アイデンティティ／アクセス
- **補足**: 承認待ち・拒否のユーザーは業務メニューを利用できず、利用申請状況画面のみ表示する（`REQ-F-017`）。

## 5. ロール

### R-001: 管理者

- **英語名**: `Administrator`
- **定義**: 全メニューを表示・利用でき、利用申請の許可／拒否、ユーザー管理、お知らせ管理、データベース参照を行える権限ロール。
- **使用しない表現**: 「アドミン」「システム管理者」「特権ユーザー」
- **境界コンテキスト**: 全コンテキスト（core）
- **補足**: Django 標準の `auth_group` で管理する。管理者はメニューグループの指定を要しない。

### R-002: 一般ユーザー

- **英語名**: `GeneralUser`
- **定義**: 付与されたメニューグループに一致する業務メニューのみを表示・利用できる権限ロール。管理メニューは表示しない。
- **使用しない表現**: 「通常ユーザー」「一般社員」「利用者」（利用者は不特定を指す語として区別する）
- **境界コンテキスト**: 全コンテキスト（core）

### R-003: 権限ロール

- **英語名**: `PermissionRole`
- **定義**: 管理者（R-001）／一般ユーザー（R-002）の 2 値からなる権限の軸。メニューグループ（V-002）とは独立している。
- **使用しない表現**: **「権限」「ロール」**（単独で用いず、必ず「権限ロール」と表記する）
- **適用範囲**: 管理者／一般ユーザーの軸を指す場合に限る。**メニュー・画面・API の利用可否を指す場合は「権限」ではなく メニューグループ（V-002）を用いて記述する**（例: 「生産管理メニューグループを持つユーザー」）。両者を合わせて述べる必要がある場合の章題は「認可」とする。
- **境界コンテキスト**: 全コンテキスト（core）
- **補足**: アプリケーション仕様書 7.4、`REQ-F-011`。

## 7. 業界専門用語

### T-001: 基幹連携（ACL）

- **英語名**: `AntiCorruptionLayer`
- **定義**: 基幹 Oracle の物理構造（テーブル・カラム）をポータル向けドメインモデルへ変換する層。業務コンテキストが基幹の構造変更に直接影響されないようにする。
- **使用しない表現**: 「アダプタ層」「変換層」「ラッパー」
- **境界コンテキスト**: 基幹連携
- **補足**: [ドメイン駆動設計.md](../../Document/ドメイン駆動設計.md) を正とする。`REQ-F-041`。

### T-002: 集計基準年

- **英語名**: `CurrentFiscalYear`
- **定義**: 出荷トレンド一覧において、集計基準日が属する暦年。比較基準年（V-003）との差分で変動数・変動率を算出する。
- **使用しない表現**: 「今年度」（暦年であり会計年度ではないため）、「現在年」
- **境界コンテキスト**: 営業（出荷トレンド一覧）
- **補足**: 本プロジェクトの「年度」は **暦年（1月〜12月）** を指す。会計年度とは一致しない。
  したがって「年度」という語の使用そのものは禁止しない（例: 「年度別出荷」は暦年別の出荷を指す正しい表記である）。
  **禁止するのは、どの年を指すかが一意に定まらない用法**（「今年度」「初年度」の単独使用）である。会計年度の意味で「年度」を用いてはならない。

### T-003: 予測込み合計

- **英語名**: `WithForecastTotal`
- **定義**: 集計基準年の実績出荷に、残り月の予測出荷（出荷平均に基づく）を加えた合計。年度比較では集計基準年のみ本値を用いる。
- **使用しない表現**: 「見込み合計」「予測値」
- **境界コンテキスト**: 営業（出荷トレンド一覧）
