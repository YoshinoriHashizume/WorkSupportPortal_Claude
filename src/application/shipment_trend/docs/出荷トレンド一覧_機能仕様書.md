## 2. 背景・目的

### 2.1 背景と目的

**現状の課題**: 営業担当は得意先ごとの出荷の増減を、基幹 Oracle から都度抽出した表計算ファイルで確認している。抽出・集計を担当者が手作業で行うため、①確認できるのは依頼したときだけで、増減に気づくのが遅れる ②得意先×内作品番の粒度で全件を横並びに見る手段がなく、担当者の記憶と勘に依存して確認対象を選んでいる ③どの年と比較するかが担当者ごとに異なり、増減の判断基準が揃わない、という問題がある。結果として、出荷が落ち込んでいる内作品番への働きかけが後手に回る。

**目的**: 出荷の増減トレンドから、営業担当が得意先へアクションすべき内作品番を素早く見つける。全件を一覧で横並びに見られるようにし、比較基準年を全ユーザー共通で明示することで判断基準を揃える。  
在庫発注アラート（生産管理）とは別アプリとし、営業部門のメニューに配置する。

## 3. システム境界・前提

| 区分 | 内容 |
|------|------|
| 基幹 Oracle | **参照のみ**（SELECT）。`T_SHIP`（`DEL_FLG != 1`）から出荷を取得する。ブラウザから直結しない |
| ポータル PostgreSQL | 集計スナップショット・警告閾値設定・比較基準年オーバーライドを保存する |
| 認証 | Django 認証（ログイン必須）。未ログインは画面・API とも `/login` へリダイレクト（302）。認可エラーは 403（§7.4.1） |
| 認可 | **営業** メニューグループを持つ一般ユーザーおよび管理者が利用可能（§8） |
| データ鮮度 | **データ更新の実行時のみ** Oracle を集計する。一覧・グラフ・CSV はスナップショットを参照する（§5.5） |
| 集計単位 | 得意先コード × 内作品番。年は **暦年（1月〜12月）** であり会計年度ではない |
| 共有範囲 | スナップショット・警告閾値・比較基準年は **全ユーザー共通**。ユーザー単位のデータを持たない |

## 5. データ・集計ロジック

### 5.1 データソース

| 区分 | 内容 |
|------|------|
| Oracle | `T_SHIP`（`DEL_FLG != 1`）、読取のみ。集計キーは `TRIM(CUST_CD)` × **`TRIM(ITEM_CD)`**（`shipment_queries.py`） |
| PostgreSQL | 集計スナップショット、警告閾値設定、比較基準年オーバーライド |

**集計基準日**: 一覧・グラフ・CSV の集計の基準となる日付。**データ更新を実行した日のサーバ暦日**（`timezone.localdate(refresh_record.refreshed_at)`）とし、集計スナップショット（`as_of_date`）に固定保存する。集計基準年・前年出荷合計・月次予測の開始月・比較基準年の候補上限はすべて本日付から導出し、**表示時に当日日付で再計算しない**（UL-SHIPMENT-TREND-2026-001 V-407、core V-008）。

**集計基準日の常時表示**（REQ-F-013）: 表示時に再計算しない以上、データ更新を長期間行わないと集計基準年が過去年のまま「集計基準年出荷+予測」「変動率」「警告色」が表示され続ける。利用者が **いつ時点の数値を見ているか** を常に判別できるよう、集計基準日を一覧上部に常時表示する（§7.1.1）。

| 状態 | 表示 |
|------|------|
| 集計スナップショットあり（`as_of_date` あり） | `YYYY年M月D日 時点の集計結果` |
| 集計スナップショットなし、または `as_of_date` なし | 表示しない（一覧自体が空であり、データ更新を促すメッセージを表示する） |

### 5.2 集計年（暦年）

- **1月〜12月**（西暦年）で合計する
- ラベルは西暦年（例: 2025-01〜2025-12 → **2025年**）

### 5.3 変動指標（一覧）

| 項目 | 定義 |
|------|------|
| データ初年度 | 当該得意先×内作品番で **最初に出荷があった暦年**（自動。変更不可） |
| 比較基準年 | 変動数・変動率の分母に使う年。未設定時は **データ初年度** と同じ。手動設定時は §5.6 |
| 基準年出荷合計 | 比較基準年（暦年）の月次出荷数量合計（一覧列「基準年出荷合計」は本値を表示） |
| 前年出荷合計 | **集計基準日の暦年 − 1** の暦年の月次出荷数量合計 |
| 集計基準年出荷+予測 | 集計基準年の集計基準日までの出荷実績合計 ＋ **集計基準年の残月**の予測合計（**当年1月〜集計基準月の出荷合計 ÷ 経過月数** を切り上げた月次予測） |
| 集計基準年の予測込み合計 | **集計基準年** の出荷合計に **集計基準年の残月の予測** を加えた合計（`current_fy_with_forecast_total`）。変動数・変動率の被減数に用いる |
| 変動数 | `集計基準年の予測込み合計 − 基準年出荷合計` |
| 変動率 | `(変動数 / 基準年出荷合計) × 100`（基準年出荷合計が 0 かつ集計基準年の予測込み合計が正のときは `—` 表示） |

一覧表示時はスナップショット行の `monthly` と **比較基準年オーバーライド** から `hydrate_row_metrics` で指標を再計算する（旧スナップショット互換・暦年変更の即時反映）。

一覧列名は **比較基準年** とし、比較基準年の値を表示する（従来の列名「初年度」はデータ初年度と混同するため使用しない）。手動設定中は UI 上で自動との違いが分かる表示とする（§7.2）。

### 5.4 月次データ・予測（グラフ）

- 横軸: **月単位**（最初の出荷月から予測最終月まで連続。出荷のない月は 0 として表示）
- 横軸ラベル: **1月・7月**（半年ごと）および系列の**最初・最後**の月に `YYYY/M` 形式で表示
- 横軸目盛: 月ごとに等幅。**ダイアログ幅いっぱいに収める**（横スクロールなし）
- 縦軸: 月次出荷数量合計
- 実績: 折れ線（緑・実線）＋各月のマーカー。**マーカーにカーソルを合わせると月・実績/予測・数量を表示**
- 予測: **当年1月〜集計基準月の出荷合計 ÷ 経過月数**（出荷のない月は 0 として合計に含める）を **切り上げ** し、集計基準日の**翌月から当該年12月まで**折れ線（青・破線）で表示（`kind=forecast`）。最終実績月から予測線を接続する
- 縦軸: 左端に出荷数量の目盛（約5段）。**データ最大値がグラフ上端付近に来る**よう、最小のきりの良い上限値を採用。縦線と短い横線（目盛）＋数値ラベルを表示
- **最小二乗法（回帰直線）**: §5.7

### 5.5 スナップショット

1. 「データ更新」POST → Oracle 集計（本アプリで Oracle を参照する唯一の契機）
2. `ShipmentTrendSummarySnapshot.rows` に JSON 保存（行ごとに `monthly` を含む）
3. 一覧・グラフ・CSV はスナップショットを参照
4. 警告閾値変更・比較基準年変更は **データ更新不要**（表示時に再判定する）

**同時実行**（指摘 L3-4）: データ更新は排他制御を行わず **後勝ち** とする。スナップショットは更新のたびに新しい更新レコード（`ShipmentTrendRefresh`）とともに追加され、既存行を全件削除しないため、在庫発注アラートの SLIMS 取込のようなデータの部分破壊は起きない（同アプリ機能仕様書 §3「取込の排他」）。ただし以下の 2 点は現行仕様として明示する。

| 事象 | 現行の振る舞い | 備考 |
|------|--------------|------|
| データ更新の実行中に一覧を開く | **一覧が空**（「集計データがありません」）になる | 更新レコードは集計の開始時に作成され、スナップショットは集計の完了時に保存されるため、その間は最新の更新レコードに対応するスナップショットが存在しない |
| 2 名が同時にデータ更新を実行 | **後から開始した実行**の結果が最新として参照される（完了順ではない） | 一覧は `refreshed_at` の降順で先頭の更新レコードを読むため。先に開始し後に完了した実行の結果は参照されない |
| 比較基準年を同時に変更 | **後勝ち**。得意先×内作品番ごとに 1 行のオーバーライドを上書きし、最終更新者・更新日時を保持する（§5.6） | 行単位の更新のため競合の影響は当該行に限られる |

いずれも実運用（営業部門の少人数がそれぞれの判断で更新する）では問題にならない前提とする。更新中の空表示が支障になる場合は、更新完了時にスナップショットと更新レコードを併せて確定させる方式へ見直す（Issue として起票する）。

### 5.6 比較基準年（手動・全ユーザー共通）

試作などでデータ初年度の出荷が少なく変動率が歪む場合に、比較の分母となる年を手動で指定する。

| 項目 | 内容 |
|------|------|
| 粒度 | **得意先コード × 内作品番** 単位 |
| 既定 | 未設定＝データ初年度（従来どおり） |
| 永続 | PostgreSQL（例: `ShipmentTrendBaselineYear`）。**全ユーザー共通** |
| 監査 | 最終更新者・更新日時を保持 |
| 戻す | 「自動（データ初年度）に戻す」でオーバーライド行を削除し、データ初年度に復帰 |
| 候補年 | 当該行の `monthly` に出荷がある暦年、かつ **集計基準年以下** |
| 適用範囲 | 一覧の変動率・変動数・警告色、詳細の年度別「基準年比」、CSV の変動率・変動数、一覧列「比較基準年」「基準年出荷合計」、**詳細グラフの表示開始年（比較基準年の1月〜）と回帰直線** |
| 非適用 | （なし。比較基準年は詳細グラフの横軸開始にも反映する） |

### 5.7 最小二乗法（回帰直線）

詳細グラフに、傾向を示す直線を重ねる。

| 項目 | 内容 |
|------|------|
| 対象点 | 表示単位に応じた系列。**月**: 実績月＋予測月。**年**: 比較基準年以降の各暦年の合計（集計基準年は予測込み合計）。数量は各点の `qty` |
| 横軸 | 表示系列の先頭月を 0 とした通番 `x = 0, 1, 2, …` |
| 縦軸 | 月次数量 `y` |
| 式 | 通常の線形最小二乗 `y = a + b·x`（切片 `a`、傾き `b`） |
| 点数 | 点が **2 未満**のときは直線を描画しない |
| 表示 | 実績・予測とは別系列（色・線種を区別。凡例「最小二乗法」）。直線は表示期間の端まで延長 |
| 数値 | 傾き `b`（月あたり数量の増減）と決定係数 **R²** をグラフ付近に表示 |
| 一覧 | 本版では一覧列・ソートには使わない（グラフ表示のみ） |

## 6. 警告色

閾値は `ShipmentTrendSettings`（pk=1）に保存。UI から変更可（既定 20% / 20%）。

| 条件 | 背景色 | CSS クラス | 在庫発注アラートで同色を用いる箇所 |
|------|--------|------------|------------------------|
| 変動率 ≤ −減少閾値 | 薄い赤（`#fde8e8`） | `st-row-decrease-strong` | アラートレベル **重点** |
| −減少閾値 ＜ 変動率 ＜ 0% | 薄い黄（`#fff8e1`） | `st-row-decrease-mild` | アラートレベル **警告（出荷なし）** |
| 変動率 ≥ ＋増加閾値 | 薄い緑（`#dcfce7`） | `st-row-increase-strong` | 確認状態 **確認済み** |
| 0% ≤ 変動率 ＜ ＋増加閾値、または率なし | 白 | `st-row-neutral` | アラートレベル **アラート無し** |

右列は **配色（パレット）の対応のみ** を示す。判定軸は本アプリが変動率（警告色 S-401）、在庫発注アラートがアラートレベル（S-202）と確認状態（S-201）であり、意味は対応しない。

一覧行・警告条件ダイアログの行背景色は、在庫発注アラートと同一パレット（`.alert-row--*`）を共有する。

警告条件ダイアログの閾値セレクトは、在庫発注アラートと共通クラス（`.portal-alert-rules-select` / `.portal-alert-rules-setting`）で同一見た目とする。

#### 7.4.1 エラー応答

API のエラー応答本文は `{"ok": false, "message": "<日本語メッセージ>"}` を基本とする（認可エラーのみ後述の別形式）。

| 状況 | ステータス | 応答本文 |
|------|-----------|---------|
| 未認証 | **302**（`/login` へリダイレクト） | — （Django の `login_required` による。ポータル共通の挙動） |
| 営業メニューグループを持たない | **403** | `{"success": false, "error": {"message": "権限がありません。"}}`（ポータル共通ミドルウェアが返す） |
| 利用承認が未完了 | **403** | `{"success": false, "error": {"message": "利用承認が完了していません。"}}`（ポータル共通） |
| 許可外の HTTP メソッド | **405** | — |
| リクエスト本文が JSON として不正 | **400** | `JSON の形式が不正です。` |
| 検証エラー（下表 E-01〜E-07） | **400** | 各行のメッセージ |

**`PUT` / `DELETE /api/shipment-trend/baseline-year` の検証**（REQ-F-010・REQ-F-011）

| # | 検証 | メッセージ | 対象 |
|---|------|-----------|------|
| E-01 | `custCode` または `itemCd` が未指定 | `custCode と itemCd を指定してください。` | PUT / DELETE |
| E-02 | `baselineYear` が未指定または空 | `baselineYear を指定してください。` | PUT |
| E-03 | `baselineYear` が整数として解釈できない | `baselineYear は整数で指定してください。` | PUT |
| E-04 | 集計スナップショットが存在しない | `集計データがありません。データ更新を実行してください。` | PUT |
| E-05 | 集計基準日が保存されていない | `集計基準日がありません。` | PUT |
| E-06 | 指定の得意先×内作品番が集計結果に存在しない | `指定された得意先×内作品番が見つかりません。` | PUT |
| E-07 | 指定年が比較基準年の候補（§5.6）に含まれない | `比較基準年の候補に含まれない年は設定できません。` | PUT |

> **補足**: E-06 は「該当リソースなし」に相当するが、**404 ではなく 400** を返す（入力値の検証エラーとして統一的に扱うため）。

**`GET /api/shipment-trend/chart` の検証**: 上記 E-01・E-04・E-06 に相当する条件で 400 を返す。

### 7.5 CSV 出力

一覧とは異なり、**月次出荷数量**を列として出力する。

| 列 | 内容 |
|----|------|
| 担当者コード〜変動数 | 一覧と同じ（基準年出荷合計・前年出荷合計・集計基準年出荷+予測の **3列は含めない**） |
| `YYYY-MM` 列 | 出力対象行全体の **最小月〜最大月** まで連続。当該月の出荷合計（実績のみ）。出荷がない月は **空欄** |

- フィルタ適用後の行を対象とする
- 月次データは行の `monthly`（スナップショット）を使用
- UTF-8 BOM 付き

#### 7.5.1 列名改称の後方互換（指摘 L3-17）

版 1.49（2026-07-30）で一覧列名・CSV ヘッダーの「得意先品番」を **「内作品番」** に改称した（実データが `T_SHIP.ITEM_CD` ＝内作品番であり、旧名称が事実と異なっていたため。L1レビュー是正 追加検出 3-21）。

| 項目 | 方針 |
|------|------|
| 後方互換 | **取らない**。旧ヘッダー名を併記・維持しない |
| 根拠 | 本アプリはリリース初期であり、CSV を機械処理している既存の運用が確認されていない。旧名称は事実と異なるため、維持すると誤解が続く |
| 列の並び・データ内容 | **不変**。改称は表示名のみで、集計キー・列順・値は変更していない。列位置で読む処理には影響しない |
| 運用への周知 | CSV をヘッダー名で読む処理が判明した場合は Issue として起票し、個別に対応する |

> L1レビュー是正タスク（[tasks.md](../../../docs/spec/l1-review-remediation/tasks.md) 影響範囲「後方互換」）で「要確認」としていた点は、本項をもって決着とする。
