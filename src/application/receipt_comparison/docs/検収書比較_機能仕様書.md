# 検収書比較 機能仕様書

文書ID: REQ-RECEIPT-COMPARISON-2026-001
作成日: 2026-06-04
更新日: 2026-07-30
対応文書: [ubiquitous_language_core.md](../../../docs/ubiquitous_language_core.md)（UL-CORE-2026-001）、[ubiquitous_language.md](./ubiquitous_language.md)（UL-RECEIPT-COMPARISON-2026-001）、[検収書比較_テスト仕様書.md](./検収書比較_テスト仕様書.md)

本書は、旧 VB.NET WinForms **受領書比較(MARI)** を業務支援ポータル上で再実装した **検収書比較** の要件を定義する。  
受領書（完成品 CSV / 支給品 TXT）と MARI（Oracle）の出荷・売上・受入データを突合し、結果を `〇` / `△` / `×` で管理する。

用語は上記ユビキタス言語集に従う。特に **突合の入力となるファイルは「受領書」**、**機能・画面は「検収書比較」** と呼び分ける（UL-RECEIPT-COMPARISON-2026-001 E-101）。
機能要件の一覧は §2.4、スコープ外は §2.5 に定める。

## 2. 背景・業務目的

### 2.1 背景

得意先および子取引先から受領する受領書と、MARI（Oracle）の出荷/売上/受入実績を突合し、受領内容が基幹システムと一致しているかを生産管理が確認する。旧 WinForms アプリ `ProductionManegementSystem` の受領書比較を Web 化した。

### 2.2 本機能の目的

| 目的 | 内容 |
|------|------|
| 突合の効率化 | 受領ファイル取込と MARI 自動照合で `〇`/`△`/`×` を一覧化 |
| 差異の継続管理 | `〇` 以外の未完了行を次回比較にも引き継ぐ |
| マスタ管理 | 得意先ごとの受入/納品場所・支給品子取引先・品番設定 |
| 帳票出力 | 表示中結果の CSV ダウンロード（印刷は初期対象外） |

### 2.3 旧実装からの引き継ぎ

| 引き継ぐ | 引き継がない |
|----------|----------------|
| MARI 参照のみ、3項目一致で `〇` | WinForms 固有 UI、旧アプリログイン |
| 比較結果保存・CSV 出力 | MySQL（→ PostgreSQL） |
| 納品/受入場所の対象・除外 | TopLink 版、直接印刷 |
| 完成品 CSV / 支給品 TXT の別取込 | |

## 4. 画面（ルーティング）

| 画面 ID | 画面 | ルート | 概要 |
|---------|------|--------|------|
| SCR-01 | 検収書比較 | `/app/production/receipt-comparison?type=finished-product\|supplied-parts` | 比較・表示・登録・更新・CSV |
| SCR-02 | 受入/納品場所設定 | `/app/production/receipt-comparison/settings?type=...` | 得意先マスタ・場所/品番設定（**管理者のみ**） |
| — | CSV 出力 | `GET /app/production/receipt-comparison/export?type=...` | 表示中結果のダウンロード |

比較画面は **SSR フォーム POST**（`display` / `compare` / `register` / `update` アクション）で処理する。独立 REST API は設けない。

### 4.1 検収書比較画面（SCR-01）

#### 4.1.1 操作フロー

1. 得意先・比較日（開始〜終了）を指定し **表示** → PostgreSQL の保存済み結果を読込（未登録プレビューはクリア）。
2. **表示後**、比較結果エリア右上の **ファイル選択** で受領書を選ぶと **即時比較**（MARI 取得 + 突合）。結果はセッションに **未登録** 保持。
3. 問題なければ **登録** で PostgreSQL へ保存。
4. 保存済み表示中は **更新** で `receipt_flag`・備考を更新。
5. **CSV** で表示中データ（未登録含む）をダウンロード。

表示前は比較結果カードに「比較結果はありません。」。得意先未選択時はカード内に案内メッセージ（ファイル選択は非表示）。

#### 4.1.2 レイアウト

- 検索条件（得意先・開始日・終了日・表示ボタン）は **`portal-search-disclosure`** の白カード内に配置する。各ラベル（得意先・開始日・終了日）は入力の**左**に横並び表示する。カード下辺に枠と一体のコンパクトなトグル帯（**折りたたむ**／**展開**、12px）を全幅配置し、開閉する（`<summary>` は DOM 上先頭だが CSS `order` で**下辺**に表示）。**ページを開くたびに展開**（`open` 属性 + 読込時 JS で `section.open = true`）。開閉状態は **保存しない**（次回表示時も常に展開）。比較結果カード内の操作・表は折りたたみ対象外。
- 検索条件・操作は上部固定。**比較結果表のみ** `.db-table-wrap` 内で縦スクロール。
- `body.portal-app-page` でビューポート高に収め、ページ全体は縦スクロールしない。
- 表ヘッダは `position: sticky`。
- 得意先セレクトと開始日・終了日入力は **同じ高さ**（40px）。

#### 4.1.3 比較結果一覧列

| # | 表示名 | 編集 |
|---|--------|------|
| 1 | 受領データID | 不可 |
| 2 | 結果（`〇`/`△`/`×`） | 可 |
| 3 | 品目番号(MARI) | 不可 |
| 4 | 売上計上日(MARI) | 不可（支給品は受入日） |
| 5 | 売上実績数量(MARI) | 不可（支給品は受入数） |
| 6 | 得意先指定納品場所コード | 不可 |
| 7 | 品番(受領書) | 不可 |
| 8 | 納入月日(受領書) | 不可 |
| 9 | 納入数(受領書) | 不可 |
| 10 | キャンセル数(受領書) | 不可（**完成品のみ**表示） |
| 11 | 子取引先名 | 不可（**支給品のみ**表示） |
| 12 | 備考 | 可 |

> **品番の呼称について**: 列 `品目番号(MARI)` / `品番(受領書)` の実体は **比較区分によって異なる**（完成品＝得意先品番 `T_SHIP.CUST_ITEM_CD`、支給品＝内作品番 `T_RLSD_PUCH_ODR.ITEM_CD` の末尾5桁除去）。
> 単一の正式名称が存在しないため、本コンテキストでは **総称としての「品番」** を用い、列名は区分共通で固定する（UL-RECEIPT-COMPARISON-2026-001 V-106、core V-005 適用範囲）。
> 一律「得意先品番」へ改称すると支給品側が事実と不一致になるため、改称してはならない。

#### 4.1.4 ソート・メッセージ

- 列ヘッダクリックで昇順/降順（`sort`, `dir` クエリ）。
- **表示・比較直後**の初回ソート: **結果** 列昇順（`×` → `〇` → `△`）。
- 比較・登録・更新 **成功時は画面上部メッセージなし**（未登録は見出し「（未登録）」）。エラー・警告のみ表示。

## 5. ファイル取込仕様

### 5.1 共通

- 文字コード: **Shift_JIS / CP932** 第一候補。UTF-8 も受け付け可。
- 区切り: カンマ。

### 5.2 完成品（`.csv`）

| 項目 | 内容 |
|------|------|
| ヘッダー | あり |
| 必須列 | `カードNO`, `品番`, `納入月日`, `納入数`, `納入取消数` |
| 除外 | `カードNO = "S"` の行は対象外 |
| 取込項目 | 品番、納入月日、納入数、納入取消数 |

### 5.3 支給品（`.txt`）

| 項目 | 内容 |
|------|------|
| ヘッダー | なし。ダブルクォート囲み行あり |
| 2列目 | 登録済み **子取引先** `vendor_code` または親 **得意先** `customer_code` と完全一致 |
| 4列目 | 品番（TRIM 後 **10桁**）。品番設定と照合（除外フラグに従う） |
| 3列目 | 日付から `/` 除去、右4桁を `MMDD` |
| 6列目 | 数量（小数可）。0以下は除外 |
| キャンセル数 | 0 固定。子取引先名は 2列目 |

## 6. Oracle（MARI）データ取得

### 6.1 完成品

**テーブル**: `T_SHIP`, `T_SHIP_ODR`, `T_SALES_TEMP`

| 条件 | 内容 |
|------|------|
| 得意先 | 直送先得意先コード（`direct_delivery_customer_code`）を優先、なければ得意先コード（`customer_code`） |
| 期間 | `SHIP_DATE` / `SALES_DATE` BETWEEN 開始日 AND 終了日 |
| `T_SALES_TEMP` | `SHIP_SEQ_NO IS NULL` |
| 数量 | `SHIP_QTY` / `SALES_QTY` **> 0** の明細行のみ |
| 集約 | **`SUM` / `GROUP BY` しない**（明細行のまま。検証: `scripts/verify_mari_shipment_aggregation.py`） |
| 納品場所 | 登録済み受入/納品場所と `exclusion` に従い `IN` / `NOT IN` |

**取得項目**: `item_cd`, `ship_date`, `ship_qty`, `delivery_place`（`CUST_DESINATED_DLV_LOC_CD`）

### 6.2 支給品

**テーブル**: `T_ACPT_RSLT`, `T_RLSD_PUCH_ODR`, `M_VEND_CTRL`

| 条件 | 内容 |
|------|------|
| 子取引先 | PostgreSQL 登録得意先に紐づく **子取引先** コード一覧で `VEND_CD IN (...)` |
| 期間 | `ACPT_DATE` BETWEEN 開始日 AND 終了日 |
| 品番 | `ITEM_CD` 末尾5桁除去（LENGTH>10 時）。TXT 側正規化と一致 |
| 場所除外 | **MARI SQL には適用しない**（旧実装準拠）。TXT 取込側のみ品番設定で絞込 |

## 7. 比較ロジック

### 7.1 一致判定（3項目）

| 項目 | 正規化 |
|------|--------|
| 品番 | MARI の `-` 除去。支給品は末尾5桁除去ルールを TXT/MARI で統一 |
| 日付 | MARI 日付 → `MMdd` と受領 `納入月日` を比較 |
| 数量 | 数値同値（`0` は空表示。NULL は `0` 扱い） |

3項目一致 → **`〇`**。不一致・片側のみ → 初期 **`×`**。ユーザーが **`△`** に手動変更可。

### 7.2 表示処理（取込後）

1. MARI 行を一覧に追加。
2. 保存済み結果を読込み、品番・日付・数量一致行へ受領側情報を反映。
3. 受領書各行を MARI と比較。一致 MARI 行は `〇` + 受領側列をセット。
4. 未一致 MARI 行は `×`。未一致受領行は MARI 列空の `×` 行として追加。

### 7.3 未完了データの引き継ぎ

開始日より前の **`receipt_flag != 1`（`〇` 以外）** の保存済み行も次回一覧に含める（旧 `SelectReceiptData` 準拠）。

## 8. PostgreSQL 永続化

完成品・支給品で **テーブル分離**（`code_type` は使用しない）。
