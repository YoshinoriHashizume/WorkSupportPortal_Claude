# 要発注の大半が MRP 発注品で、人が発注をかける必要のない品番まで並んでいる

## 現状の課題

要発注は「判定期間内に在庫が切れるが、発注期限はまだ先」の照合単位である。発注方式（V-227）は区別していない。
開発環境（2026/11/25 14:32 取込）では、要発注 311 照合単位のうち **253 単位（81%）が MRP 発注**である。

MRP は内示から発注を自動で起票するため、人が発注をかける必要はない（2026/11/25 ユーザー確認）。
それでも要発注に並ぶので、担当者は本当に自分で発注すべき手動発注品を探しにくい。

| 発注期限まで | MRP 発注 | 手動発注 |
|---|---|---|
| 1〜7 日 | 63 | 5 |
| 8〜14 日 | 95 | 40 |
| 15〜30 日 | 95 | 12 |

（ほかに手動発注と MRP 発注の混在が 1 単位。1〜7 日）

## 改善提案

要発注は、手動発注（V-227）を含む照合単位だけにする。MRP 発注のみ・発注方式が不明の照合単位は対象外とする。
要監視（11 REQ-JS-F-003）と同じ考え方である。

- 発注期限が当日または過去（発注遅れ）と、納期遅れの発注残がある場合（納期確認）は変えない。MRP の起票漏れは発注遅れで気づける
- 対象外にした照合単位にも、在庫切れ日と発注期限は理由として残す。そのうえで「MRP が発注を自動で起票するため対応区分に反映していません」と添える
- 手動発注と MRP 発注が混在する照合単位は、人に見せる方へ倒して要発注のままにする

## 期待効果

要発注は 311 単位から約 58 単位（手動発注 57・混在 1）に減る。担当者は自分が発注すべき品番だけを見ればよくなる。

## 代替案

- MRP 発注品も、発注期限が N 日以内になったら要発注に出す（不採用。MRP の起票を信頼する）
- 発注方式にかかわらず、発注期限まで N 日以内だけを要発注にする（不採用）
