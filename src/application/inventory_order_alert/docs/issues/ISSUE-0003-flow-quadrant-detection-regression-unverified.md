# 流動区分への置換で供給リスクの検知力が落ちていないかが未検証

## 現状の課題

要件定義書 REQ-LOW-FLOW-VISIBILITY-2026-001 §1.3 は、目的4として
**「既存のアラートレベルが担っていた供給リスクの検知力を落とさない」** を掲げている。
しかし §8 受け入れ基準 18 項目に、この目的を確かめる基準がない。

- 基準4（入荷実績なしの識別）は副次フラグの表示確認にとどまる
- 基準14（旧ラベルが表示されない）は**撤去の確認**であって検知力の確認ではない

具体的に懸念されるのは、**旧アラートレベルより深刻度が下がる行が存在する**ことである。

| 行の条件 | 旧アラートレベル | 現在の流動区分（既定＝低流動判定軸・3か月） |
|---|---|---|
| 入荷実績なし・最終出荷が4か月前 | **重点**（ランク0＝最上位） | **在庫死蔵品**（ランク1） |

旧方式の「重点」は `post_shipment_count > 0` を見ており出荷時期を問わなかったのに対し、
流動区分は期間内出荷（V-213）の有無で判定するため、出荷が判定期間より前だと供給リスク品にならない。
入荷実績なし（V-214）のバッジで緩和されるが、**並び順・行背景色・件数サマリ上の扱いは下がる**。

これが意図した設計変更なのか、それとも検知漏れなのかを判断する根拠が、現状どこにも記録されていない。

## 改善提案

1. 旧アラートレベルと流動区分の**深刻度ランクが入れ替わる条件**を洗い出し、一覧表にする
2. その各ケースについて、現在の扱いが意図どおりかを業務側で確認する
3. 確認結果を回帰テストとして固定する（`tests/test_flow_quadrant.py` への追加を想定）
4. 意図どおりでないケースがあれば、対策を別途検討する（本Issueからの派生）

## 期待効果

- §2.1 の事故事例（仕入先が設備・金型を廃棄していた）に該当する行が、
  既定の判定条件でも確実に上位に現れることを保証できる
- 「流動区分に変えたら見落としが増えた」という運用上の不信を未然に防ぐ

## 代替案

- メニュー画面アラート帯と同じく、一覧でも入荷実績なしの行を常に最上位へ固定する案。
  ただし流動区分のランクと二重の並び順基準を持つことになるため、まず現状把握を優先する
