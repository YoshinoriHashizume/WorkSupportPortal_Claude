# 在庫数ソートの空値センチネル `-1` が負の在庫数と衝突する

## 事象（現象）

一覧の在庫数列（**在庫数(SLIMS)** / **在庫数(MARI)**）をソートすると、
**負の在庫数を持つ行が「空（該当なし）」「未取得」より下に並ぶ**。

design.md §6.1 は「空は最小として扱う」と定めているが、負値が存在するとこれが成立しない。

## 再現手順

**未確認**（実データに負の在庫数が存在するかを調査していないため、再現は未実施）。

論理的な再現条件は次のとおり。

1. MARI（`T_ITEM_STOCK.STOCK_ON_HAND_QTY`）に **負の在庫数**を持つ内作品番が存在する
2. 同じ一覧に、MARI 在庫が「該当なし（空）」または「未取得（`－`）」の行も存在する
3. 在庫数(MARI) 列を**昇順**でソートする

## 期待動作 vs 実際の動作

| | 昇順ソートの並び |
|---|---|
| 期待（design.md §6.1） | 空・未取得 → -5 → 0 → 95 |
| 実際 | -5 → 空・未取得（`-1` 相当） → 0 → 95 |

## 原因分析

**未確定**（実データの確認前）。コード上の直接原因は次の 2 箇所。

| 実装 | 該当箇所 |
|---|---|
| サーバ側 | `domain/value_objects/table_display.py` の `_sort_value()`。空・変換不能を `Decimal("-1")` として返す |
| クライアント側 | `static/js/inventory-order-alert-list-client.js` の `sortValue()`。同じく `-1` を返す |

`-1` は「値ではないもの」を表すつもりの番兵だが、**実在しうる値と同じ数直線上に置いている**ため衝突する。

## 影響範囲

- **在庫数(SLIMS)** にも同じ実装が入っており、本 Issue 以前から存在する（今回の変更で顕在化したわけではない）。
  ただし MARI の理論在庫は取引の計上タイミングで負になり得るため、**在庫数(MARI) の追加により発生確率が上がった**。
- 発注判断への影響: 「在庫が少ない順」に並べたときに、在庫が最も少ない（マイナスの）行が
  先頭に来ることは期待どおりだが、**空の行がその下に埋もれる**。
  空は「MARI に品番が無い」であって在庫僅少ではないため、誤読の方向としては軽い。
- **表示の正しさには影響しない**（負値はそのまま表示される。design.md §8 のとおり）。

## 仕様上の矛盾

design.md 内で次の 2 つが両立していない。両者のどちらを優先するかを決める必要がある。

| 箇所 | 記述 |
|---|---|
| §6.1 | 既存の `stock_qty` のソート規則（**空は最小として扱う**）を `mari_stock_qty` にも適用する |
| §8 | MARI の在庫数が負値 → **そのまま表示する**。基幹の値を加工しない |

## 対策案 (Plan)

**未確定。** 先に次を調査してから方針を決める。

1. **MARI に負の在庫数が実在するか**を SELECT で確認する（読み取りのみ）
2. 実在しない場合 → design.md §6.1 に「負の在庫数は想定しない」旨を明記して**クローズ**する
3. 実在する場合 → 番兵を数直線から外す。候補:
   - ソートキーをタプル `(0 if 値あり else 1, 値)` にして「値の有無」を第1キーにする
   - サーバ・クライアントの**両方**を同時に直す（片方だけだと初期表示と再描画で並びが変わる）

いずれも**軽微（表示ロジックのみ・複数ファイルだが再設計を伴わない）**の想定。
本格 SDD への委譲は不要と判断する。
