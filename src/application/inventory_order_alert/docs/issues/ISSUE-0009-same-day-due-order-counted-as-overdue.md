# 納期が基準日当日の発注残が「納期遅れ」に数えられ、予定入荷にも足されない

## 事象（現象）

納期が基準日（取込日）当日の発注残を、**納期遅れ**として数えている。同時に**予定入荷（V-236）にも足していない**ため、その日に届く予定の品物が在庫の見通しから抜け落ちる。
その結果、今日届く予定の発注残しかない得意先品番が「納期確認」になる。今日の入荷を足していないため、在庫切れ日（V-232）が早く出て「要発注」「発注遅れ」になる品番もある。

## 再現手順

1. 完成品直下の工程に、納期 ＝ 取込日・発注残数 > 0 の発注残（V-225）がある得意先品番を用意する
2. SLIMS 在庫 CSV を取り込む
3. 一覧で、その得意先品番の対応区分と詳細ダイアログを見る

## 期待動作 / 実際の動作

- **期待**: 納期が基準日当日の発注残は、まだ遅れていない。予定入荷として在庫の見通しに足し、納期確認の根拠にしない（納期遅れは**納期 < 基準日**）
- **実際**: **納期 ≤ 基準日** を納期遅れとしている。当日分は納期確認の根拠になり、在庫の見通しには足されない

## 影響範囲・環境

- 影響範囲: 対応区分（一覧・件数サマリ・アラート帯・CSV）、在庫切れ日・発注期限、詳細ダイアログの予定入荷と在庫シミュレーションのグラフ
- 規模（開発環境・2026/11/25 13:36 取込）: 納期確認 153 照合単位のうち、**58 単位は最大の遅れが 0 日（当日納期のみ）**。うち 51 単位は在庫切れ予測も出ている
- 環境: 開発環境で確認。本番も同じロジック

## 原因分析（root cause）

境界条件を `納期 > 基準日 → 予定入荷`／`納期 ≤ 基準日 → 納期遅れ` と定めているため（spec/08 の改訂。用語集 V-225 の注記）。同じ境界が次の 3 か所に重複している。

- `domain/value_objects/stock_simulation.py` `planned_incoming_by_due()`（`due > as_of_date`）
- `domain/value_objects/stock_simulation.py` `overdue_order_breakdown()`（`due > as_of_date` 以外を遅れとする）
- `infrastructure/oracle/summary_queries.py` `build_planned_incoming()`（`due > as_of_date`）

在庫の見通し（`build_stock_projection`）とグラフ（`inventory-order-alert-list.js`）は、基準日の**翌日から**予定入荷を足している。このため境界を変えるだけでは、基準日当日の予定入荷が見通しに入らない。

## 対策案 (Plan)

- 対策区分: 軽微（ユーザー判断で Issue 内完結。変更は複数ファイルだが、判定ルールの境界を 1 日動かすだけで新しい概念は増えない）
- 方針（2026/11/25 ユーザー決定）: **納期が基準日当日の発注残は予定入荷として在庫に数え、納期遅れから外す**
  - 取込前に当日分が入荷済みで SLIMS 在庫にも入っていると二重に数える。この点は許容する（ユーザー判断）
- 変更内容:
  1. `stock_simulation.py`: `planned_incoming_by_due()` を `due >= as_of_date` に、`overdue_order_breakdown()` を `due < as_of_date` のみ遅れとするよう変える
  2. `stock_projection.py`: 基準日当日の予定入荷を、見通しの起点の在庫に足す
  3. `summary_queries.py`: `build_planned_incoming()` を `due >= as_of_date` に変える（詳細ダイアログの予定入荷）
  4. `static/js/inventory-order-alert-list.js`: グラフの未来側の起点に基準日当日の予定入荷を足す
  5. テスト: 当日納期の境界値テストを各関数に追加する（TDD）
  6. 文書: 機能仕様書（納期遅れ・滞留発注残・予定入荷の定義）と用語集（V-225・V-236・V-238 の境界）を `納期 < 基準日` に改める
- 影響: 再取込後、当日納期のみの照合単位は納期確認から外れる。在庫切れが解消すれば対象外に、残れば要発注などに移る
