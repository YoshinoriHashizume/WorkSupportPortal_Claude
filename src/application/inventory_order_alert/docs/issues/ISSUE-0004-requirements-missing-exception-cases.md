# 要件定義書の異常系に同時実行と集計エラーの記載がない

## 現状の課題

要件定義書 REQ-LFV-F-017「異常系・エッジケースの扱い」は 8 ケースを定義しているが、
manage-issue / requirements-review-l3 が定める異常系パターンのうち **2 つが漏れている**。

| 漏れているパターン | 具体的な状況 | 現在の実装の挙動 |
|---|---|---|
| **同時実行**（L3F-4） | SLIMS 在庫 CSV の取込中に、別の利用者が判定軸・判定期間を切り替える／確認状態を保存する | `infrastructure/persistence/import_lock.py` の排他ロックにより取込側が保護される。表示側は取込前のスナップショットを読むため破綻しない |
| **集計エラー時**（L3F-5） | 集計スナップショットに `aggregation_error` が入っている | 一覧はエラーメッセージを表示し、件数サマリを 0 件とする。メニュー画面アラート帯は tone=neutral |

**いずれも実装では正しく扱われており、不具合ではない。**
要件定義書に書かれていないため、
「意図した挙動なのか、たまたまそう動いているのか」が文書から判断できないことが課題である。

REQ-LFV-F-017 #4 は「SLIMS 在庫が未取込」のみを扱っており、集計エラーは別の状態である点に注意。

## 改善提案

REQ-LFV-F-017 の表に 2 行を追加し、期待する扱いを明文化する。

| # | ケース | 期待する扱い（案） |
|---|--------|--------------|
| 9 | 取込中に判定軸・判定期間の切り替えや確認保存が行われた | 取込の排他は機能仕様書 §7.2 の既存機構に委ねる。表示側は取込前のスナップショットで判定を継続し、エラーにしない |
| 10 | 集計スナップショットに集計エラーが記録されている | 既存の挙動を維持する。エラーメッセージを表示し、流動区分の件数はすべて 0 とする |

## 期待効果

- 要件定義書が実装の挙動を説明できる状態になり、次に触る人が挙動の根拠を辿れる
- 将来 `import_lock` の方式を変更する際に、要件として守るべき線が明示されている

## 代替案

- 機能仕様書 §7.2 への参照だけを REQ-LFV-F-017 に添える案。
  ただし集計エラー時の件数の扱いは機能仕様書にも明記がないため、要件側で書くほうが確実
