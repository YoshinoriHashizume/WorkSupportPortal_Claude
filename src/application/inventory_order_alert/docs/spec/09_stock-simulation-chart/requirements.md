## 3. 背景と課題

### 3.1 きっかけ

詳細ダイアログのグラフで「予定入荷の棒は立っているのに、予測在庫の線が 0 に戻らない」という指摘を受けた。調べたところ**表示は仕様どおり**だったが、その過程で **同じ画面に計算方法の違う「在庫切れ」が 2 つ並んでいる**ことが分かった。

| 表示箇所 | 値 | 根拠 |
|---|---|---|
| グラフの赤い縦線・需要予測セクション | 在庫切れ予測月（V-221） | **月平均需要**で割る。発注残を含めない |
| 対応区分セクション・一覧の列 | 在庫切れ日（V-232） | **内示を日次**で引く。予定入荷（V-236）を足す |

spec/08 で対応区分（S-204）を「予測を使わず内示のある範囲を日次で追う」方式に全面改訂したが、**グラフと需要予測セクションは月平均需要ベース（V-221）のまま残った**。

### 3.2 現状の課題

| # | 課題 | 内容 |
|---|---|---|
| 1 | **在庫切れの定義が 1 つでない** | 同じ品目に対し、グラフの縦線と一覧の在庫切れ日が別の日を指しうる。どちらを見て動けばよいか決まらない |
| 2 | **グラフの線と縦線が食い違う** | 2026/09/22 に線から予定入荷を外した（「線は持ち直しているのに縦線が手前に立つ」を避けるため）。結果、線は予定入荷を反映せず、棒と目で照合する必要がある |
| 3 | **月次では入荷と出荷の前後が表せない** | 同じ月の中で「先に出荷して尽きるのか、先に入荷して間に合うのか」が読めない。spec/08 で判定を日次にした理由と同じ問題がグラフに残っている |
| 4 | **過去の傾向と未来の見通しが 1 枚に混在** | 左は 24 か月の月次逆算（実測ではない参考値）、右は 3 点の予測。性質の違うものが 1 本の線に見える |
| 5 | **予定入荷が判断に使えない** | 「これから届く分を入れても間に合わないのか」が線で読めない |

### 3.3 やりたいこと

1. グラフを **実績（過去の傾向）** と **在庫シミュレーション（日次の見通し）** の 2 つに分ける
2. 在庫シミュレーションは **日次**にし、**予定入荷を線に足す**
3. 在庫シミュレーションを **対応区分（S-204）とまったく同じ材料・同じ規則**で描き、画面内の「在庫切れ」の定義を 1 つにする

## 4. 機能要件

### REQ-SSC-F-001: グラフを 2 つに分ける

詳細ダイアログの「推定在庫推移（参考値）と入荷実績」区分を、**2 つの区分**に分ける。

| # | 区分名 | 内容 | 対応する用語 |
|---|---|---|---|
| 1 | **在庫推移（実績）** | 過去 24 か月の月次。推定在庫の折れ線＋入荷実績の棒 | 推定在庫推移（V-218） |
| 2 | **在庫シミュレーション** | 基準日の 1 か月前〜翌々々月末の日次 | 在庫シミュレーション（V-237） |

- 1 は**予測を一切描かない**（点線・予定入荷の棒・在庫切れの縦線をすべて 2 へ移す）
- 2 は 1 の下に置く（過去を見てから見通しを見る順）

### REQ-SSC-F-002: 在庫シミュレーションの算出

在庫シミュレーション（V-237）を、基準日を境に次のとおり算出する。

```
【基準日まで（実績・逆算）】
  前日の在庫 ＝ 当日の在庫 ＋ 当日の日次出荷（V-234） − 当日の日次入荷（V-235）
  起点 ＝ 基準日の在庫（SLIMS 在庫数 V-206 の照合単位合計）

【基準日より後（見通し）】
  当日の在庫 ＝ 前日の在庫 − 当日の内示（V-219） ＋ 当日の予定入荷（V-236）
  起点 ＝ 基準日の在庫（同上）
```

- 範囲は **基準日の 1 か月前 〜 基準日の翌々々月末**
- 範囲内の**すべての日**を持つ（値のない日も前日の値を引き継ぐ）
- 数量は**マイナスを許容する**（クランプしない）

### REQ-SSC-F-003: 発注残の扱いを対応区分と揃える

在庫シミュレーションに加算する発注残は、**納期が基準日より後のもの（予定入荷 V-236）のみ**とする。

| 発注残の区分 | 線への加算 | 表示 |
|---|---|---|
| 納期 > 基準日（予定入荷） | **足す** | 納期の日に棒で描く |
| 納期 ≤ 基準日（納期遅れ） | **足さない** | 基準日の位置に**別の色の棒**で描く |

納期遅れを別の色で描くのは、「催促すれば回復しうる量」を判定を変えずに目で示すため（ユーザー判断 2026/09/29）。

### REQ-SSC-F-004: 在庫切れの縦線を在庫切れ日に統一する

在庫シミュレーションに描く縦線は **在庫切れ日（V-232）** とする。在庫切れ予測月（V-221）による縦線は描かない。

- 在庫切れ日は、REQ-SSC-F-002 の見通し部分が **初めて 0 未満になる日**と一致しなければならない
- あわせて **発注期限（V-233）** の縦線も描く（この日までに発注すれば間に合う最終ライン）
- 在庫切れ日が空（尽きない）なら、いずれの縦線も描かない

### REQ-SSC-F-005: 安全在庫の水準線

安全在庫（V-231）が設定されている照合単位では、在庫シミュレーションに**安全在庫の水平線**を描く。対応区分の「要監視」（安全在庫割れ）が目で確認できるようにするため。安全在庫が 0（未設定）なら描かない。

### REQ-SSC-F-006: 算出に必要なデータを行に持たせる

日次出荷（V-234）・日次入荷（V-235）を、取込時に集計スナップショットの行へ持たせる。

- **Oracle への問い合わせを増やしてはならない**。既存の `fetch_all_shipments` / `fetch_incoming_receipts` が返す日次明細を束ね直すだけとする
- 範囲は基準日の 1 か月前から基準日まで（疎な配列。値のない日は持たない）
- 内示（`unconfirmed_order_daily`）・発注残（`open_purchase_orders`）は spec/08 で既に行が持っているため追加しない

### REQ-SSC-F-007: 在庫が未取得のときの扱い

在庫が**未取得**（SLIMS 未取込・旧スナップショット）の照合単位では、在庫シミュレーションを**算出せず、グラフを表示しない**（「在庫シミュレーションを算出できません。」を表示）。**該当なし（空）は 0 を起点に算出する**。V-218 と同じ方針。

### REQ-SSC-F-008: 旧スナップショットの読込

日次出荷・日次入荷を持たない旧スナップショットの行では、**在庫シミュレーションの過去側を描かない**（基準日から右だけを描く）。例外にせず、取込し直せば解消する旨を画面に示す。

## 5. 非機能要件

### REQ-SSC-NF-001: Oracle への問い合わせを増やさない

取込時の Oracle 問い合わせ回数を **現状から増やしてはならない**（REQ-SSC-F-006）。

### REQ-SSC-NF-002: 配信データ量

日次出荷・日次入荷の追加による 1 行あたりの増分を、**内示の日次（`unconfirmed_order_daily`、平均 46 件）と同程度に収める**。範囲が 1 か月のため、営業日ベースで各 20 件程度を見込む。

### REQ-SSC-NF-003: 算出場所

在庫シミュレーションの算出は **クライアント（JS）側**で行う（V-218 と同じ）。ただし**在庫切れ日・発注期限・安全在庫はサーバが判定した値を使い、JS では再計算しない**（判定ロジックを JS に持ち込まない。spec/05 NF-005 と同じ方針）。

### REQ-SSC-NF-004: 描画性能

日次 4 か月分（約 120 点）× 2 系列 + 棒を、既存の月次 24 点と同じ SVG 描画方式で描く。外部グラフライブラリは導入しない。

## 6. 前提条件・制約事項

| # | 内容 |
|---|---|
| 1 | 内示（V-219）の取得範囲は基準日〜翌々々月末（`unconfirmed_order_window_end`）。在庫シミュレーションの右端はこれに合わせる |
| 2 | 在庫の実測値は SLIMS 取込日時点の 1 点のみ。過去側は逆算であり実測ではない |
| 3 | 基準日は BOM 基準日（取込暦日） |
| 4 | 算出単位は照合単位（T-208）。同じ照合単位に属する行はすべて同じグラフになる |
| 5 | Oracle は読み取り専用 |

## 7. スコープ外

| # | やらないこと | 理由 |
|---|---|---|
| 1 | 対応区分（S-204）・在庫切れ日（V-232）・発注期限（V-233）の**判定ロジックの変更** | spec/08 で確定済み。本件は表示を判定に合わせる変更であり、逆ではない |
| 2 | 一覧の列・CSV・件数サマリ・メニュー帯の変更 | 詳細ダイアログのみの変更 |
| 3 | 需要予測（V-220）・在庫切れ予測月（V-221）・在庫月数（V-222）の**撤去** | 需要予測セクションは月次の見通しとして残す。ただしグラフの縦線には使わない（REQ-SSC-F-004）。撤去の要否は別途判断する |
| 4 | 過去の実績による在庫切れ予測（出荷実績ベース等） | 2026/09/29 の検討で比較資料を作成したが、採否は未決。本件には含めない |
| 5 | 推定在庫推移（V-218）の月数（24 か月）・粒度（月次）の変更 | 実績グラフは現状のまま |
| 6 | 在庫シミュレーションの範囲（1 か月前〜翌々々月末）を利用者が変更する UI | 固定とする |

## 8. 受け入れ基準

| # | 基準 |
|---|---|
| 1 | 詳細ダイアログに「在庫推移（実績）」と「在庫シミュレーション」の 2 つの区分が、この順で表示される |
| 2 | 「在庫推移（実績）」に予測の点線・予定入荷の棒・在庫切れの縦線が**描かれない** |
| 3 | 「在庫シミュレーション」の線が初めて 0 未満になる日が、**対応区分セクションの在庫切れ日（V-232）と一致する**（全照合単位で） |
| 4 | 発注期限（V-233）の縦線が、在庫切れ日の縦線よりリードタイム（V-225）ぶん手前に立つ |
| 5 | 納期遅れの発注残は線に加算されず、基準日の位置に別の色の棒で描かれる |
| 6 | 安全在庫が設定されている照合単位で、水平線が描かれる |
| 7 | 内示が 1 件もない照合単位では、基準日より後が水平線になる |
| 8 | 在庫が未取得の照合単位では在庫シミュレーションを表示せず、案内文が出る |
| 9 | 取込時の Oracle 問い合わせ回数が現状と変わらない |
| 10 | 旧スナップショットの行でも例外が出ず、基準日から右だけが描かれる |
