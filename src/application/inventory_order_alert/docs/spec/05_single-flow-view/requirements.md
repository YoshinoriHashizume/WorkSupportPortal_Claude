## 1. 背景と目的

### 1.1 背景

在庫発注アラートの一覧は、02_low-flow-visibility で **判定軸**（V-210、本書で廃止。低流動判定軸 1/3/6 か月・死蔵判定軸 1/2/5 年）と**判定期間**を選び、期間内の入荷・出荷の有無から流動区分（4 象限）を表示している。運用してみて次の課題が出た。

1. **2 回見ないと全体が分からない**。「最近の動きが鈍い品目」は低流動判定軸、「長期間動いていない品目」は死蔵判定軸に切り替えないと見えない
2. **セルが区分名だけで、何をすべきか分からない**。「供給リスク品」（旧称）と出ても、根拠（いつから入荷がないか）と次の行動（誰が何を確認するか）を担当者が頭の中で補う必要がある
3. **緊急度が分からない**。同じ「入荷なし」でも、在庫が数年分ある品目と来月切れる品目が同列に並ぶ
4. **低流動判定軸（月単位）が目的とずれていた**。本機能の目的は「仕入先が設備・金型を廃棄する前に気づく」こと（機能仕様書 §2.1、事例では 8 年の無発注）であり、問われるのは「最後に入荷してから何年経ったか」である。3 か月動かないこと自体は仕入先の設備が消えるリスクと無関係で、判定の時間スケールは年単位が適切

### 1.2 調査で確定した事実（根拠）

2026/09/15 に基幹 Oracle（読み取り）と 2026/09/07 取込の集計スナップショット（2,298 行）で確認した。

| 観測 | 値 | 意味 |
|---|---|---|
| 内示受注（`T_UNCNFM_ODR`）の先行き | 当月残＋翌月から **3 か月分**（2026-10〜12）。2027-01 以降なし | 「3 か月は内示受注、その先は平均」という需要予測の組み立てが実態に合う |
| 直近 3 か月に内示受注がある行 | 1,354 / 2,298 行（59%） | 内示受注だけでは全行を覆えない |
| 同・通常流動品 | 947 / 1,034（92%） | 動いている品目はほぼ内示受注がある |
| 同・供給リスク品（旧称。新: 低流動品（入荷なし）） | 185 / 250（**74%**） | 本命の区分でも 1/4 は内示受注がない → 過去出荷による代替が必須 |
| 同・在庫死蔵品 | 188 / 903（21%） | 需要がないので当然。予測「なし」の表示が要る |
| 内示受注の単位 | 得意先 × 内作品番 | 同じ内作品番を共有する得意先品番の行に **同じ内示受注が重複して現れる**（例: 得意先 137 の内示受注が 96160-00500 と 10523-X0A02 の両方に出る） |
| 照合単位（04 で導入） | 1,994 単位。複数の得意先品番を含むのは 25 単位・144 行 | 在庫・出荷・入荷・内示受注を突き合わせる単位は既に確立している |

### 1.3 目的

| 目的 | 内容 |
|---|---|
| 1 回で全体を把握 | 判定期間を 1 つにし、死蔵と低流動を同じ一覧で同時に見られるようにする |
| 状況と行動の提示 | 各行に「今どういう状態か（根拠の日付つき）」「誰が何を確認すべきか」を表示し、担当者が判断を補わなくてよいようにする |
| 緊急度の提示 | 内示受注に基づく需要予測から「あと何か月もつか」「いつ在庫が切れるか」を示し、仕入先確認の優先順位を決められるようにする |
| 目的との整合 | 判定の時間スケールを年単位に統一し、仕入先の設備・金型廃棄に先回りするという本来の目的に判定を合わせる |

## 3. 対象ユーザーと利用シーン

### 3.1 対象ユーザー / 対象業務

生産管理メニューグループの利用者（生産管理・調達G・営業G）が、SLIMS 在庫 CSV 取込後の一覧で、仕入先確認・処分検討・発注抑制の要否を判断する業務。

### 3.2 利用シーン

| ID | シーン | 概要 |
|---|---|---|
| UC-01 | 仕入先確認の優先順位付け | 一覧を「低流動品（入荷なし）」で絞り、在庫月数の短い順に並べ、上から仕入先へ生産継続可否を確認する |
| UC-02 | 死蔵在庫の洗い出し | 判定期間を 5 年にして「在庫死蔵品」を抽出し、処分・廃却や得意先への補給要否確認を検討する |
| UC-03 | 入れすぎの抑制 | 「低流動品（出荷なし）」を絞り、発注の抑制や営業への需要確認を行う |
| UC-04 | 日常の気づき | メニュー画面のアラート帯で、既定の判定期間（1 年）における各区分の件数を確認する |
| UC-05 | 個別品目の深掘り | 詳細ダイアログで状況・推奨アクション・推定在庫推移・需要予測を確認し、必要なら 5年9組へ遷移する |

## 4. 機能要件

### REQ-SFV-F-001: 判定期間の一本化

- 判定期間は **1 年 / 3 年 / 5 年** の固定 3 値とし、既定は **1 年**とする
- 判定期間セレクタは一覧ヘッダのアクション行で **「判定ルール」ボタンの左**に置く
- 起点は BOM 基準日。境界日ちょうどは期間内（`>=`）、基準日より未来の日付も期間内、日付が空・解析不能なら期間外とする（02 の REQ-LFV-F-003 の規則を踏襲）

### REQ-SFV-F-002: 判定軸の廃止

- 「低流動判定軸／死蔵判定軸」の切り替え UI を撤去する
- URL パラメータ・保存済みの選択状態に旧判定軸が含まれていても、エラーにせず既定の判定期間で表示する
- 旧判定軸の値（`low_flow` / `dormant`）と月単位の判定期間（1/3/6 か月、2 年）は受け付けない（無視して既定にする）

### REQ-SFV-F-003: 流動区分の判定

判定期間内の期間内入荷・期間内出荷の有無から、行ごとに次の 4 値のいずれかを判定する（S-203）。

| 期間内入荷 | 期間内出荷 | 流動区分 |
|:---:|:---:|---|
| なし | なし | 在庫死蔵品 |
| なし | あり | 低流動品（入荷なし） |
| あり | なし | 低流動品（出荷なし） |
| あり | あり | 通常流動品 |

- 判定単位は得意先 × 得意先品番の 1 行。在庫数・出荷回数・需要予測は判定に用いない
- 判定期間の切り替えは集計スナップショットを作り直さず、表示時に再判定する
- 旧区分名（供給リスク品・在庫過剰リスク品）で保存されているデータは読込時に新区分へ正規化する

### REQ-SFV-F-004: 一覧セルの表示内容

一覧の流動区分列のセルに、行ごとに次を表示する。

| 要素 | 内容 |
|---|---|
| 区分 | 流動区分（S-203）。通常流動品は**セルを空**にする |
| 状況 | 区分の意味を一言で示し、根拠として最終入荷日・最終出荷日のうち「止まっている側」の日付を添える（例: 「出荷は継続、最終入荷 2025/04/02」） |
| 緊急度（V-223） | 在庫月数（V-222）と在庫切れ予測月（V-221）の組。算出できない場合は表示しない（REQ-SFV-F-009） |
| 推奨アクション | 区分に対応する文言（REQ-SFV-F-006） |
| 責任部署 | 区分に対応する責任部署（R-201） |
| 副次バッジ | 入荷実績なし（V-214）は従来どおりバッジで併記する |

- 行の背景色は流動区分に応じて付け、確認状態の色を優先する（02 の REQ-LFV-F-005 を踏襲）
- セル内の要素の並び・省略の仕方（幅が狭いときの折り畳み等）は design.md で定義する

### REQ-SFV-F-005: 状況の根拠

- 「状況」の日付は当該行の最終入荷日・最終出荷日を用いる（照合単位の合算値ではない）
- 「入荷なし」の行で最終入荷日が空（入荷実績なし）の場合は、日付の代わりに「入荷実績なし」を示す

### REQ-SFV-F-006: 推奨アクションの文言

- 区分ごとの推奨アクション（T-207）は S-203 の表の文言を暫定として用いる
- 文言は業務側で確定するものとし、**コードに埋め込まず設定または定義ファイルで差し替えられる**こと（差し替えの手段は design.md で定義する）
- 責任部署の割当ては R-201 の暫定割当てを用いる（業務側で未確定である旨は 02 と同じ）

### REQ-SFV-F-007: 内示推移の取得

- SLIMS 在庫 CSV 取込時に、基幹 Oracle から内示受注を取得し、得意先 × 内作品番ごとの**当月残（取込日以降）＋翌月〜翌々々月**の月次数量（内示推移 V-219）として集計スナップショットに保持する
- 削除された内示受注（`DEL_FLG`）は含めない
- 内示推移は得意先品番の行に対応づけて保持する。内作品番から得意先品番への対応は、既存の最終入荷日・出荷回数の解決と同じ基準日で行う
- 一覧表示・詳細ダイアログ表示のたびに Oracle へ問い合わせない（V-216・V-217 と同じ方針）

### REQ-SFV-F-008: 需要予測

照合単位（T-208）ごとに月次の需要予測（V-220）を算出する。

- 翌月〜翌々々月: 内示推移を照合単位で合算した値。合算では **(得意先, 内作品番) の組で重複を除く**
- それ以降: 上記 3 か月の平均
- 内示推移が 3 か月とも 0 で、直近 12 か月に出荷実績がある場合: 直近 12 か月の月平均出荷数量（照合単位で合算）で代替し、算出根拠を「実績ベース」とする
- どちらも 0 の場合: 需要予測「なし」
- 算出根拠（`内示` / `実績ベース` / `なし`）を画面で判別できること
- 合算は一覧の絞り込み状態に依存しない（**SLIMS 取込時に全行で合算**し、結果を集計スナップショットに保持する。2026/09/16 設計承認により「配信済みの全行で行う」から改訂）

### REQ-SFV-F-009: 在庫切れ予測月と在庫月数

- 在庫切れ予測月（V-221）: 照合単位の SLIMS 在庫数の合計から、当月残の内示受注数量と累積の需要予測を差し引き、初めて 0 を下回る年月
- 在庫月数（V-222）: 照合単位の SLIMS 在庫数の合計 ÷ 需要予測の月平均（小数 1 桁）
- 次の場合は算出せず表示しない: 需要予測が「なし」、照合単位の全品番で SLIMS 在庫数が未取得
- SLIMS 在庫数が「該当なし（空）」の品番は 0 として合算する（V-218 と同じ扱い）
- 照合単位が複数の得意先品番を含む場合、在庫の合算内訳を詳細ダイアログで確認できること

### REQ-SFV-F-010: 絞り込みとソート

- 流動区分（4 値）で絞り込めること。旧「流動区分」ドロップダウンは新区分に置き換える
- 在庫月数で昇順・降順にソートできること（空は末尾）
- 既存の並び順の既定（流動区分ランク → 出荷数量降順）は、新区分のランク（S-203 で定義: **低流動品（入荷なし） → 在庫死蔵品 → 低流動品（出荷なし） → 通常流動品**）に読み替える

### REQ-SFV-F-011: 件数サマリ

一覧上部の件数サマリは新区分名で 4 区分の件数を表示する。

### REQ-SFV-F-012: 判定ルールダイアログ

判定ルールダイアログの表を新区分に置き換え、各行に 期間内入荷/出荷・区分・状況・推奨アクション・責任部署 を示す。判定軸の説明は削除する。

### REQ-SFV-F-013: CSV 出力

- 流動区分列は新区分名で出力する
- 在庫月数・在庫切れ予測月・需要予測の算出根拠・推奨アクション・責任部署を列として追加する
- 出力時の判定期間は画面で選択中の値を用いる

### REQ-SFV-F-014: 詳細ダイアログ

- 「流動区分」区分に、区分・状況・推奨アクション・責任部署・判定期間（例: `1 年`）を表示する
- 需要予測の内訳（月別の内示受注数量、算出根拠、在庫切れ予測月、在庫月数、照合単位の在庫内訳）を確認できること
- 推定在庫推移（V-218）と 5年9組への遷移は現状のまま維持する

### REQ-SFV-F-015: メニュー画面アラート帯と確認記録

- メニュー画面のアラート帯は、**既定の判定期間（1 年）で固定判定**した 4 区分の件数を表示する（旧「低流動判定軸・3 か月」から変更）
- 深刻化による未確認化（A-201）の判定も同じ固定基準と S-203 のランクを用いる
- 一覧で別の判定期間を選んでいる場合、帯の件数と一覧の件数は一致しない（帯は固定条件のため。02 と同じ考え方）

### REQ-SFV-F-016: 選択状態の保持

判定期間・絞り込み・ソートは URL に同期し、ブックマーク・共有で再現できること（02 の REQ-LFV-F-012 を踏襲）。

### REQ-SFV-F-017: 既存データとの互換

- 内示推移を持たない既存の集計スナップショットでも一覧が表示でき、需要予測は「なし」（在庫月数・在庫切れ予測月は非表示）として扱う
- 旧区分名・旧アラートレベルで保存された確認記録は読込時に新区分へ正規化する（02 の REQ-LFV-F-014・§6.2.1 の正規化に新区分名を追加）

### REQ-SFV-F-018: 異常系・エッジケース

| ケース | 扱い |
|---|---|
| 最終入荷日・最終出荷日が空 | 期間外（なし）として判定。「入荷なし」の状況表示は「入荷実績なし」 |
| 内示受注の取得に失敗（Oracle 障害等） | 取込自体は成功させ、内示推移を空として保持し、需要予測は実績ベースまたは「なし」にフォールバックする。失敗した旨をログと取込結果メッセージで示す |
| 内示受注数量が負値 | 0 として扱う |
| 需要予測が極端に小さい（在庫月数が 999 か月超） | 上限を設けず算出するが、表示は「十分」等に丸めてよい（丸め方は design.md） |
| 照合単位に SLIMS 在庫数が「未取得」の品番が混在 | 未取得は 0 として合算。全品番が未取得なら算出しない |
| 在庫が 0 で需要予測がある | 在庫切れ予測月は当月、在庫月数は 0.0 |
| 判定期間の URL 値が不正 | 既定（1 年）にフォールバック |
| 得意先品番に対応する内作品番が `M_CUST_ITEM` にない、または基準日に有効期間外 | 内示推移を空として保持し、需要予測は実績ベースまたは「なし」にフォールバックする |
| 1 つの得意先品番が複数の内作品番に対応する | それぞれの内示推移を照合単位の合算で扱う（(得意先, 内作品番) で重複を除く）。行への紐づけ方は design.md で定義する |
| 内示受注はあるが出荷実績がない新規品目（立ち上がり品） | 需要予測は内示で立つ。区分は「通常流動品」または「低流動品（出荷なし）」になり、緊急度の対象（低流動品（入荷なし））には入らない |

### REQ-SFV-F-019: 呼称の一貫性

画面・CSV・ダイアログ・メニュー画面のアラート帯・詳細で新区分名のみを用いる。旧称（供給リスク品・在庫過剰リスク品）、「判定軸」、「象限 N」を表示しない。

### REQ-SFV-F-020: 確認記録の移行措置

確認記録の「確認時の流動区分」は旧基準（低流動判定軸・3 か月）で保存されており、深刻化による未確認化（A-201）はこれと再取込後の区分をランク比較する。判定基準（1 年）とランク順が変わるため、旧基準の記録と新基準の区分を比較してはならない。

- **リリース時に、管理者が設定画面（SCR-02）の「確認状態リセット」を実行し、確認済み・確認中を全件「未確認」に戻す**。これをリリース手順に含める
- リセットでは確認メモ・メモ履歴は維持する（既存のリセット仕様どおり）。「確認時の流動区分」・確認者・確認日時は消去される
- リセット後は新基準の記録のみが存在するため、深刻化による未確認化は通常どおり動作する
- 確認記録が全件未確認に戻ること（メモは残ること）を、リリース前に利用者へ周知する
- 旧基準の記録を新基準へ自動変換する処理は**行わない**（変換規則を定義できないため）
