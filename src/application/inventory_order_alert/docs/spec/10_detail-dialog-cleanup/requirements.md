# 要件定義書: 詳細ダイアログを「在庫が切れるか」を軸に整理する

作成日: 2026/09/30
更新日: 2026/09/30
対応文書: [ubiquitous_language.md](../../ubiquitous_language.md)、[09_stock-simulation-chart/requirements.md](../09_stock-simulation-chart/requirements.md)、[08_stockout-risk-rework/requirements.md](../08_stockout-risk-rework/requirements.md)

## 1. 位置づけ

| 項目 | 内容 |
|---|---|
| 境界づけられたコンテキスト | **B: 在庫発注アラート** |
| 変更の種類 | **表示の再編のみ**。判定ロジック・データ取得は変更しない |
| 影響する画面 | 一覧（SCR-01）の**詳細ダイアログ** |

## 2. 背景と課題

### 2.1 きっかけ

spec/08（対応区分）・spec/09（グラフ 2 分割）を重ねた結果、詳細ダイアログが 8 区分になり「ごちゃごちゃしてきた」（2026/09/30 ユーザー指摘）。

### 2.2 課題

| # | 課題 | 内容 |
|---|---|---|
| 1 | **「切れるか」を 4 か所で述べている** | 流動区分 / 在庫シミュレーション / 対応区分 / 需要予測 |
| 2 | **うち 1 つだけ根拠が違う** | 需要予測の在庫切れ予測月（V-221）は**月平均需要**ベースで、対応区分の在庫切れ日（V-232、日次・内示）と別の日を指しうる。spec/09 で直した不整合の残り |
| 3 | **「次にすること」が 2 か所にある** | 流動区分の推奨アクション（T-207）と、対応区分の区分名 |
| 4 | **結論がどこにあるか分からない** | 上から読んでも、最初に出るのは流動区分（＝品目の性質であって切れるかではない） |
| 5 | **文言が読み手に変換を強いる** | 「算出根拠: 内示」「月平均需要 250」「在庫月数 0.5」など、何を意味するか一読で分からない |

## 3. 機能要件

### REQ-DDC-F-001: 「判定サマリ」を先頭に置く

詳細ダイアログの**最上段**に 判定サマリ（T-211）の区分を新設する。

| 要素 | 内容 |
|---|---|
| 見出し | 「この品番は **2026/10/10** に在庫が切れます。**2026/10/05** までに発注が必要です」のような**一文**（用語集 T-211 の表を正とする） |
| 対応区分 | S-204 の区分名 |
| 発注期限 | V-233 と、基準日からの残り日数（例「2026/10/05（あと 5 日）」） |
| 次にすること | 対応区分ごとの行動 |
| そう判断した理由 | `response_reasons` を箇条書き |

**新しい判定は行わない。** 既存の判定値（S-204・V-232・V-233・理由）を読み替えて文にするだけとする。

### REQ-DDC-F-002: 区分を 4 段構成に並べ替える

| 順 | 区分 | 内容 |
|---|---|---|
| 1 | **判定サマリ**（新設） | 結論 |
| 2 | **在庫シミュレーション** | 結論の根拠（日次のグラフ） |
| 3 | **品番情報** | 品目（得意先・品番・仕入先・リードタイム・発注方式・安全在庫・最終入荷日・最終出荷日）/ 在庫と発注残（在庫数・届く予定・納期遅れ・客先の出荷予定）を左右 2 列 → 在庫内訳(SLIMS) / 工程の連鎖 → 在庫推移（実績）のグラフ |
| 4 | **メモ** | 現状のまま |

**2026-09-30 改訂 (1)**: 当初は「在庫と発注残」を独立した区分（材料）としたが、参考の中へ統合して **4 区分**にした（ユーザー判断）。結論（判定サマリ）と根拠（在庫シミュレーション）以外はすべて参考という整理にする。
**2026-09-30 改訂 (2)**: 区分名「参考」を **「品番情報」** に改称し、流動区分の区分を撤去した（REQ-DDC-F-008）。
**2026-10-05 改訂 (3)**: 安全在庫・リードタイム・発注方式を「在庫と発注残」から「品目」へ移した（REQ-DDC-F-009）。

品目（得意先・品番・最終入荷日等）は結論より下でよい（誰の何かは一覧の行で分かっているため）。

### REQ-DDC-F-003: 需要予測区分を詳細ダイアログから撤去する

需要予測（V-220）・在庫切れ予測月（V-221）・在庫月数（V-222）・月平均需要を**詳細ダイアログに表示しない**。

- **算出と保存は続ける**（一覧のソート項目「在庫月数」が使うため。REQ-DDC-F-006）
- **月別内示数量**は「在庫と発注残」区分へ「客先の出荷予定（月別）」として移す

### REQ-DDC-F-004: 推奨アクション・責任部署を判定サマリへ一本化する

流動区分（S-203）由来の 推奨アクション（T-207）・責任部署（R-201）を、流動区分の区分では**表示しない**。判定サマリの「次にすること」に一本化する。

流動区分の区分に残すのは **区分名・状況・理由・判定期間**のみ。
→ **2026-09-30 に REQ-DDC-F-008 で区分ごと撤去した**（下記）。本要件はその過程として残す。

### REQ-DDC-F-005: 文言を読み手の言葉に直す

| 現状 | 変更後 |
|---|---|
| 算出根拠「内示」 | （撤去。判定サマリが「客先の出荷予定（内示）から」と述べる） |
| 予定入荷(納期>基準日) 900 | **届く予定 900（10/05 納期）** |
| 納期遅れの発注残 120 / 3 | **納期遅れ 120（3 件）— 在庫の計算に入れていません** |
| 安全在庫割れ あり | **安全在庫 1,000 を下回ります** |
| 状況「在庫なし・入荷はあるが在庫が残らない（最終入荷 …・最終出荷 …）」 | 日付部分を理由へ移し、状況は短くする |

### REQ-DDC-F-006: 一覧の機能を減らさない

一覧の列・ソート項目・フィルタ・CSV は**変更しない**。とくに「在庫月数」はソート項目として残す。

### REQ-DDC-F-007: 旧スナップショットの読込

判定サマリは対応区分（S-204）から作る。`response_class` を持たない旧スナップショットの行は **対象外** として扱い、見出しは「在庫は切れません」とする。例外にしない。

### REQ-DDC-F-008: 流動区分の区分を撤去し、「参考」を「品番情報」に改称する

**2026-09-30 追加（ユーザー指示）。** REQ-DDC-F-004 で推奨アクション・責任部署を判定サマリへ移した結果、
流動区分の区分に残ったのは 区分名・状況・理由・判定期間 の 4 行だけになった。
実データでは 通常流動品 / 状況 `-` / 判定期間 `1年` のように**読み手の判断に使われない行が並ぶ**ため、区分ごと撤去する。

| 対象 | 変更 |
|---|---|
| 詳細ダイアログの流動区分の区分（区分名 / 状況 / 理由 / 判定期間） | **撤去する** |
| 「参考」の区分名 | **「品番情報」** に改称する |
| 「在庫と発注残」の置き場所 | 流動区分があった位置（品目の右隣）へ移し、**品目と左右 2 列**に並べる |
| 一覧の流動区分列・絞り込み・件数サマリ・CSV | **変更しない**（REQ-DDC-F-006） |
| 流動区分・理由・推奨アクション・責任部署の**算出と保存** | **変更しない**（一覧が使う） |

改称の理由: 「参考」では中身が分からない。この区分に残るのはすべて**この品番そのものの情報**であるため（ユーザー判断）。

### REQ-DDC-F-009: 品目マスタ由来の 3 項目を「品目」へ移す

**2026-10-05 追加（ユーザー指示「安全在庫とリードタイムと発注方式は品目に入れて」）。**

**安全在庫（V-231）・リードタイム（V-225）・発注方式（V-227）** はいずれも **品目マスタ（`M_ITEM`）の属性**であって、
在庫数や発注残のように取込ごとに動く数量ではない。「在庫と発注残」から「品目」へ移す。

| 区分 | 移動後の項目（この順） |
|---|---|
| **品目** | 得意先 / 得意先品番 / 仕入先 / 仕入先品番 / **リードタイム** / **発注方式** / **安全在庫** / 最終入荷日 / 最終出荷日 |
| **在庫と発注残** | 在庫数(SLIMS) / 在庫数(MARI) / 届く予定 / 納期遅れ / 客先の出荷予定（月別） |

- 並びは **マスタ属性（仕入先品番の後）→ 実績の日付（最終入荷日・最終出荷日）** とする（ユーザー選択）
- **class 名は変えない**（`ioa-detail-safety-stock` / `ioa-detail-stockout-lead-time` / `ioa-detail-stockout-ordering-method`）。JS は class で引くため描画の変更は不要
- 安全在庫の「— 期間内に下回ります」の添え書き・リードタイムの「（既定値）」の表記は**変更しない**

## 4. 非機能要件

| # | 内容 |
|---|---|
| REQ-DDC-NF-001 | **判定ロジックを変更しない**。対応区分・在庫切れ日・発注期限・流動区分の既存テストが 1 件も変わらないことを条件とする |
| REQ-DDC-NF-002 | Oracle への問い合わせ・配信データ量を増やさない（既に配信済みの値の組み替えのみ） |
| REQ-DDC-NF-003 | 見出し文の組み立ては **domain の純関数**に置く。JS では文言を組み立てない（判定と文言を 1 か所に保つため） |

## 5. スコープ外

| # | やらないこと | 理由 |
|---|---|---|
| 1 | 対応区分・在庫切れ日・発注期限・流動区分の判定ロジック | spec/08・09 で確定済み |
| 2 | 一覧・CSV・件数サマリ・メニュー帯 | 詳細ダイアログのみ |
| 3 | 需要予測の**算出・保存・一覧ソート**の撤去 | 表示だけをやめる（REQ-DDC-F-003/006） |
| 4 | タブ化 | 印刷・画面キャプチャで一覧できなくなるため採らない（2026/09/30 ユーザー判断で案 A を採用） |
| 5 | グラフの描画仕様 | spec/09 で確定済み |

## 6. 受け入れ基準

| # | 基準 |
|---|---|
| 1 | 詳細ダイアログの最上段が判定サマリで、対応区分ごとに定めた見出し文が出る |
| 1b | 在庫シミュレーションの下に、在庫切れ日・発注期限を繰り返す注記が**出ない**（判定サマリと重複するため。2026-09-30 追加） |
| 2 | 区分が 判定サマリ → 在庫シミュレーション → 品番情報 → メモ の 4 つに並び、在庫と発注残が品番情報の中にある |
| 3 | 需要予測区分・在庫切れ予測月・月平均需要・在庫月数が詳細ダイアログに**出ない** |
| 4 | 月別内示数量が「在庫と発注残」区分に出る |
| 5 | 推奨アクション・責任部署が流動区分の区分に**出ず**、判定サマリに出る |
| 5b | 詳細ダイアログに 流動区分の区分名・状況・理由・判定期間が**出ない**。区分の見出しが「参考」ではなく「品番情報」である（REQ-DDC-F-008） |
| 5c | 一覧の流動区分列・絞り込み・件数サマリ・CSV が従来どおり動く（流動区分の算出・保存は不変） |
| 5d | 安全在庫・リードタイム・発注方式が「品目」に出て、**「在庫と発注残」には出ない**。「品目」では 仕入先品番の後・最終入荷日の前に並ぶ（REQ-DDC-F-009） |
| 6 | 一覧のソート項目に「在庫月数」が残っている |
| 7 | 対応区分・在庫切れ日・発注期限・流動区分の既存テストが全件そのまま通る |
| 8 | 旧スナップショットの行で例外が出ず、「在庫は切れません」と出る |
| 9 | 見出し文の組み立てが domain の純関数にあり、JS に文言の組み立てがない |
