## 1. 背景と目的

### 1.1 背景

06（在庫切れリスク）を実データで確認したところ、SLIMS 在庫のない行（2,299 行中 693 行）が「在庫 0」として在庫切れリスクの危険に大量に上がった。しかし在庫がない理由は一様でなく、**供給が遅れて入荷したそばから出荷している**（欠品）、**供給が終わった**（打ち切り候補）、**本当に補充が来ていない**（欠品（入荷なし））が混在しており、現行の流動区分（期間内入荷 × 期間内出荷の 4 分類）では切り分けられない。また需要予測の実績ベースが 12 か月平均のため、半年前に出荷が止まった品目まで「需要あり」に見えていた。

### 1.2 調査で確定した事実（9/18 スナップショット、brainstorm 相当の測定）

| 事実 | 数値 |
|---|---|
| SLIMS 在庫なしの行 | 693 / 2,299（在庫切れリスク 危険 152・注意 249・監視 282） |
| うち 30 日以内に入荷と出荷がある（欠品。旧称 入荷即出荷） | 212 |
| うち 内示なし・出荷 3 か月超なし（改訂前の需要なし） | 354 |
| うち 需要あり・30 日以内に入荷なし | 113（得意先 105 の「入荷記録なし・出荷継続」を含む） |

上表の「需要なし」は改訂前（内示または直近 3 か月出荷）の定義による。改訂後（内示のみ）の内訳はタスク 15 の実データ確認で記録する。
| 得意先品目マスタの適用終了日が過去 | 7（打ち切りの確定情報は基幹にほぼない） |
| 「出荷なし × 内示あり」14 行のうち入荷が 6 か月以上続くもの | 12（立ち上がりではなく出荷が基幹に記録されない経路） |
| 出荷実績が一度もなく内示のある 得意先 × 内作品番 | 22（うち初回入荷済み 11。**現行の一覧には行が存在しない**） |

業務知識（2026/09/18）: 在庫を持たない運用は基本的にない。在庫なしで入荷即出荷は **製品が遅延している状態**。

### 1.3 目的

1. SLIMS 在庫のない行を、対処が異なる 3 区分（欠品（入荷なし）／欠品／打ち切り候補）に切り分け、流動区分で絞り込めるようにする
2. 需要の判定を内示のみに基づかせ、止まった品目を需要ありと見なさない（出荷実績の平均を予測に混ぜない）
3. 在庫切れリスクの判定を新区分の前提に合わせ、欠品を危険の中心に、打ち切り候補・通常流動品を監視以下にする

## 4. 機能要件

### REQ-FQR-F-001: 流動区分の 7 分類

行ごとに次の順で評価し、最初に該当した区分にする（用語集 S-203 の表）。

| ランク | 区分 | 条件 |
|---|---|---|
| 0 | 欠品（入荷なし） | SLIMS 在庫なし かつ 需要あり かつ 直近入荷なし |
| 1 | 欠品 | SLIMS 在庫なし かつ 需要あり かつ 直近入荷あり |
| 2 | 低流動品（入荷なし） | 在庫あり かつ 期間内出荷あり かつ 期間内入荷なし |
| 3 | 在庫死蔵品 | 在庫あり かつ 期間内入荷なし かつ 期間内出荷なし |
| 4 | 低流動品（出荷なし） | 在庫あり かつ 期間内入荷あり かつ 期間内出荷なし |
| 5 | 打ち切り候補 | SLIMS 在庫なし かつ 需要なし |
| 6 | 通常流動品 | 上記以外 |

- **SLIMS 在庫なし** = 取込時の SLIMS 在庫に当該得意先品番の行がない（`stock_qty` が空）。在庫が未取得（旧スナップショット）は「在庫あり」として扱う（旧行を欠品にしない）
- **需要あり** = 内示推移（翌月〜翌々々月）に数量がある（＝需要予測 V-220 の算出根拠が `内示`）。出荷実績は用いない（2026/09/18 改訂。改訂前は「または直近 3 か月に出荷がある」）
- **直近入荷あり** = 最終入荷日が 基準日 − `recent_incoming_days`（設定、既定 30 日）以降
- 期間内入荷・期間内出荷は判定期間（1/3/5 年）で従来どおり。欠品 2 区分と打ち切り候補は判定期間によらない（`flow_quadrants` 行列の Y1/Y3/Y5 すべてで同じ）
- 旧称・旧キーの互換（`normalize_flow_quadrant`）は維持する

### REQ-FQR-F-002: 需要予測を内示のみに（実績ベースの廃止）

- 需要予測（V-220）は内示推移の合算のみで算出する。内示推移が 3 か月とも 0 なら「なし」
- 出荷実績の平均による代替（旧「実績ベース」。05 F-008 の 12 か月平均、本書の当初案の 3 か月平均）は **行わない**。算出根拠は `内示` / `なし` の 2 値
- 内示のない照合単位は 在庫切れ予測月・在庫月数・緊急度が空となり、在庫切れリスク（S-204）は「監視」になる（出荷が続いていても危険・注意には上がらない。人が見る運用とする）
- 推定在庫推移グラフの予測部分（V-218）は内示のない照合単位では描かない
- 在庫切れリスクの理由「需要は実績ベース」は廃止する
- **在庫切れ予測月（V-221）の改訂（2026/09/21 追加）**: 「在庫 0 以下は当月」の特例を廃止し、「当月残と月別需要を順に引いて初めて負になる月」の一般規則だけにする。在庫 0・当月残 0・翌月 0・翌々月 320 の照合単位は翌々月が在庫切れ予測月（従来は当月）。在庫 0・当月残 50 なら当月（従来どおり）。SLIMS に行がない得意先品番は在庫 0 として計算する

### REQ-FQR-F-003: 推奨アクション・状況・責任部署

用語集 S-203 の表のとおり 7 区分ぶんを定義する。定義ファイル（`recommended_actions.json`）のキーに新区分のキー（`stockout-no-incoming` / `stockout` / `discontinuation-candidate`）を加える。

### REQ-FQR-F-004: 在庫切れリスクとの整合

- 打ち切り候補は需要なしのため自動的に監視。通常流動品は 06（補正 3 まで）の規則で判定する
- 欠品（在庫なし・需要あり）は 06 の判定順を **免除なし** で通す（2026/09/21 改訂、ユーザー選択「猶予日数を使う」）: 猶予日数（V-228）≤ リードタイム＋安全日数 かつ 補充見込みが不足数量に満たなければ **危険**、それ以外（猶予がある／補充が足りている／納期超過あり）は **注意**。**対象外にはしない**。理由に「在庫なし」を付け、直近入荷ありなら「供給遅延（入荷即出荷）」を添える
- 欠品（入荷なし）も同じ判定。入荷の記録が一度もない行は理由「入荷の記録なし・経路要確認」
- 06 補正 3 とのすり合わせ（2026/09/21）: 06 の「補充サイクル稼働中（直近に入荷あり）は危険にしない」は **在庫がある かつ MRP 発注** の行に限る。06 の「MRP 先送り（発注期限が先・発注残なしは対象外）」は **在庫がある** 行に限る（欠品は対象外にしない）

### REQ-FQR-F-005: 理由（補足）

流動区分の判定根拠として、行に次の補足を持ち詳細ダイアログに示す: 「入荷の記録なし・経路要確認」（欠品（入荷なし）で最終入荷日が空）、「入荷 < 需要」（欠品で直近の入荷数量が翌月の内示を下回る）、「{判定期間}以上出荷なし・経路要確認」（欠品 2 区分で期間内出荷（V-213）がない）、「内示あり（立ち上がり／出荷経路要確認）」（低流動品（出荷なし）で内示あり）、「適用終了日 YYYY/MM/DD」（打ち切り候補で得意先品目マスタの終了日が過去）。

**期間判断の基準（2026/09/21 統一、ユーザー判断「基準は一つにしたい」。用語集 V-211 に定義）**

期間にかかわる判断は**すべて判定期間（V-211）で行う**。値は「選択 UI がある画面（一覧）は利用者の選択値、選択 UI がない場所（メニュー帯・深刻化判定）は既定 1 年」の 1 規則で決まる。理由もこの基準に従う。

- 「{判定期間}以上出荷なし・経路要確認」は **期間内出荷がない**ことを条件とし、文言の判定期間は表示中の値で埋める（例: 1年以上出荷なし・経路要確認）
- 対象は **欠品・欠品（入荷なし）の 2 区分**。出荷が基幹に記録されない経路の疑いは直近入荷の有無と関係しないため
- 理由は流動区分と同じく判定期間で変わるので、行は **3 期間ぶん（Y1/Y3/Y5）の理由**を持ち、一覧の期間切替でクライアントが引き直す（流動区分の `flow_quadrants` と同じ持ち方。判定ロジックは JS に持ち込まない）

  > **［2026/09/21 改訂前］** 条件は「欠品で最終出荷日が空（出荷実績が一度もない）」だった。一覧は出荷実績のある 得意先 × 得意先品番 から組み立てるため該当が構造上存在せず（実データ 2,299 行中 0 件、§1.2 の「出荷実績が一度もない 22 行は現行の一覧には行が存在しない」と整合）、理由が一度も出ない状態だった。判定期間基準では 1 年で 25 行が該当する。

**「入荷 < 需要」の比較対象（2026/09/21 確定、ユーザー選択）**:

- **入荷側** = **最終入荷日（V-215）が属する月**の入荷推移（V-217）の合計。入荷推移は月次の合計しか持たず「直近 30 日」を日単位で切り出せないため、直近に入荷があった月の実績で代表する。基準日が月初でも月末でも結果がぶれず、前月の大量入荷に今月の不足が隠れることもない
- **需要側** = **翌月の内示**（需要予測 V-220 の `monthly` の先頭）。月平均需要は内示のある月だけの平均で遠い先の需要をならした予測値であり、今この瞬間の供給不足を見る本理由には用いない。翌月の内示が 0 の行（需要が翌々月以降に始まる）は理由を出さない（その月が近づけば出る）

### REQ-FQR-F-006: 画面・CSV・メニュー帯

- 流動区分フィルタ・判定ルールダイアログ・詳細ダイアログ・CSV の流動区分値を 7 区分に。判定ルールダイアログは 7 行（条件列を「在庫 / 需要 / 直近入荷 / 期間内入荷 / 期間内出荷」に）
- メニュー帯の流動区分の件数行を「欠品（入荷なし） N 件 / 欠品 N 件 / 低流動品（入荷なし） N 件 / 在庫死蔵品 N 件」に
- 行の色は在庫切れリスクのみ（06 のまま）

### REQ-FQR-F-007: 深刻化による未確認化

A-201 は新ランクで判定する（例: 低流動品（入荷なし）→ 欠品（入荷なし）で未確認に戻る）。旧称で保存された確認記録は従来どおり正規化する。

### REQ-FQR-F-008: 設定

設定画面に `recent_incoming_days`（1〜90、既定 30）を追加する（第 2 段階。第 1 段階は既定値）。当初案の `demand_window_months`（需要の窓）は F-001 の改訂により不要になったため設けない。

### REQ-FQR-F-009: 既存データとの互換

旧スナップショット（在庫未取得）は在庫ありとして 4 区分のいずれかになり、欠品・打ち切り候補にはならない。

### REQ-FQR-F-010: 異常系

| ケース | 期待 |
|---|---|
| 在庫キーなし（旧行） | 在庫ありとして扱う |
| 内示推移なし（旧行・出荷推移の有無によらず） | 需要なし → 在庫なしなら打ち切り候補、在庫ありなら 4 区分 |
| 最終入荷日が空 | 直近入荷なし。欠品（入荷なし）なら理由「入荷の記録なし」 |
| 得意先品目マスタに終了日なし | 補足なし |

## 5. 非機能要件

- 判定は取込時に行い保存する（05・06 と同じ）。表示時の判定期間切替は期間内入荷・出荷の部分のみクライアントで引き直す（欠品・打ち切り候補は行列の全キーで同じ）
- 用語・命名は用語集に従う。旧識別子の走査（`test_legacy_alert_identifiers_removed.py`）を維持

## 6. 前提条件・制約事項

- 立ち上がり品（出荷実績が一度もなく内示のある品番）は一覧の集計対象外（出荷実績のあるペアのみ集計）のため、本書では区分にしない。対象拡大は別件
- 打ち切りの確定情報は基幹にない。「打ち切り候補」は需要なしの代用判定であり、確認済みにする運用で補う
- 05 requirements F-003（4 分類）・F-008（実績ベース 12 か月。本書 F-002 で廃止）、06 requirements F-005（危険の条件）・想定ケース 9（需要が実績ベースのみ）は本書で置き換える

## 7. スコープ外

- 一覧の対象拡大（内示のみの品番・立ち上がり品）
- 記録外品（入荷／出荷が基幹に載らない経路）の専用区分（理由で示すに留める）
- 打ち切り確定情報の取り込み
