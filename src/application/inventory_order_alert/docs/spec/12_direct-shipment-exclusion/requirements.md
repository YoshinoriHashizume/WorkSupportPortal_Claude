# 要件定義書: 直送品を在庫発注アラートの対象から外す

文書ID: REQ-DIRECT-SHIPMENT-EXCLUSION-2026-001
作成日: 2026/11/25
更新日:
対応文書: [ubiquitous_language.md](../../ubiquitous_language.md)（UL-INVENTORY-ORDER-ALERT-2026-001）、[11_judgement-scope/requirements.md](../11_judgement-scope/requirements.md)（REQ-JUDGEMENT-SCOPE-2026-001）、[在庫発注アラート_機能仕様書.md](../../在庫発注アラート_機能仕様書.md)
対象スコープ: 直送仕入先（V-240）から仕入れ SLIMS を通らない直送品（T-212）を、対応区分（S-204）の判定と一覧・件数サマリ・アラート帯・CSV から外し、直送仕入先を設定画面で変更できるようにする

---

## 1. 背景と目的

### 1.1 背景

利用者から「在庫発注アラートで確認する品番が多すぎる。もっと絞れないか」との相談を受けた（2026/11/25）。
要対応（S-204）の内訳を調べたところ、**発注遅れの大半が、SLIMS 在庫数（V-206）がすべて空の照合単位**だった。

これらは、グループ会社の丸栄豊田などから仕入れている得意先品番である。**売りと買いの伝票は基幹（MARI）を通るが、品物は仕入先から得意先へ直接納入され、SLIMS（丸栄ニューウェーブ）の倉庫を通らない**。
そのため SLIMS 在庫数（V-206）が空になり、在庫の見通しが 0 から始まる。実際には品物が流れているのに、翌日に在庫切れ → 発注期限切れ → **発注遅れ**と判定されている。
在庫切れ日・発注期限・在庫月数・流動区分なども同じく在庫 0 を起点にしており、直送品では**どの値も事実を表さない**。そのため直送品は判定せず、**一覧にも CSV にも出さない**（2026/11/25 ユーザー判断）。

### 1.2 調査で確定した事実（根拠）

実データ（開発環境スナップショット、BOM 基準日 2026/11/02、2,301 行、照合単位 2,032）:

| 観測 | 値 | 意味 |
|---|---|---|
| 発注遅れのうち、SLIMS 在庫数がすべて空の照合単位 | **174 単位中 150 単位（86%）** | 発注遅れの大半が直送の疑い |
| 丸栄豊田（9100）の照合単位のうち SLIMS 在庫数が空 | 258 単位中 257 単位 | ほぼ全量が SLIMS を通らない |
| 丸栄豊田（福岡）（9250）・テクノス工場（9200） | 20 / 29 単位すべて空 | 同上 |
| 誠豊電子・丸栄ニューウェーブ・丸栄宮崎 | 空と在庫ありが混在 | 直送ではない。SLIMS にない理由は別（未登録か本当に在庫 0） |
| 直送仕入先と直送でない仕入先が混在する照合単位 | 0 単位 | 丸栄豊田では業務上起こらない（2026/11/25 業務確認） |
| 直送品（T-212）の条件に当たる照合単位 | **306 単位（306 行）** | うち要対応は 発注遅れ 119 行・要発注 16 行。納期確認・要監視は 0。残る 171 行は対象外 |

### 1.3 目的

**SLIMS を通らないために在庫で判定できない照合単位を一覧から外し、利用者が本当に手を打つべき得意先品番に集中できるようにする。**
直送仕入先の登録を誤っても、SLIMS 在庫数のある得意先品番は外さない。また、設定から外せば次回取込から再び一覧に出るようにし、誤りを取り消せるようにする。

## 4. 機能要件

要件 ID は spec/11 と同じく機能名入り形式（`REQ-DSE-*`）とする。同一アプリ内に要件定義書が 11 件並存しており、横断参照で ID を一意にするため。

### REQ-DSE-F-001: 直送仕入先を設定画面で登録・解除できる

- 管理者は設定画面で、直送仕入先（V-240）として扱う**仕入先コードを追加・削除**できる
- 登録済みの直送仕入先は**仕入先コードと仕入先名を並べて**表示し、どの仕入先を登録したかが分かる
- 同じ仕入先コードは重複して登録できない。空の仕入先コードは登録できない
- 実在しない仕入先コードは登録できない（存在の確かめ方は design.md で定義する）
- 存在を確かめられない場合（基幹に接続できない等）は登録せず、登録できなかった理由を利用者に示す
- 登録済みの仕入先コードが後で仕入先マスタから見つからなくなった場合も、登録は残し判定に使い続ける。仕入先名は分からない旨を表示する
- 0 件も許す（0 件のときは直送品が 1 件もない＝本機能を使わない状態）
- 初期値は `9100` 丸栄豊田・`9250` 丸栄豊田（福岡）・`9200` テクノス工場とする。本番導入時にもこの 3 件が登録された状態にする

### REQ-DSE-F-002: 直送品を判定する

取込時に、照合単位（T-208）ごとに直送品（T-212）かどうかを判定する。次の**すべて**を満たすものを直送品とする。

| # | 条件 |
|---|---|
| 1 | 照合単位に属する仕入先が、**すべて**直送仕入先（V-240）である |
| 2 | 照合単位に含まれる得意先品番の SLIMS 在庫数（V-206）が、**すべて空（該当なし）**である |

- 直送仕入先から仕入れる照合単位でも、SLIMS 在庫数が空でない得意先品番（数量 0 を含む）が 1 つでもあれば直送品としない（通常どおり判定する）
- 仕入先が空の行を含む照合単位は、条件 1 を満たさないものとする
- 直送品の判定は、同じ照合単位のすべての行で同じ結果になる
- 1 回の取込は、**取込を開始した時点の直送仕入先**で最後まで判定する。取込の途中で設定が変わっても、その取込の結果には混ぜない

### REQ-DSE-F-003: 直送品を一覧・件数・CSV に出さない

- 直送品の照合単位に属する行は、**一覧・件数サマリ・アラート帯の件数・CSV のいずれにも出さない**
- 直送品は対応区分（S-204）を判定しない。**納期遅れの発注残があっても要対応にしない**（直送品は本アプリの守備範囲外とする。2026/11/25 ユーザー判断）
- 一覧の絞り込みの候補（担当者コード・得意先コード等）は、一覧に出す行から作る（既存の規則どおり）。直送品の行にしか現れない値は候補に出ない
- **直送品の件数や一覧を画面に出す手段は設けない**（2026/11/25 ユーザー判断）。どの得意先品番が直送品かを確かめたいときは、直送仕入先から外して再取込する（REQ-DSE-F-005）

### REQ-DSE-F-004: 一覧の既存機能を減らさない

- 一覧の列・ソート項目・絞り込み・件数サマリ・詳細ダイアログ・CSV の**構成は変えない**。出る行が直送品の分だけ減るだけとする
- CSV は「スナップショット全件」から「**直送品を除く全件**」になる。絞り込みに関係なく出力する方針は変えない

### REQ-DSE-F-005: 設定変更は次回取込から反映する

- 直送品の判定は取込時に行うため、直送仕入先を変えても、**次に SLIMS 在庫 CSV を取り込むまで一覧は変わらない**。設定画面にその旨を明記する（判定ホライズン・既定リードタイムと同じ扱い）
- 直送仕入先から外した仕入先の照合単位は、次回取込から通常どおり判定され、一覧・件数サマリ・アラート帯・CSV に戻る
- 本機能より前に保存されたスナップショットは、次回取込までは従来どおりすべての行を表示する（例外にしない）

### REQ-DSE-F-006: 確認記録は直送品になっても残す

- 直送品になった得意先品番の確認状態（S-201）・確認メモ（E-202）は削除・変更しない
- 直送仕入先から外れて一覧に戻ったときも、確認記録は引き継がれる

## 5. 非機能要件

### REQ-DSE-NF-001: Oracle への問い合わせを増やさない

取込時の Oracle への問い合わせ回数を増やさない。直送品の判定は、既に取得している仕入先コードと SLIMS 在庫数だけで行う。

### REQ-DSE-NF-002: 判定は domain の純関数に置く

直送品の判定は domain の純関数に置き、単体テストで固定する。JS では判定しない。

### REQ-DSE-NF-003: 直送品でない照合単位の結果を変えない

在庫切れ日・発注期限・安全在庫割れ・在庫シミュレーション・対応区分・流動区分について、**直送品でない照合単位の算出結果と表示は 1 件も変わらない**。既存テストが全件そのまま通ることを条件とする。

### REQ-DSE-NF-004: 設定の変更は管理者に限る

直送仕入先の登録・解除は、既存の設定画面と同じく管理者だけが行える。変更した利用者と日時が残る（既存の設定と同じ扱い）。

## 6. 前提条件・制約事項

### 6.1 外部システム / API 制約

| 外部システム | 制約 |
|---|---|
| 基幹（MARI） | 読み取りのみ。**直送を示すフラグは基幹に存在しない**ため、仕入先コードを設定で指定する方式とする |
| SLIMS | 丸栄ニューウェーブの倉庫の在庫のみを持つ。直送品は SLIMS 在庫 CSV に現れない |

### 6.2 既存システムへの影響

| 対象 | 影響 |
|---|---|
| 一覧（SCR-01） | 直送品の行が出なくなる（実測 2,301 → 1,995 行）。件数サマリ・絞り込みの候補も、一覧に出す行から作られる |
| 詳細ダイアログ | 変更なし（直送品の行は一覧に出ないため開かれない） |
| 設定画面（SCR-02） | 直送仕入先の登録欄が増える。次回取込から反映される旨を明記する |
| 設定値の保存 | 直送仕入先を保存する場所が増える。本番導入時に初期値 3 件が登録された状態にする |
| アラート帯 | 件数が減る |
| CSV | 直送品の行を出さない（列の構成は変えない） |
| 用語集 | T-212 を「判定せず、一覧・件数サマリ・アラート帯・CSV に出さない」に改める |
| 機能仕様書・テスト仕様書 | 実装完了時に更新する（機能仕様書 §4.1 一覧・CSV の「全件」の記述、§4.2 設定、§6.2 対応区分。テスト仕様書の該当ケース） |
| 運用 | 利用者に周知する（丸栄豊田などの得意先品番が一覧から消える。導入報告の「要対応 722 件」などの件数も変わる） |

## 7. スコープ外・将来検討事項

| 項目 | 対応方針 |
|---|---|
| 直送品の件数・一覧を画面で確かめる手段 | 設けない（2026/11/25 ユーザー判断）。確かめるときは直送仕入先から外して再取込する |
| 直送品の流動区分（S-203）・在庫月数（V-222）・在庫切れ予測月（V-221） | 算出方法は変えない。直送品は一覧・CSV に出さないため、事実と異なる値が利用者に見えることはない |
| 直送品の納期遅れを追う仕組み | 本アプリの守備範囲外とする（2026/11/25 ユーザー判断） |
| SLIMS 在庫数が空で、直送品でない照合単位（誠豊電子など）の扱い | 本件では変えない。SLIMS 未登録か本当に在庫 0 かの切り分けは別途検討 |
| 得意先品番単位での直送の指定 | 行わない。仕入先単位で足りる（丸栄豊田では混在が起こらない） |
| 基幹で直送を判別する方法の調査 | 行わない。フラグが存在しないため設定で代替する |
| 要対応の他の絞り込み案（納期当日の扱い・照合単位での集計・発注期限ベースのホライズン等） | 別件として後続で検討する |
