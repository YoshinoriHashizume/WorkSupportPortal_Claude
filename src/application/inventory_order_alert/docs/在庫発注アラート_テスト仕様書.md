## 2. 目的

| 目的 | 説明 |
|------|------|
| 回帰防止 | 5年9組準拠の BOM・入荷・出荷集計ロジックが Web 化後も検証スクリプトと一致することを保証する |
| SLIMS 在庫連携 | CSV 取込・品番突合・スナップショット置換が仕様どおり動作することを検証する |
| 流動区分の固定 | **7 分類**（欠品 2 区分 / 低流動品 2 区分 / 在庫死蔵品 / 打ち切り候補 / 通常流動品）の境界条件をテストで固定し、誤検知・見逃しを防ぐ（§6.2） |
| 在庫切れリスクの固定 | **危険 / 注意 / 監視 / 対象外** の判定順と理由を固定する（§6.2.3） |
| 期間判断の基準 | 期間にかかわる判断がすべて判定期間（V-211）で行われ、判定期間を切り替えても在庫なしの 3 区分・需要予測・在庫切れリスクが変わらないことを固定する（§6.2.0） |
| 確認状態の保証 | PostgreSQL への確認状態・確認メモ・フィルタ・表示が仕様どおり動作することを検証する |
| 外部依存の分離 | CI では実 Oracle・実 SLIMS に接続せず、ドメイン層単体テストを最優先する |

## 4. テスト戦略

### 4.1 テストピラミッド

1. **単体テスト（最優先）** … 純関数: 流動区分・判定材料・理由、需要予測、在庫切れリスク、出荷集計、入荷解決、SLIMS CSV パース、在庫突合、日付変換、CSV ヘッダ、ソートキー
2. **結合テスト（限定的）** … Django views / API に Oracle・DB を **モック** して 401/403/400/200 を検証
3. **E2E（任意）** … ログイン済みブラウザで一覧表示・SLIMS 取込・CSV ダウンロードのスモーク

### 4.2 共通原則

| 原則 | 内容 |
|------|------|
| 決定性 | `asOfDate`・`today`・設定値（判定期間・直近入荷の日数・安全日数・既定リードタイム・監視期間）は **引数化** し、テスト内で固定値を使用する。07 の基準日は **2026-09-18** に固定する |
| 判定ロジックの一元化 | 流動区分・在庫切れリスクの判定は domain のみに置く。JS 側のテストは「サーバが配信した値を引くだけ」であることを**ソース文字列の検査**で固定する（`test_inventory_order_alert_list_js.py`） |
| スクリプトとの一致 | domain 層の Oracle 出力が検証スクリプト `build_summary_rows` と同一になるよう、fixture データで比較テストを行う |
| SLIMS サンプル | 機能仕様書 §4.1.2 の想定フォーマットに基づく最小 CSV fixture をリポジトリに同梱する |
| 秘密情報 | `ORACLE_*` をリポジトリ・ログに含めない |
| 本番 Oracle 非依存 | CI では実 Oracle に接続しない |
