## 背景

1. 会社単位フィルタは実装しないことが確定した。仕様書・ユビキタス言語から「将来の会社単位フィルタ」を前提とした記述を削除する。
2. 棚卸を選ぶたびに desknet's から最新データを取得したい。ただしフィルタ・ソート・ページング・CSV は desknet's へ取りに行かず、メモリ上（ブラウザ内 `aiv-list-data`）または突合結果スナップショット（Django セッション）で行う。

## 影響範囲

- 一覧画面の表示ごとに資産・棚卸・拠点マスタの `list_data` が発行される（従来は棚卸選択の変更時のみ）。desknet's への API 呼び出し回数が増える。
- フィルタ・ソート・ページングはブラウザ内ローカル処理のためサーバ往復が発生せず、API 呼び出しは増えない（従来どおり）。
- CSV 出力はスナップショット再利用のため desknet's を呼ばない（従来どおり）。
- 拠点マスタのみ取得失敗した縮退結果をスナップショットに保存しない規定（§7.4.1）は維持する。

## 削除対象（明示）

- 機能仕様書 §2.4 スコープ外 行6「会社単位のフィルタ」（以降の行番号を繰り上げ）
- 機能仕様書 §5.5 の一文「会社単位フィルタを追加する段階で取得を実装する。」
- 機能仕様書 §6 mermaid の `list_data 会社/拠点/資産/棚卸 app_id` の「会社/」
- ユビキタス言語 E-305 の「および将来の会社単位の絞り込み」
- ※ 棚卸データ管理の参照列としての **会社マスタ**（§2.1・§3.1・UL E-301/E-305・`MANAGEMENT_FIELDS`）は desknet's 側の事実のため残す
- ※ 改訂履歴・レビュー履歴の既存行は履歴のため書き換えない
