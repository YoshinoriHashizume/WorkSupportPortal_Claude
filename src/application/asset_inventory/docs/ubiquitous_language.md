## 1. エンティティ

### E-301: 棚卸データ管理

- **英語名**: `InventoryManagement`
- **定義**: desknet's NEO（core SYS-001）上のアプリ（`app_id=401`）で、年度・会社・拠点・突合対象のデータセットをひとまとめに定義する行。画面の棚卸セレクトの選択単位となる。
- **構成要素**: データID・棚卸項目・年度・参照先 app_id（会社マスタ／拠点マスタ／資産データ／棚卸データ）。
- **使用しない表現**: 「棚卸マスタ」「棚卸ヘッダ」「管理データ」

### E-302: 資産データ

- **英語名**: `AssetLedger`
- **定義**: desknet's NEO 上で管理する **固定資産台帳**。突合における台帳側の入力。
- **使用しない表現**: 「資産台帳データ」「固定資産マスタ」「台帳」（単独）
- **補足**: 突合の前に 棚卸対象資産（V-303）の条件で絞り込む。

### E-303: 棚卸データ

- **英語名**: `InventoryRecord`
- **定義**: desknet's NEO 上で管理する **現地読取結果**。突合における実績側の入力。棚卸日時・棚卸実施者・資産写真等を持つ。
- **使用しない表現**: 「棚卸実績データ」「読取データ」「現物データ」
- **補足**: 台帳外の判定に用いるため、棚卸対象資産（V-303）の条件では絞り込まない。

### E-304: 拠点マスタ

- **英語名**: `SiteMaster`
- **定義**: 棚卸データ管理（E-301）が参照する desknet's アプリ。管理部門コードから拠点（V-302）を解決するために用いる。
- **構成要素**: `データID`（拠点識別子）・`管理部門コード`（突合キー）・`拠点名`（表示・フィルタ用）の 3 部品に確定済み（[資産棚卸結果_機能仕様書.md](./資産棚卸結果_機能仕様書.md) §3.1）。
- **使用しない表現**: 「工場マスタ」「事業所マスタ」
- **補足**: 工場変化判定（A-302）の正。取得できない環境では管理部門コードの直接比較にフォールバックする。

### E-305: 会社マスタ

- **英語名**: `CompanyMaster`
- **定義**: 棚卸データ管理（E-301）が参照する desknet's アプリ。棚卸データ管理の参照列としてのみ存在し、**本機能では取得・表示を行わない**。
- **使用しない表現**: 「法人マスタ」「組織マスタ」
- **補足**: 工場変化判定（A-302）には用いない（拠点マスタ E-304 を正とする）。

## 2. バリューオブジェクト

### V-301: 突合キー

- **英語名**: `ReconcileKey`
- **定義**: 資産データ（E-302）と棚卸データ（E-303）を対応づけるキー。`正規化(資産番号)` + `|` + `正規化(資産枝番)`。
- **構成要素**: 資産番号は前後空白を除去し、**先頭が `L` または `l` のとき 1 文字除去**する。資産枝番は前後空白を除去する。
- **使用しない表現**: 「照合キー」「マッチングキー」
- **補足**: 画面の資産番号列は原値を表示し、突合とフィルタは正規化後の値で行う。

### V-302: 拠点

- **英語名**: `Site`
- **定義**: 資産の設置場所を表す単位。一覧の拠点名列は資産データ／棚卸データの `管理部門名称` を表示し、工場変化（A-302）の判定は `管理部門コード` を拠点マスタで解決した拠点識別子で行う。
- **使用しない表現**: **「工場」（単独）「事業所」「部門」**
- **補足**: 表示・フィルタの経路（`管理部門名称`）と判定の経路（`管理部門コード` → 拠点マスタ）が異なる点に注意する。判定名としての「工場変化」は旧来の業務呼称として存続する。

### V-303: 棚卸対象資産

- **英語名**: `InventoryTargetAsset`
- **定義**: 資産データのうち `生産品番⑧コード` が TRIM 後 **`1` と完全一致** する資産。台帳側の突合対象を限定する固定条件（利用者は変更できない）。
- **使用しない表現**: 「対象資産」（単独）「棚卸フラグ」

### V-304: 資産番号

- **英語名**: `AssetNumber`
- **定義**: 固定資産を識別する番号。資産データ（E-302）・棚卸データ（E-303）の双方が持ち、資産枝番（V-305）と組で突合キー（V-301）を構成する。
- **構成要素**: 文字列。画面には **原値** を表示し、突合・絞り込みには正規化後（前後空白除去、先頭 `L`/`l` を1文字除去）の値を用いる。
- **使用しない表現**: 「資産コード」「管理番号」「固定資産番号」
- **補足**: 先頭 `L` は同一資産を指す別表記として扱う（例: `L5262` と `5262` は同一）。**`L` の業務上の由来は未確認**（採番規則の確認が必要）。

### V-305: 資産枝番

- **英語名**: `AssetBranchNumber`
- **定義**: 同一の資産番号（V-304）に属する個体を識別する枝番。
- **構成要素**: 文字列。前後空白を除去し、空は空文字のまま扱う（空も有効な値である）。
- **使用しない表現**: 「枝番号」「サブ番号」「連番」
- **補足**: 取り込み用データ（V-306）へ出力する際は、数字のみの場合に 4 桁ゼロ埋めとする（例: `1` → `0001`）。**空値は空欄のまま出力し、チェック仕様（V-310）の `O` 違反として警告する**（ASP 側で補記が必要なため）。

### V-306: 取り込み用データ

- **英語名**: `AspImportData`
- **定義**: 棚卸で判明した変更を ASP（SYS-302）の『資産／異動情報修正入力』へ貼り付けるために出力する CSV。ヘッダー行を持たず、ASP の入力レイアウトと同じ列の並び・列数で構成する。
- **構成要素**: 修正対象行（V-307）の集合。1 行は貼り付けレイアウト（V-309）に従う **75 列固定**。ヘッダー行を持たず、値を持たない列は空欄。文字コードは UTF-8（BOM 付き）、改行コードは CRLF。
- **使用しない表現**: 「ASP連携ファイル」「取込CSV」「反映データ」
- **補足**: 差異のある項目のみ値を持ち、差異のない列は空欄とする。資産番号（V-304）・資産枝番（V-305）は ASP の必須入力項目のため常に出力する。値を入れるのは **9 列**（1・2・3・16・38・44・59・64・65 列目）で、残り 66 列は常に空欄とする。6 列目 取得日付は棚卸で変更しないため、差異の有無にかかわらず空欄のままとする。

### V-307: 修正対象行

- **英語名**: `AmendmentRow`
- **定義**: 取り込み用データ（V-306）に出力する対象となった突合結果の行。突合結果（S-301）が 棚卸済み であり、かつ 変化状況（S-302）が 差異 または 拠点変更 である行。
- **使用しない表現**: 「更新対象」「変更行」「差分行」

### V-308: 突合結果スナップショット

- **英語名**: `ReconcileSnapshot`
- **定義**: 選択中の棚卸データ管理（E-301）について、突合済みの一覧項目とデータ差異を Django セッションに保持したもの。同一の棚卸を表示・CSV 出力・取り込み用データ（V-306）の作成で扱う間、desknet's NEO への再取得を行わずに再利用する。
- **構成要素**: 対象の棚卸データ管理の データID ＋ 突合結果の一覧項目 ＋ データ差異。
- **使用しない表現**: 「キャッシュ」「一時データ」「セッションデータ」
- **補足**: **棚卸データ管理一覧（E-301 の一覧）そのものは含まない**（画面表示のたびに desknet's から取得する）。core E-004 スナップショットの適用範囲に位置づく。保持中に選択する棚卸を切り替えた場合は再作成する。

### V-309: 貼り付けレイアウト

- **英語名**: `AspPasteLayout`
- **定義**: ASP（SYS-302）の『資産／異動情報修正入力』が受け付ける列の並びと総列数。**1 列目 資産番号 〜 75 列目 システムリザーブ の 75 列固定**。
- **構成要素**: 列番号・項目名・チェック仕様（V-310）・領域長（byte）。列の一覧は要件定義書 [REQ-ASP-IMPORT-DATA-2026-001](spec/02_asp-import-data/requirements.md) §9 付録を正とする。
- **使用しない表現**: 「ASPフォーマット」「取込レイアウト」「入力フォーマット」
- **補足**: ASP 側の外部仕様であり、ポータルは変更できない。会社コードの列は存在しない。列数・並びが変わった場合は要件定義書 §9 付録と取り込み用データ（V-306）の出力列数を併せて見直す。
- **補足（ポータルが値を入れる 9 列）**: 1 資産番号 / 2 資産枝番 / 3 管理部門コード（V-311）/ 16 型番 / 38 摘要 / 44 管理者コード（V-312）/ 59 抽出コード１３（使用区分コード V-313）/ 64 抽出コード１８（メーカーコード V-315）/ 65 抽出コード１９（旧資産番号コード V-314）。

### V-310: チェック仕様

- **英語名**: `AspFieldCheck`
- **定義**: 貼り付けレイアウト（V-309）が各列に課す入力チェックの種別。列ごとに領域長（byte）を併せ持つ。
- **構成要素**:

  | コード | 意味 |
  |--------|------|
  | `O` | 必須入力 |
  | `M` | 半角英数記号 |
  | `I` | 整数 |
  | `N` | 数値 |
  | `D` | 日付 |
  | `P` | 全角可 |

- **使用しない表現**: 「入力チェック区分」「バリデーション種別」「属性」
- **補足**: 1 列に複数のコードが付く（例: 資産枝番は `O,I`）。ポータルは違反を検出しても**出力は止めず、警告として利用者に通知する**。

### V-311: 管理部門コード

- **英語名**: `DepartmentCode`
- **定義**: 拠点（V-302 拠点名）を ASP（SYS-302）上で識別するコード。棚卸データ（E-303）の `管理部門コード` 部品が持つ。
- **構成要素**: 半角英数記号・最大 12 byte（チェック仕様 `M`）。前後空白を除去して扱う。
- **使用しない表現**: 「部門コード」「拠点コード」「工場コード」
- **補足**: 貼り付けレイアウト（V-309）の 3 列目に対応する。拠点名（V-302）が表示用の名称であるのに対し、管理部門コードは ASP へ渡す値である。

### V-312: 管理者コード

- **英語名**: `ManagerCode`
- **定義**: 画面の **型番**（desknet's の `管理者名称` 部品）を ASP（SYS-302）上で識別するコード。棚卸データ（E-303）の `管理者コード` 部品が持つ。
- **構成要素**: 半角英数記号・最大 12 byte（チェック仕様 `M`）。前後空白を除去して扱う。
- **使用しない表現**: 「型番コード」「管理者番号」
- **補足**: 貼り付けレイアウト（V-309）の 44 列目に対応する。変化点判定（A-301）は `管理者名称` で行い、出力する値は本コードとする。

### V-313: 使用区分コード

- **英語名**: `UsageCategoryCode`
- **定義**: 使用区分を ASP（SYS-302）上で識別するコード。棚卸データ（E-303）の `使用区分コード` 部品が持つ。
- **構成要素**: 半角英数記号・最大 12 byte（チェック仕様 `M`）。前後空白を除去して扱う。
- **使用しない表現**: 「区分コード」「稼働区分コード」
- **補足**: 貼り付けレイアウト（V-309）の 59 列目 抽出コード１３ に対応する。変化点判定（A-301）は `使用区分` で行い、出力する値は本コードとする。

### V-314: 旧資産番号コード

- **英語名**: `OldAssetNumberCode`
- **定義**: 旧資産番号を ASP（SYS-302）上で識別するコード。棚卸データ（E-303）の `旧資産番号コード` 部品が持つ。
- **構成要素**: 半角英数記号・最大 12 byte（チェック仕様 `M`）。前後空白を除去して扱う。
- **使用しない表現**: 「旧番号」「旧資産No.」
- **補足**: 貼り付けレイアウト（V-309）の 65 列目 抽出コード１９ に対応する。変化点判定（A-301）も同じ `旧資産番号コード` 部品で行うため、判定と出力で部品の読み替えは生じない。

### V-315: メーカーコード

- **英語名**: `ManufacturerCode`
- **定義**: メーカー名（desknet's の `メーカー` 部品）を ASP（SYS-302）上で識別するコード。棚卸データ（E-303）の `メーカーコード` 部品が持つ。
- **構成要素**: 半角英数記号・最大 12 byte（チェック仕様 `M`）。前後空白を除去して扱う。
- **使用しない表現**: 「製造元コード」「メーカーNo.」
- **補足**: 貼り付けレイアウト（V-309）の 64 列目 抽出コード１８ に対応する。変化点判定（A-301）は `メーカー` で行い、出力する値は本コードとする。

## 3. ステータス

### S-301: 突合結果

- **英語名**: `ReconcileStatus`
- **定義**: 突合キー（V-301）の一致状況。**棚卸済み**（両方に存在）/ **未棚卸**（資産データのみ）/ **台帳外**（棚卸データのみ）の 3 値。
- **構成要素**: `matched`（棚卸済み）/ `asset_only`（未棚卸）/ `inventory_only`（台帳外）
- **使用しない表現**: **「突合済み」**（業務上は「棚卸済み」と表記する）「未突合」（変化状況 S-302 の値としてのみ用いる）「一致／不一致」

### S-302: 変化状況

- **英語名**: `ChangeStatus`
- **定義**: 棚卸済み行における台帳との差異の種別。**一致** / **拠点変更** / **差異** / **未突合** の 4 値。
- **使用しない表現**: **「拠点変更あり」「差異あり」**（送り言葉を付けない。行背景色の凡例でも同一表記とする）
- **補足**: 優先順位は 拠点変更（薄黄）> 差異（薄青）> 一致（薄緑）> 未突合（白）。

### S-303: プレート作成

- **英語名**: `PlateStatus`
- **定義**: 資産プレートの作成状態。棚卸データ（E-303）の `プレート作成` 部品が持つコードで、**`0`＝作成済み**（プレートが貼付済みの資産）/ **`1`＝作成対象**（プレートを新たに作成する必要がある資産）の 2 値。
- **構成要素**:

  | コード | 意味 | 表示ラベル |
  |---|---|---|
  | `0` | **作成済み** | プレート有 |
  | `1` | **作成対象** | プレート作成 |

  未棚卸行（S-301 が `asset_only`）は空。
- **使用しない表現**: 「プレート区分」「プレートフラグ」「プレート未作成」（作成対象と表記する）
- **補足**: 値の意味は **2026-07-31 に業務担当が確定**（L2レビュー 指摘 L2-7 のクローズ）。表示ラベル「プレート有」「プレート作成」は確定した意味と整合するため **据え置く**（`0`＝プレート有＝作成済み、`1`＝プレート作成＝これから作成する対象）。実装の変換規則（`domain/value_objects/plate_display.py`）も変更しない。
  一覧の **列名**「プレート作成」と値ラベル「プレート作成」が同一である点は、値の意味が確定したため許容する。

## 4. アクション

### A-301: 変化点判定

- **英語名**: `DetectChanges`
- **定義**: 棚卸済み行について、資産データと採用した棚卸データを 7 項目（拠点名・メーカー名・型番・シリアルNo.・旧資産番号・使用区分・摘要）で TRIM 後の文字列完全一致により比較し、1 つでも異なれば **変化点あり** とすること。
- **使用しない表現**: 「差分検出」「変更検知」
- **補足**: 両方が空の場合は一致とみなす。取得日付は判定の対象外（表示のみ）。
- **補足（画面表示名と desknet's 部品名の対応）**: **画面の表示名と desknet's の部品名は一致しない**。特に画面「シリアルNo.」が desknet's の `型番` 部品を指すため、文書・実装で「型番」と書く際はどちらを指すか明示すること。ASP 対応列は貼り付けレイアウト（V-309）の列番号。**差異の判定は名称の部品で行い、取り込み用データ（V-306）へ出力する値はコードの部品を使う**（旧資産番号は判定・出力とも `旧資産番号コード`）。

  | 画面表示名（本項の 7 項目） | desknet's 部品名 | ASP 対応列 |
  |------------------|------------------|-----------|
  | 拠点名 | `管理部門名称` | 3 列目 管理部門コード（V-311 を出力） |
  | メーカー名 | `メーカー` | 64 列目 抽出コード１８（V-315 を出力） |
  | 型番 | `管理者名称` | 44 列目 管理者コード（V-312 を出力） |
  | シリアルNo. | `型番` | **16 列目 型番** |
  | 旧資産番号 | `旧資産番号コード` | 65 列目 抽出コード１９（V-314 を出力） |
  | 使用区分 | `使用区分` | 59 列目 抽出コード１３（V-313 を出力） |
  | 摘要 | `摘要` | 38 列目 摘要 |


### A-302: 工場変化判定

- **英語名**: `DetectSiteChange`
- **定義**: 変化点ありの行について、資産データと棚卸データの `管理部門コード` を拠点マスタで解決した拠点識別子が異なる場合に **工場変化あり** とすること。
- **使用しない表現**: 「拠点変更判定」（判定名は「工場変化判定」、判定結果の表示ラベルは「拠点変更」とする）
- **補足**: 拠点マスタで両方を解決できない場合は、両方非空かつコード値が異なれば工場変化ありとする。

### A-303: 重複解決

- **英語名**: `ResolveDuplicates`
- **定義**: 同一突合キーの棚卸データが複数ある場合、**棚卸日時が最も新しい 1 件を採用** すること。
- **使用しない表現**: 「重複排除」「デデュープ」
- **補足**: 棚卸日時がパースできない行は最古扱い。同時刻はデータID 昇順で決定する。

## 5. 外部システム

### SYS-301: サービス連携アカウント

- **英語名**: `ServiceAccount`
- **定義**: AppSuite API の呼び出しに用いる専用の desknet's NEO（core SYS-001）アカウント。棚卸関連アプリの参照権を持つ。
- **構成要素**: 環境変数 `DESKNETS_ASSET_INVENTORY_LOGIN_ID` / `DESKNETS_ASSET_INVENTORY_PASSWORD`。
- **使用しない表現**: 「共通アカウント」「システムアカウント」「API ユーザー」
- **補足**: 設定されている場合はこのアカウントの `access_key` を用い、ポータルの総務メニューグループを持つ利用者が個別の desknet's アプリ権限なしで画面を利用できる。未設定時はログインユーザーの `access_key` を用いる。

### SYS-302: ASP

- **英語名**: `Asp`
- **正式名称**: 固定資産管理システム 〜総合資産管理サービス ASP〜
- **定義**: 固定資産を管理する社外提供のサービス。『資産／異動情報修正入力』に値を貼り付けて資産情報の変更を取り込む。ポータルからの API 接続手段はなく、取り込み用データ（V-306）の受け渡しは利用者の手作業で行う。
- **使用しない表現**: **「基幹」（単独）「基幹システム」（単独）「基幹反映」**（core SYS-003 基幹システム（Oracle）と混同するため。ASP を指す場合は必ず「ASP」と書く）／「固定資産システム」（単独）「資産管理システム」（単独）
- **補足**: ポータルは ASP へ自動で書き込まない。取り込みの成否は ASP 側で確認する。受け付ける列の並びは貼り付けレイアウト（V-309）を参照。
