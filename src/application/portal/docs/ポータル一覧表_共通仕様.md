# ポータル一覧表 共通仕様

業務支援ポータル内の **フィルタ・ソート・ページング付き一覧表** を共通化するための仕様書。  
資産棚卸結果・在庫発注アラートで実装済みのパターンを標準とし、今後の一覧画面でも再利用する。

---

## 1. 目的

| 目的 | 内容 |
|------|------|
| UI/UX 統一 | フィルタ即時反映、複数列ソート、表下ページング、URL 同期 |
| 保守性 | バグ修正・仕様変更を1箇所で反映 |
| 拡張性 | 列定義・フィルタ・行色・件数サマリだけ画面別に差し替え |

---

## 2. アーキテクチャ

```
┌─────────────────────────────────────────────────────────┐
│ 画面テンプレート (list.html)                              │
│  - フィルタ panel / 表 / フッタ / sort dialog           │
│  - json_script (list-data)                               │
└─────────────────────────────────────────────────────────┘
         │ SSR 初回描画              │ 埋め込み JSON
         ▼                           ▼
┌──────────────────┐    ┌──────────────────────────────┐
│ Django usecase   │    │ {app}-list-config.js (任意)   │
│ list_client_data │    │ 画面別: filter/sort/render     │
└──────────────────┘    └──────────────────────────────┘
         │                           │
         └───────────┬───────────────┘
                     ▼
         ┌───────────────────────────────┐
         │ portal-list-core.js           │  汎用エンジン
         │ portal-list-sort-dialog.js    │  並び替えダイアログ
         └───────────────────────────────┘
                     │
         ┌───────────┴───────────┐
         ▼                       ▼
  {app}-list-client.js     {app}-list.js
  (init + 画面設定)         (詳細ダイアログ等)
```

### 2.1 サーバー（Python）

| モジュール | 役割 |
|-----------|------|
| `application/portal/domain/list_table.py` | `SortSpec` / `PaginatedRows` / `paginate_rows` / `parse_sort_specs` 等の共通 primitives |
| `application/portal/domain/prefix_filter.py` | 前方一致テキストフィルタ（候補抽出・一致判定・オートコンプリート用） |
| `application/portal/domain/dependent_cust_filter.py` | 担当者コード連動の得意先セレクト候補 |
| `application/portal/domain/code_sort.py` | 担当者コード等の数値優先ソートキー |
| `application/{app}/domain/list_client_data.py` | 画面別 JSON payload 組み立て |
| `application/{app}/domain/table_display.py` | 画面別ソートキー・列定義（必要なら portal を import） |

### 2.2 クライアント（JavaScript）

| ファイル | 役割 |
|---------|------|
| `static/js/portal-list-core.js` | ソート解析、ページング、列見出し描画、URL 同期ヘルパ、datalist 更新 primitives |
| `static/js/portal-list-prefix-filter.js` | 列指定の前方一致フィルタ factory（`createPrefixColumnFilter`） |
| `static/js/portal-list-dependent-cust-filter.js` | 担当者コード連動の得意先セレクト |
| `static/js/portal-list-sort-dialog.js` | 複数列ソートダイアログ（ドラッグ並べ替え含む） |
| `static/js/{app}-list-client.js` | 画面別 init（フィルタ・行描画・件数サマリ） |
| `static/js/{app}-list.js` | 画面固有 UI（行詳細、CSV 取込等） |

## 3. 共通 UI 仕様

### 3.1 フィルタ

- 変更時 **ページ再読込なし**（ブラウザ内ローカル処理）
- 変更時 **page = 1** にリセット
- ソート・表示件数は維持
- URL は `history.replaceState` で同期
- セレクト・テキスト入力の幅は `--portal-list-filter-control-width`（既定 `9.5rem`）で両画面共通
- ラベル（タイトル）はコントロールの **上** に縦並び（`flex-direction: column`）

#### 3.1.1 前方一致テキストフィルタ（オートコンプリート）

資産番号・品番など、**列値の前方一致**で絞り込むテキストフィルタの共通仕様。

| 項目 | 内容 |
|------|------|
| Python | `application/portal/domain/prefix_filter.py`（`matches_prefix_filter` / `filter_prefix_options` / `extract_distinct_values*`） |
| JS | `PortalListPrefixFilter.createPrefixColumnFilter({ getValue, normalizeValue? })` |
| HTML | `includes/portal_prefix_filter_field.html`（ラベル・input・datalist） |
| 一致 | TRIM 後の **前方一致**（画面別に `normalize` 関数を渡せる。例: 資産番号は先頭 `L` 除去） |
| 候補 | 全行から列値を重複除去・昇順。SSR で datalist に出力し、入力時に JS で前方一致絞り込み |
| 入力 | 600ms デバウンス + Enter 即時反映 + IME 対応 |
| 状態同期 | `bindPrefixFilterInput` が返す `sync(value)` は **input の表示値** と datalist 候補を更新する。保留中のデバウンスはキャンセルする（担当者・得意先変更時の品番クリア等） |

画面別に変えるのは **対象列**（`getValue` / `column_key`）と **正規化関数**（任意）のみ。

#### 3.1.2 担当者コード連動の得意先セレクト

担当者コード選択に応じて、得意先コードセレクトの候補を絞り込む共通仕様（在庫発注アラート・出荷トレンド一覧）。

| 項目 | 内容 |
|------|------|
| Python | `application/portal/domain/dependent_cust_filter.py`（`build_cust_chrg_cust_index` / `cust_options_for_chrg_psn` / `sanitize_cust_code`） |
| JS | `PortalListDependentCustFilter`（`buildCustChrgCustIndex` / `renderCustCodeSelect` 等） |
| 連動方向 | **担当者コード → 得意先コード** のみ（逆方向は連動しない） |
| 担当者が「すべて」 | 得意先候補はスナップショット全件 |
| 担当者を指定 | 当該担当者の行に現れる得意先のみ |
| 担当者コード変更時 | 得意先コードは **常に「すべて」にリセット**（候補の再計算に加え、選択値もクリア） |
| データ源 | 埋め込み JSON の全行（Oracle 再問い合わせなし） |
| 担当者候補の並び | **数値として昇順**（`numeric_code_sort_key`、非数字は末尾） |
| 品番系フィルタのクリア | **担当者コード・得意先コード** 変更時に、画面の品番テキストフィルタ（`item_cd` 等）を空にリセット |

### 3.2 ソート

- 列見出しクリック: **単一列** 昇順/降順トグル
- **並び替え** ダイアログ: 最大 **5 条件**、ドラッグで優先順位変更
- 列見出しは **`<a href="#">`** を標準（`th a` CSS 適用）。レガシー画面は `button` モードも可

### 3.3 ページング

- 表示件数: 20 / 50 / 100 / 200（既定 50）
- 配置: 表示件数 → 前へ → 次へ → 件数範囲

### 3.4 行の色付け

- **共通エンジンは色を付けない**
- 行 CSS クラスは `{app}-list-client.js` の `renderTableBody` で画面別に付与

## 4. JSON payload 共通フィールド

各画面の `list_client_data.py` は次を含める。

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `rows` | array | 全行（フィルタ前） |
| `sortableColumns` | `{key, label}[]` | 列定義 |
| `defaultSortSpecs` | `{column, direction}[]` | 初期ソート |
| `pageSizeOptions` | number[] | 表示件数候補 |
| `defaultPageSize` | number | 既定表示件数 |

画面固有フィールド（例: `filterOptions`, `rowDetails`, `confirmationStatusChoices`）は各アプリで追加する。

## 5. 新規一覧画面の追加手順

1. Django: `list_client_data.py` で payload 組み立て
2. テンプレート: フィルタ panel / 表 / フッタ / sort dialog / `json_script`
3. JS: `{app}-list-client.js` で `PortalListCore` を利用した画面別 init を実装
4. JS: `{app}-list.js` で `PortalListSortDialog.init(...)` と画面固有 UI
5. テスト: payload 組み立て + list-client 設定のソース検証
6. 本仕様書の「採用画面一覧」に追記
