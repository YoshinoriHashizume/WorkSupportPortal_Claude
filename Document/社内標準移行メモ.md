| 項目 | 内容 |
|------|------|
| 作成日 | 2026-07-20 |

## 1. 目的

リポジトリ構成と Django app レイヤーを社内標準に揃え、新規参加者・エージェントが迷わず開発できるようにする。

---

## 2. 移行内容（要約）

### 2.1 Docker / リポジトリ分離

| 変更前（概要） | 変更後（社内標準） |
|----------------|--------------------|
| Django ソースがリポジトリルート直下 | Django ソースは **`src/`** |
| ルートに `Dockerfile` / 旧 `docker-compose.yml` 等 | **`docker/`** 配下にイメージ定義、`docker-compose.devcontainer.yaml` / `docker-compose.production.yaml` |
| ローカルはホスト Python または旧 Compose 中心 | **DevContainer** 前提（workspace: `/django_app/src`） |
| アプリポート 3000/3100、DB 5432 等 | ホスト **8990**（Django）、**5440**（PostgreSQL） |
| `.env.local` 等 | ルート **`.env`**（`.env.example` をテンプレート） |

### 2.2 レイヤー改称・配置

各業務 app は次の形に統一する。

```text
src/application/<app>/
  domain/
    entities/
    value_objects/
    repositories/   # ABC / Protocol（ports）
  use_cases/        # Django 非依存。動詞+名詞のクラス
  infrastructure/   # domain IF の実装
  interfaces/       # views.py, urls.py, wiring.py
  models.py         # ORM 定義の正（マイグレーション互換）。infrastructure/django/models からリエクスポート
  tests/
```

依存の向き: **interfaces → use_cases → domain ← infrastructure**

> **ORM 補足**: 社内 reference は infrastructure 側定義だが、本リポジトリは Django migrations 互換のため **app 直下 `models.py` を定義の正** とする。

### 2.3 composition 廃止

| 廃止 | 代替 |
|------|------|
| app 直下の `composition.py` | **`interfaces/wiring.py`** で手動 DI |
| app 直下の `views.py` / `urls.py` | **`interfaces/views.py`** / **`interfaces/urls.py`** |
| DI コンテナ | **使用しない** |

### 2.4 Document の維持

- **`Document/` はリポジトリルートに残す**（`src/` 配下へは移さない）。
- 仕様・手順書は Docker 分離後もルートから参照する。

> **【2026-07-29 改訂】** 本節の方針は §8 で見直した。**アプリ固有文書と横断設計文書は `src/` 配下へ移す**（`src/application/<app>/docs/` および `src/docs/`）。`Document/` に残すのはアプリケーション仕様書と全体の手順書のみ。

## 5. 開発者向けメモ

1. 作業は **DevContainer を開いてから**行う（cwd = `/django_app/src`）。
2. 新規 app は §5.0 のフォルダと依存ルールに従う。`wiring.py` で組み立て、views から infrastructure を直接 import しない。
3. 仕様変更は該当する仕様書に記載し、単体テストを追加する。配置は §8 に従う（アプリ固有は `src/application/<app>/docs/`、横断設計は `src/docs/`、全体の手順書は `Document/`）。
4. pytest は `src/` を cwd / `PYTHONPATH` にし、必要なら `WSP_REPO_ROOT` にリポジトリルートを指定する。SQLite では一部マイグレーションが失敗するため、`conftest.py` で **nomigrations**（モデルからスキーマ生成）とする。

## 8. 文書配置の SDD 構成への移行（2026-07-29）

§2.4 で「`Document/` はリポジトリルートに残す（`src/` 配下へは移さない）」と定めていたが、
社内標準の SDD（スペック駆動開発）ワークフローが前提とする配置に合わせ、**アプリ固有文書と
横断設計文書を `src/` 配下へ移す**方針に改めた。狙いは、コードと仕様書を同じディレクトリツリーで
改訂できるようにし、`sdd` スキル群（`make-requirements` / `make-design` / `make-tasks` /
`manage-issue` 等）の出力先とリポジトリの実体を一致させることにある。

### 8.1 新しい配置

| 配置 | 内容 |
|------|------|
| `src/application/<app>/docs/` | アプリ固有文書。機能仕様書・テスト仕様書・`ubiquitous_language.md`・`spec/{feature}/`・`issues/` |
| `src/docs/` | プロジェクト横断の設計文書。`ubiquitous_language_core.md`・`strategic_design.md`・アプリ横断の共通仕様 |
| `Document/` | アプリケーション仕様書と**全体の手順書**（ローカル開発環境構築・本番デプロイ・Entra ID 構築・プログラム作成実行書・本メモ） |

### 8.2 移動の内訳

|--------|--------|
| `Document/application/5年9組/` | `src/application/gonenkukumi/docs/` |
| `Document/application/検収書比較/` | `src/application/receipt_comparison/docs/` |
| `Document/application/在庫発注アラート/` | `src/application/inventory_order_alert/docs/` |
| `Document/application/資産棚卸結果/` | `src/application/asset_inventory/docs/` |

| `Document/application/共通/テスト配置_共通仕様.md` | `src/docs/` |
