# Microsoft 認証（Entra ID）構築手順

## 文書情報

| 項目 | 内容 |
|------|------|
| 目的 | 本ポータルで Microsoft サインインを使うために、**Microsoft 側**と**プログラム側**でそれぞれ必要な作業を示す |
| 前提 | 社内に **Entra ID テナントは既にある**（テナント新規構築は対象外） |
| 実装 | Auth.js、`microsoft-entra-id` プロバイダ。コード上のエントリはリポジトリにより異なる（例: `src/auth.ts`） |

---

## 1. Microsoft（Entra ID）側でやること

**場所**: [Microsoft Entra 管理センター](https://entra.microsoft.com) または Azure ポータルの「Microsoft Entra ID」→ **アプリ登録**。

| # | 作業 | 内容 |
|---|------|------|
| 1 | **アプリ登録を作る** | **新規登録**で名前を付ける。アカウントの種類は社内のみなら **この組織ディレクトリのみ**（シングルテナント）が一般的。 |
| 2 | **リダイレクト URI を登録する** | 種類は **Web**。下記の形で、使う **環境ごと**（ローカル／検証／本番）に追加する。 |
| 3 | **API の権限を整える** | サインイン用に、例: `openid`、`profile`、`email`、`User.Read`（Microsoft Graph・委任）。組織ルールで **管理者の同意** が必要なら実施。 |
| 4 | **クライアントシークレットを発行する** | **証明書とシークレット** → 新しいクライアントシークレット。値は開発者へ **安全に渡す**（平文メールは避ける）。 |
| 5 | **次の値を開発者へ渡す** | 下表の 4 点。 |

**リダイレクト URI の形（本アプリ固定）**

ユーザーがブラウザで開く **サイトのオリジン**（例: `http://localhost:3000` や本番の **`http://192.168.3.196`**）に、次のパスを付ける。

```text
{オリジン}/api/auth/callback/microsoft-entra-id
```

例: ローカルで `http://localhost:3000` を開くなら  
`http://localhost:3000/api/auth/callback/microsoft-entra-id`  
本番（確定）で `http://192.168.3.196` を開くなら  
`http://192.168.3.196/api/auth/callback/microsoft-entra-id`  
nginx 経由やポート付き公開なら、その **実際のオリジン** で同じパスを登録する。

**開発者へ渡す情報**

| 渡すもの | どこで分かるか |
|----------|----------------|
| **アプリケーション（クライアント）ID** | アプリ登録の「概要」 |
| **ディレクトリ（テナント）ID** | テナントの「概要」 |
| **クライアントシークレット** | 手順 4 で発行した値 |
| **Issuer URL** | `https://login.microsoftonline.com/<テナントID>/v2.0`（`<テナントID>` はディレクトリ（テナント）ID） |

## 2. プログラム（アプリ）側でやること

| # | 作業 | 内容 |
|---|------|------|
| 1 | **環境変数を設定する** | 下表を `.env.local`（ローカル）や本番の秘密管理に設定する。 |
| 2 | **URL を揃える** | `NEXTAUTH_URL`（または `AUTH_URL`）は、**ユーザーがアドレスバーで見るアプリの URL のオリジン**と同じにする。Microsoft に登録したリダイレクト URI のオリジンとも一致させる。 |
| 3 | **動作確認する** | アプリを起動し、ログイン画面の **「Microsoft で続行」** でサインインできるか確認する。 |

**設定する環境変数**

| 変数 | 必須 | 説明 |
|------|------|------|
| `AUTH_SECRET` または `NEXTAUTH_SECRET` | はい | セッション用の秘密鍵（長いランダム値） |
| `NEXTAUTH_URL` または `AUTH_URL` | はい | 例: `http://localhost:3000`、本番は **`http://192.168.3.196`**（末尾スラッシュなし推奨。HTTPS 終端後は `https://...` に合わせる） |
| `AUTH_MICROSOFT_ENTRA_ID_ID` | はい | Microsoft から渡された **クライアント ID** |
| `AUTH_MICROSOFT_ENTRA_ID_SECRET` | はい | **クライアントシークレット** |
| `AUTH_MICROSOFT_ENTRA_ID_ISSUER` | 推奨 | `https://login.microsoftonline.com/<テナントID>/v2.0` |

テンプレートは、リポジトリに `.env.example` がある場合はそれをコピーして利用する。

**補足（開発のみ）**

- Entra の準備がまだのときは、`NODE_ENV=development` かつ `AUTH_DEV_MODE=true` で **開発用ログイン**（Entra なし）が使える。本番では無効にする。

**よくある不具合**

| 症状 | 確認 |
|------|------|
| `redirect_uri_mismatch` | Entra のリダイレクト URI と、実際の `{オリジン}/api/auth/callback/microsoft-entra-id` が **完全一致** か（http/https・ポート含む） |
| コールバック後に失敗 | `NEXTAUTH_URL` が、実際に開いている URL と一致しているか |
