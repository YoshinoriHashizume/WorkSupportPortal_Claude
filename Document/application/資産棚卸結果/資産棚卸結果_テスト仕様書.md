本書は **資産棚卸結果（asset_inventory）** に関する **自動テストの方針・設計・詳細テストケース** を定義する。  
機能要件の正は [資産棚卸結果_機能仕様書.md](./資産棚卸結果_機能仕様書.md) とする。

## 2. 目的

| 目的 | 説明 |
|------|------|
| 突合の固定 | 資産番号 L 除去・枝番キー・3 区分が仕様どおりであることを保証する |
| 重複解決 | 棚卸データ複数行から **最新棚卸日時** を採用するルールを固定する |
| 差異・色付け | 変化点・工場変化・行背景色の導出をテストで固定する |
| 表示列 | 棚卸データ部品から画面ラベルへのマッピングを検証する |
| API 分離 | CI では実 desknet's に接続せず、ゲートウェイをモックする |
| 回帰防止 | クリーンアーキテクチャ規約（`usecase_*.py` のみ等）を `test_clean_architecture` で担保する |

## 4. テスト戦略

### 4.1 テストピラミッド

1. **単体テスト（最優先）** … `domain/` の純関数: キー正規化、重複解決、突合、変化点、工場変化、行色、表示列マッピング、CSV ヘッダ
2. **ユースケーステスト** … `usecase_reconcile` / `usecase_export_csv` に desknet ゲートウェイ **モック**
3. **結合テスト（限定的）** … views: 401 / 403 / 503 / 200、CSV Content-Type
4. **E2E（任意）** … ログイン済み総務ユーザーで一覧・CSV のスモーク（desknet's モックサーバまたは VCR）

### 4.2 共通原則

| 原則 | 内容 |
|------|------|
| 決定性 | 日時パース・ソートは fixture 固定。`棚卸日時` は ISO 風文字列で与える |
| desknet's 非依存 | CI では `DesknetAppDataGateway` をモックし、`list_data` 応答 JSON fixture を返す |
| 秘密情報 | `access_key` をリポジトリ・ログに含めない |
| サンプル整合 | fixture は提供 CSV の代表行を JSON 化したもの（app_id 401 / 415 / 408 等） |

### 4.3 実行方法

リポジトリルートで:

```bash
pytest tests/test_asset_inventory.py
pytest tests/asset_inventory/
pytest -k "TC_AIV"
pytest tests/test_clean_architecture.py -k asset_inventory
```

## 6. テストデータ方針

### 6.1 突合キー fixture

| 資産番号（入力） | 資産枝番 | 期待キー |
|------------------|----------|----------|
| `L5262` | `0001` | `5262\|0001` |
| `l999` | `0000` | `999\|0000` |
| ` 3043 ` | `0000` | `3043\|0000` |
| `5262` | `0001` | `5262\|0001`（L なしと突合） |

### 6.2 棚卸重複 fixture

同一キー `5262|0001` の棚卸 2 行:

| データID | 棚卸日時 | 採用 |
|----------|----------|------|
| 10 | `2026/01/10 10:00:00` | |
| 20 | `2026/01/16 18:46:01` | **採用** |

### 6.3 突合 3 区分 fixture

| キー | 資産 | 棚卸 | 期待区分 |
|------|------|------|----------|
| `5262\|0001` | あり | あり | 棚卸済み |
| `1\|0000` | あり | なし | 未棚卸 |
| `9999\|0000` | なし | あり | 台帳外 |

### 6.4 変化点・行色 fixture

台帳と棚卸が突合済みの行:

| ケース | 台帳 管理部門名称 | 棚卸 管理部門名称 | 管理部門コード差 | 拠点マスタ | 期待 row_tone |
|--------|-------------------|-------------------|------------------|------------|---------------|
| 一致 | 宮崎工場 | 宮崎工場 | 同じ | — | `MATCH_CLEAN`（緑） |
| 差異のみ | 宮崎工場 | 宮崎工場 | 同じ | 同一拠点 | `MATCH_DIFF`（青）。摘要のみ異なる等 |
| 拠点変更 | 宮崎工場 | 本社 | 異なる | 別拠点ID | `MATCH_FACTORY`（黄） |
| 未棚卸 | — | — | — | — | `NONE`（白） |

### 6.5 表示列マッピング fixture

棚卸データ行:

| 部品 | 値 | 期待画面列・値 |
|------|-----|----------------|
| 資産番号 | `L5262` | 資産番号=`L5262`（表示は原値） |
| 管理部門名称 | `宮崎工場` | 拠点名=`宮崎工場` |
| 管理者名称 | `M06SJ-2` | 型番=`M06SJ-2` |
| 型番 | `17009A` | シリアルNo.=`17009A` |

未棚卸行は資産データから同マッピングで `棚卸日時` 等が空であること。

### 6.6 desknet's API fixture

`tests/fixtures/asset_inventory/desknet_management.json`  
`tests/fixtures/asset_inventory/desknet_assets.json`  
`tests/fixtures/asset_inventory/desknet_inventory.json`  
`tests/fixtures/asset_inventory/desknet_sites.json`

AppSuite 応答形式: `{ "status": "ok", "list": { "item": [ { "資産番号": {"val": "..."}, ... } ] } }`

### 6.7 権限 fixture

| ユーザー | グループ | 期待 |
|----------|----------|------|
| 総務ユーザー | `general-affairs` | 200 |
| 生産管理のみ | `production` | 403 |
| 未ログイン | — | 401 |

### 6.8 拠点フィルタ fixture

拠点マスタ候補: `宮崎工場`, `本社`, `東京支社`

| 行 | 拠点名 | status フィルタ | site フィルタ | 表示 |
|----|--------|-----------------|---------------|------|
| A | 宮崎工場 | all | 未指定 | 表示 |
| B | 本社 | all | `宮崎工場` のみ | 非表示 |
| C | 本社 | matched | `本社` | 表示（AND） |
| D | （空） | all | `宮崎工場` | 非表示 |
| D | （空） | all | 未指定 | 表示 |
