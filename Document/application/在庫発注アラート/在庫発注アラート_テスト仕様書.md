# 在庫発注アラート テスト仕様書

本書は **在庫発注アラート（inventory_order_alert）** に関する **自動テストの方針・設計・詳細テストケース** を定義する。  
機能要件の正は [在庫発注アラート_機能仕様書.md](./在庫発注アラート_機能仕様書.md) とする。

## 2. 目的

| 目的 | 説明 |
|------|------|
| 回帰防止 | 5年9組準拠の BOM・入荷・出荷集計ロジックが Web 化後も検証スクリプトと一致することを保証する |
| SLIMS 在庫連携 | CSV 取込・品番突合・スナップショット置換が仕様どおり動作することを検証する |
| アラート判定の固定 | 重点／警告／なしの境界条件をテストで固定し、誤検知・見逃しを防ぐ |
| 確認状態の保証 | PostgreSQL への確認登録（処置フラグ）・フィルタ・表示が仕様どおり動作することを検証する |
| 外部依存の分離 | CI では実 Oracle・実 SLIMS に接続せず、ドメイン層単体テストを最優先する |

## 4. テスト戦略

### 4.1 テストピラミッド

1. **単体テスト（最優先）** … 純関数: アラート判定、出荷集計、入荷解決、SLIMS CSV パース、在庫突合、日付変換、CSV ヘッダ、ソートキー
2. **結合テスト（限定的）** … Django views / API に Oracle・DB を **モック** して 401/403/400/200 を検証
3. **E2E（任意）** … ログイン済みブラウザで一覧表示・SLIMS 取込・CSV ダウンロードのスモーク

### 4.2 共通原則

| 原則 | 内容 |
|------|------|
| 決定性 | `asOfDate`・`warningDays`・`today` は **引数化** し、テスト内で固定日付を使用する |
| スクリプトとの一致 | domain 層の Oracle 出力が検証スクリプト `build_summary_rows` と同一になるよう、fixture データで比較テストを行う |
| SLIMS サンプル | 機能仕様書 §4.1.2 の想定フォーマットに基づく最小 CSV fixture をリポジトリに同梱する |
| 秘密情報 | `ORACLE_*` をリポジトリ・ログに含めない |
| 本番 Oracle 非依存 | CI では実 Oracle に接続しない |

### 4.3 実行方法

リポジトリルートで:

```bash
pytest tests/test_verify_post_receipt_shipment_count.py
pytest tests/inventory_order_alert/
pytest -k "TC_IOA"
```

| 51916-60050 | 150 | 通常行との突合 |
