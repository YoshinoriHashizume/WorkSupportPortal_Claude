# 在庫発注アラート 機能仕様書

本書は、検証スクリプト `scripts/verify_post_receipt_shipment_count.py` を **業務支援ポータル上の生産管理 Web アプリ** として実装するための要件を定義する。  
5年9組と同じ Oracle テーブル・BOM 展開ロジックを用い、**最終仕入れ（入荷）が古い、または入荷実績がない品目について、在庫出荷が継続していないかを一覧し、仕入先への確認体制を支援する**。  
在庫数量は基幹 Oracle の値を **信用せず**、丸栄ニューウェーブが管理する **SLIMS** からエクスポートした CSV を取り込んで表示する。

## 2. 背景・業務目的

### 2.1 背景

客先からの注文があったが社内在庫がなく仕入先へ発注しようとしたところ、部品を作る設備や金型が既に存在しなかった事例が発生した。  
本来は一定期間の在庫保管が必要だが、仕入先への最終発注から長期間（例: 8 年）経過しており、発注がないため仕入先側で設備を廃棄していた。社内は在庫で一定期間対応できていたため、問題が表面化しにくかった。

### 2.2 本機能の目的

| 目的 | 内容 |
|------|------|
| リスクの可視化 | **最終入荷日** が古い、または **入荷実績がない** 品目について、**最終入荷日以降に得意先向け出荷が継続している** 行を一覧する |
| 在庫の提示 | SLIMS から取り込んだ **最新在庫** を同一行に表示し、在庫のみで出荷している状況を判断しやすくする |
| アラート | 上記条件を満たす行を画面上で強調表示し、生産管理担当者の注意を促す |
| 仕入先確認 | 仕入先への確認状況（未確認／確認中／確認済み）を PostgreSQL に記録し、再確認の漏れを防ぐ |
| 判断材料の提供 | 最終入荷日・最終出荷日・出荷回数・出荷数合計・在庫数を同一行で提示し、入荷発注の要否判断を支援する |

## 3. システム境界・前提

| 区分 | 内容 |
|------|------|
| 基幹 Oracle | **参照のみ**（SELECT）。5年9組と同一スキーマ・同一接続方針。入荷・出荷・BOM・仕入先マスタを取得する。**在庫数量は Oracle から取得しない** |
| SLIMS 在庫 | ユーザーが SLIMS からエクスポートした CSV をアップロードし、PostgreSQL に **最新取込スナップショット** として保存する |
| ポータル PostgreSQL | SLIMS 取込履歴・在庫スナップショット、アラート閾値設定、行単位の仕入先確認状態、確認メモ、確認日時・確認者を保存する。**ユーザー単位のデータは持たず、在庫・集計・確認状態は全員で共有** |
| 認証 | Django 認証（ログイン必須）。未ログインは `/login` へ遷移、API は 401 |
| 権限 | **生産管理** メニューグループを持つ一般ユーザーおよび管理者が利用可能（§9） |
| 複数会社 | 5年9組と同様、`MARI_COMPANY_CD` による会社コード条件を Oracle クエリに付与する（未設定時は条件なし・本番既定） |
| データ鮮度（Oracle） | **画面表示の都度** Oracle を参照する（初版）。定期バッチは将来拡張 |
| データ鮮度（在庫） | SLIMS CSV **最終取込日** を **「YYYY年M月D日時点の在庫」** 形式で表示する |

### 4.1 一覧画面（SCR-01）

#### 4.1.1 表示方針（集計スナップショット）

一覧・メニューアラート帯は **SLIMS 在庫 CSV 取込時に Oracle へ集計した結果**（`InventoryOrderAlertSummarySnapshot`）を表示する。**画面表示の都度 Oracle へは問い合わせない**。

表示する在庫発注データ（SLIMS 在庫・集計結果・確認状態）は **全員で共有** する。いずれかのユーザーが CSV を取込むと、他のユーザーの一覧・メニューアラート帯も同じ内容に更新される。

| 項目 | 内容 |
|---|---|
| 表示対象 | 直近の SLIMS 取込に紐づく **全件**（`alertOnly=false` 相当）をスナップショットに保存し、一覧では **フィルター** で絞り込み表示する |
| BOM 基準日 | 取込日（サーバ暦日）を `asOfDate` として集計時に固定し、スナップショットに保存。**一覧画面には表示しない**（在庫時点ラベルで代替） |
| 確認状態 | 表示時のみ PostgreSQL の最新確認状態を行へ **上書き反映**（集計結果自体は再計算しない） |
| 再集計 | SLIMS CSV の **再取込** のみ。設定変更（`warningDays` 等）を反映するには再取込が必要 |
| 未取込 | 一覧は空。メニュー帯は「在庫 CSV 未取込」を表示 |
| 集計失敗 | 取込は成功しても Oracle 集計が失敗した場合、エラーメッセージを表示し一覧は空 |

#### 4.1.2 SLIMS 在庫取込

一覧カード見出し行の **CSV 出力** ボタンの左に **SLIMS在庫CSV** ボタンを配置する。クリックでファイル選択ダイアログを開き、`.csv` を選ぶと **即座に取込・集計**（在庫保存 → Oracle 全件集計 → スナップショット保存）を実行する。別途の取込ボタンは設けない。

| 項目 | 内容 |
|---|---|
| ボタン | `SLIMS在庫CSV`（`button-link` 相当）。非表示の `<input type="file">` を `label` で起動 |
| 実行タイミング | ファイル選択確定時に POST 送信（`inventory-order-alert-list.js`） |
| 在庫時点表示 | 最終取込日を **「YYYY年M月D日時点の在庫」** と表示する（例: `2026年6月17日時点の在庫`）。一覧カード見出し行（`h2`）に **「YYYY年M月D日時点の集計結果を表示しています。」** と表示する。その直下に **赤字・小さめ文字** で `※入出荷の実績があるもののみ表示されます。` を表示する |
| 取込メタ情報 | 一覧カード内に在庫行数・ファイル名は **表示しない**。件数サマリは操作行に表示（§4.1.4） |
| 取込警告 | 最終取込から **`stockStaleDays` 日超** 経過している場合、画面上部に黄色バナー「SLIMS 在庫データが古い可能性があります（最終取込: YYYY/MM/DD）」を表示 |
| 取込中表示 | ファイル選択後〜サーバー応答まで、画面全体に半透明オーバーレイとスピナー、「SLIMS 在庫 CSV を取込中...」を表示する。二重取込を防ぐため **ボタン（label）のみ** 無効化する（`<input type="file">` は送信前に `disabled` にしない。disabled だとファイルが POST されず取込されない） |
| 在庫未取込 | 在庫データが 1 件もない状態では一覧カード内に「SLIMS 在庫 CSV を取り込むと、一覧が表示されます。」と表示 |

**SLIMS CSV フォーマット（2026-06 改訂）**

実ファイル `SISJB0001003000108848800.csv`（SLIMS 在庫エクスポート）に基づく。

| 項目 | 内容 |
|---|---|
| 文字コード | **Shift_JIS（CP932）** を第一候補。UTF-8（BOM あり/なし）も自動判別して受け付ける |
| ヘッダー行 | **2 行**。1 行目は英字フィールドコード、2 行目は日本語ラベル。**データは 3 行目から** |
| 品番列 | **`WSHOCD`（商品コード）** = 物理 **2 列目**。一覧の `item_cd`（Oracle 出荷品番）と **TRIM 後完全一致** で突合 |
| ロケーション列 | **`WLOCCD`（ロケーション）** = 物理 **5 列目** |
| ロケーションフィルタ | `WLOCCD` が **`[0-9][0-9A-Z][0-9]-[0-9]{2}-[0-9]`** 形式（例: `2E4-10-4`）の行 **のみ** 在庫集計対象。それ以外は **無視** |
| 在庫数列 | **`WKATQT`（引当可能バラ数）** = 物理 **8 列目**。`SUM` して一覧の `stock_qty` に使用 |
| 入荷日列 | **`WNYUDT`（入荷日）** = 物理 **14 列目**。在庫内訳ポップアップに行単位で表示（`YYYYMMDD`） |
| 後方互換 | 旧形式の **`WRSOQT`** 列がある CSV も読み込み可能（`WKATQT` を優先） |
| 集計（品番合計） | 対象行について、同一 `WSHOCD` の `WKATQT`（または `WRSOQT`）を **SUM** |
| 集計（ロケーション要約） | 同一 `WSHOCD` + `WLOCCD` の在庫数を **SUM** |
| 在庫内訳（ポップアップ） | CSV 行を **集約せず** そのまま表示 |
| 在庫基準日 | **取込日（暦日）** |

**主要列（1 行目フィールドコード）**

| 物理列 | フィールド | 日本語（2 行目） | 本機能での利用 |
|---|---|---|---|
| 1 | `WBSOKCD` | 倉庫コード | **未使用** |
| 2 | `WSHOCD` | 商品コード | **出荷品番**（突合キー） |
| 5 | `WLOCCD` | ロケーション | **必須**（形式フィルタ対象） |
| 8 | `WKATQT` | 引当可能バラ数 | **在庫数**（品番・ロケーション別 SUM） |
| 14 | `WNYUDT` | 入荷日 | 在庫内訳ポップアップ |
| 16 | `WMFGLT` | 製造ロット | 取込時に行属性として保持（集計キーには含めない） |
| — | `WRSOQT` | （旧形式）理論在庫総バラ数 | 後方互換。`WKATQT` 欠落時のみ使用 |
| — | `WBATQT` / `WSOJQT` 等 | 実在庫バラ数 | **未使用** |

- 1 行目に `WSHOCD` / `WLOCCD` / `WKATQT`（または `WRSOQT`）が存在することを必須とする。欠落時は 400 エラー。
- 取込成功時、**前回の在庫スナップショットは置き換え** する（履歴は `SlimsStockImport` にメタデータのみ保持）。

#### 4.1.3a フィルター

一覧タイトル直下に **フィルター** 枠を表示する。候補値は **直近スナップショットの集計データ** から重複除去して生成する（Oracle への再問い合わせは行わない）。

| 項目 | クエリ | 内容 |
|---|---|---|
| 担当者コード | `cust_chrg_psn_cd` | `T_SHIP.CUST_CHRG_PSN_CD`。空は「すべて」。セレクト候補は **数値として昇順**（非数字は末尾） |
| 得意先コード | `cust_code` | `T_SHIP.CUST_CD`。表示は `コード - 得意先名` |

- 変更時は GET で送信し、**ページは 1 に戻す**。ソート・表示件数は維持する。
- 件数サマリ（左: 重点・警告・アラート無し／右: 確認済み・確認中・未確認）は **絞り込み後** の行を対象とする。左・右いずれも **同じ行集合** を数え、**合計件数は一致**する（左 = 重点 + 警告（出荷あり） + 警告（出荷なし） + アラート無し、右 = 確認済み + 確認中 + 未確認）。
- CSV 出力は **フィルターに関係なくスナップショット全件** を出力する。

#### 4.1.4 一覧 UI 仕様

- テーブルは **画面内に収まる高さ** で表示し、**本体のみ縦スクロール**する。`.content` を `calc(100dvh - 56px)` の flex 列とし、見出し・フィルター・ツールバー・フッターを除いた残り高さを `.ioa-table-wrap` に割り当てる（固定 `62vh` は使用しない）。
- テーブルヘッダは **sticky** で固定する。
- 列見出し（カラム名）は **中央揃え** とする。
- 列見出しクリックで **単一列ソート** に切り替える（当該列のみ、昇順／降順トグル）。複数列ソート中にクリックした場合も **1 列のみ** にリセットする。
- **複数列ソート**: テーブル上の **並び替え** ボタンからダイアログを開き、最大 **5 条件** まで列と昇順／降順を指定する。**条件行左端の番号をドラッグ＆ドロップ** して優先順位を入れ替えられる。適用時は GET クエリ `sort=col1,col2&dir=asc,desc` で送信する。優先順位は上から。同一列の重複指定は無視する。
- 複数列ソート適用中、列見出しには優先順位番号（1, 2, …）と方向（▲／▼）を表示する。
- **日付列のソート**（`last_incoming_date` / `last_ship_date`）: 空は **最も古い** とみなし、**昇順（古い順）では先頭**、降順（新しい順）では末尾に並べる。複数列ソートでも同一ルールを用いる。
- 初期表示時のソート: **`alert_level` 昇順（重点→警告（出荷あり）→警告（出荷なし）→アラート無し）**。
- **ページング**: `page_size`（20 / 50 / 100 / 200、既定 **50**）と `page`（1 始まり）。**テーブル左下** に **表示件数 → セレクト → 前へ → 次へ → 表示範囲** の順で横並びとする。
- 表示範囲（例: `1–3 件目を表示（1 / 1 ページ）`）は **次へ** の右に表示する。
- テーブル上部（フィルター直下）の左端に **並び替え** ボタン、右端に件数サマリを配置する。
- 件数サマリは **2 段表示**（同一行内）:
  - **左寄せ**: **重点 / 警告（出荷あり） / 警告（出荷なし） / アラート無し**（フィルター適用後の全行。確認状態に関わらずアラート列の値で集計）
  - **右寄せ**: **確認済み / 確認中 / 未確認**（同一行集合を確認状態で集計。**左の合計と右の合計は一致**）
- **アラート行の背景色**（§6.2）:
  - **重点**: 赤（例: `#fde8e8`）
  - **警告（出荷あり）**: 橙（例: `#ffedd5`）
  - **警告（出荷なし）**: 黄（例: `#fff8e1`）
  - **アラート無し**: 白（通常背景）。表示・CSV・件数サマリで統一
- **確認状態の行背景色**（確認状態が未確認以外のとき、アラート色より優先）:
  - **確認中**: 薄青（例: `#dbeafe`）
  - **確認済み**: 薄緑（例: `#dcfce7`）。件数サマリから除外
- **行クリック**: データ行をクリックすると **在庫内訳** ダイアログを表示する（確認状態プルダウン等の操作要素クリック時は除く）。SLIMS 在庫 CSV から集計した **品番ごとの複数ロケーション**（`WLOCCD` と在庫数）を表形式で表示する。該当ロケーションがない行はその旨を表示する。
- **行のハイライト**: データ行にカーソルを合わせると背景色を変えて現在行を示す。行クリック中は選択行として強調表示する。
- **確認状態列**は一覧上の **プルダウン** で直接変更する。変更時に自動保存（`PUT /api/inventory-order-alert/confirmation`）。**メモ履歴は変更しない**。保存成功後は **ページ再読込せず**、対象行の背景色と件数サマリのみ更新する（行の並び順・スクロール位置は維持）。
- 一覧カード見出し行に **「YYYY年M月D日時点の集計結果を表示しています。」** を表示する。直下に **※入出荷の実績があるもののみ表示されます。**（赤字・12px 相当）を表示する。
- 数量・在庫は **3 桁カンマ区切り**で表示する。
- **ロケーション列は一覧・CSV に含めない**（在庫数集計にのみ内部利用）。
- **CSV 出力** ボタン: 一覧見出し行の右端。ラベルは **「CSV 出力」**（フィルター無関係でスナップショット全件を UTF-8 BOM 付き CSV でダウンロード）。集計データがない場合はボタン非表示。
- **警告条件** ボタン: 一覧見出し行の操作ボタン群の先頭。クリックで §6.2 の6パターン表をポップアップ表示する。**出荷あり／出荷なし** の月数を **1〜36 か月** のセレクトで変更し **保存** できる（`PUT /api/inventory-order-alert/alert-settings`）。
- **SLIMS在庫CSV** ボタン: **CSV 出力の左** に配置（§4.1.2）。

**CSV 出力（初版実装）**

| 項目 | 内容 |

| ルート | `GET /app/production/inventory-order-alert/export.csv`（画面用）、`GET /api/inventory-order-alert/export.csv`（API 用。同一処理） |
| 認証 | ログイン必須。生産管理メニュー権限がないユーザーは 403 |
| クエリ | なし（直近スナップショット全件） |
| 文字コード | UTF-8 BOM（Excel 互換） |

#### 4.1.6 在庫内訳（`WLOCCD`）

SLIMS CSV の **`WLOCCD`（ロケーション）** は取込時に品番ごとの内訳として保持し、**在庫数（`stock_qty`）の合算** に使用する。

- **一覧・CSV にはロケーション列を出力しない**（在庫数合計のみ表示）。
- 行データには `stock_location_detail`（例: `2D0-03-5=90@20161228;2E1-03-4=10@20161228`）を保持する。`@` 以降は `WNYUDT`（入荷日）。スナップショット読込時は最新 SLIMS 在庫から再付与する。
- **行クリック** で **詳細** ダイアログ（`#ioa-location-dialog`）を表示する。表スタイルは **警告条件** ポップアップ（`#ioa-alert-rules-dialog`）と同一。**詳細** ダイアログの幅は `min(960px, calc(100vw - 24px))`（警告条件は `min(480px, calc(100vw - 24px))`）。上部に得意先・品番・在庫数合計を表示し、**在庫内訳** として列 **入荷日 / ロケーション / 在庫数** を表示する。**入荷日（`WNYUDT`）昇順**（空は末尾、同日はロケーション・在庫数）。CSV 上の同一ロケーションが複数行あれば **重複のまますべて** 表示する（一覧の在庫数合計は引き続き SUM）。
- 詳細ダイアログ下部に **メモ履歴** を表形式で表示する（列: **登録日時 / 登録者 / 内容**、**新しい順**）。列幅は登録日時・登録者を必要最小（固定幅）とし、**内容** に残り幅を割り当てる。**登録者**は Django ユーザーの **氏名**（姓＋名。未設定時は社員番号）。**新しいメモ** 欄に追記し **保存** で `POST /api/inventory-order-alert/confirmation/memos` を呼び出す（確認状態は変更しない）。履歴は PostgreSQL の `InventoryOrderAlertConfirmationMemoEntry` に蓄積する。
- 該当ロケーションがない行は「SLIMS 在庫に該当するロケーションがありません。」を表示する。

#### 4.1.7 確認状態の更新（処置フラグ）

仕入先確認等の **処置を完了した行** にフラグを立て、再確認の対象から外せるようにする。

| 項目 | 必須 | 内容 |
|---|---|---|
| 確認状態 | 必須 | `未確認` / `確認中` / `確認済み` のいずれか（一覧の **確認状態列プルダウン** で変更） |
| メモ | 任意 | 仕入先への確認内容、回答概要、発注可否等（1件最大 500 文字）。**詳細ダイアログ**で **時系列に追記**（登録者・登録日時・内容を履歴管理。登録者は氏名表示）。一覧の確認状態プルダウン変更時は **メモ履歴に触れない** |

- 確認状態を変更すると **即時保存** する（別途保存ボタンなし）。保存成功後は **再読込せず** 行背景色・件数サマリを更新する。API 応答に `alertRowClass` と `counts` を含める。

- 保存キー: **`cust_code` + `item_cd`**（同一得意先・品番を一意とする）。
- 保存時に **確認者**（ログインユーザーの社員番号）と **確認日時**（サーバ時刻）を記録する。
- **確認中／確認済み** にした時点の **`alert_level`** を `confirmed_alert_level` として記録する。
- **SLIMS CSV 再取込・再集計後**、当該行の最新 `alert_level` が確認時より **深刻化** した場合（アラート無し→警告、警告→重点 等、`alert_sort_rank` が小さくなる方向）は **自動で未確認** に戻す。取込完了メッセージに戻した件数を表示する。
- 件数サマリ右側（確認済み／確認中／未確認）の横に **確認状態リセット** ボタンを表示する。押下時に確認ダイアログを表示し、同意後 **確認中・確認済みをすべて未確認** に戻す（**メモは維持**、`confirmed_alert_level`・確認者・確認日時はクリア）。対象は **全行**（フィルタ適用前の PostgreSQL 全件）。
- `確認済み` にした行は `hideConfirmed=false` 時も一覧に残る。**行背景は薄緑** とし、重点・警告の件数サマリから除外する。
- `hideConfirmed=true` のとき **確認済み行は一覧から除外** する（`unconfirmedOnly` 等と AND）。
- `未確認` に戻した場合も上書き保存する（監査ログは将来拡張可）。

#### 4.1.8 操作フロー

1. 担当者が SLIMS から在庫 CSV をエクスポートし、一覧画面で **取込** する。
2. ユーザーが BOM 基準日等の条件を入力し **表示** を実行する。
3. サーバーが SLIMS 在庫を PostgreSQL に保存し、**同一リクエスト内で Oracle から全件集計**して `InventoryOrderAlertSummarySnapshot` に保存する。
4. 一覧・メニューアラート帯は **スナップショット** を読み出して表示する（確認状態のみ都度 JOIN）。
4. アラート判定（§6.2）をサーバー側で行い、一覧を描画する。
5. 担当者がアラート行を確認し、仕入先へ連絡後、一覧の確認状態プルダウンで **確認済み** 等を登録する。
6. 必要に応じ CSV を出力し、社内共有・記録に用いる。

## 6. アラート判定

### 6.1 共通前提

- 対象行は Oracle から取得した **得意先 × 品番** ごとの 1 行とする。
- **最終入荷日以降の出荷** とは、`T_SHIP` において `DEL_FLG != 1` かつ `SHIP_DATE > 最終入荷日` の明細を指す。
- **最終入荷日が空**（入荷実績なし）の場合、**すべての出荷** を「最終入荷日以降の出荷」として集計する（検証スクリプト `aggregate_shipment_stats` と同一）。
- 在庫数（`stock_qty`）は **アラート判定には使用しない**（判断材料として表示のみ）。将来、在庫 0 かつ出荷ありを重点条件に加える拡張は可能。

### 6.2 アラートレベル（入出荷バランス）

一覧画面の **「警告条件」** ボタンから、次表をポップアップで確認・変更できる。

| 入荷 | 出荷 | 判定 |
|---|---|---|
| なし | なし | アラート無し |
| なし | あり | **重点** |
| あり | あり（`warningShipmentMonths` 以上） | **警告（出荷あり）** |
| あり | あり（`warningShipmentMonths` 未満） | アラート無し |
| あり | なし（`warningIncomingMonths` 以上） | **警告（出荷なし）** |
| あり | なし（`warningIncomingMonths` 未満） | アラート無し |

- **出荷あり** = 最終入荷日以降の出荷実績あり（`post_shipment_count > 0`）
- **出荷なし** = 最終入荷日以降の出荷実績なし（`post_shipment_count = 0`）
- **期間の基準（出荷あり）** = 最終入荷日から最終出荷日までが `warningShipmentMonths` か月以内かどうか
- **期間の基準（出荷なし）** = 最終入荷日から `asOfDate` までが `warningIncomingMonths` か月を経過したかどうか
- **月数** = 最終入荷日から N か月後の同日まで（末日入荷は対象月の末日に合わせる）
- **入出荷バランス良好** = 出荷あり かつ `最終入荷日 < 最終出荷日` かつ 期間が `warningShipmentMonths` 未満
- 判定優先順: **重点** → **警告（出荷あり）** → **警告（出荷なし）** → **アラート無し**
- 旧ラベル（`警告（出荷）` / `警告（入荷）` / `アラートなし` / `問題なし` 等）は読込時に正規化して扱う
- スナップショット読込時も **最新設定で再判定** する
- **確認済み**行は件数サマリから除外。行背景は薄緑
- 在庫数は判定に使用しない

**代表例**（`warningShipmentMonths=12`, `warningIncomingMonths=12`, asOf=2026/06/17）

| 最終入荷 | 最終出荷 | 入荷以降出荷 | レベル |
|---|---|---|---|
| 空 | 2026/06/10 | あり | **重点** |
| 2022/01/31 | 2025/02/01 | あり | **警告（出荷あり）**（入荷→出荷 12か月超） |
| 2024/05/01 | 空 | なし | **警告（出荷なし）**（入荷→asOf 12か月以上） |
| 2026/05/01 | 空 | なし | アラート無し（入荷→asOf 12か月未満） |
| 2026/05/01 | 2026/06/10 | あり | アラート無し（入荷→出荷 12か月以内） |

### 6.3 フィルタとの関係

| フィルタ | 動作 |
|---|---|
| `alertOnly=true` | `alert_level` が **重点** / **警告（出荷あり）** / **警告（出荷なし）** のいずれか |
| `alertOnly=false` | 全行表示（出荷実績のある得意先×品番ペア） |
| `unconfirmedOnly=true` | PostgreSQL 上 `confirmation_status = 未確認` の行のみ（他条件と AND） |
| `hideConfirmed=true` | PostgreSQL 上 `confirmation_status = 確認済み` の行を **除外**（他条件と AND） |

## 7. データ取得ロジック

### 7.1 Oracle（入荷・出荷・BOM）

検証スクリプト `scripts/verify_post_receipt_shipment_count.py` の `build_summary_rows` を **正** とする。Web 実装では当該ロジックを domain / application 層に移し、スクリプトと Web で同一結果になるよう共通化する。

#### 7.1.1 対象ペアの抽出

```sql
SELECT TRIM(CUST_CD) AS CUST_CD,
       TRIM(ITEM_CD) AS ITEM_CD,
       MAX(TRIM(CUST_CHRG_PSN_CD)) AS CUST_CHRG_PSN_CD
  FROM T_SHIP
 WHERE DEL_FLG != 1
 GROUP BY TRIM(CUST_CD), TRIM(ITEM_CD)
 ORDER BY CUST_CD, ITEM_CD
```

#### 7.1.2 BOM・仕入先・最終入荷日

| 処理 | テーブル | 内容 |
|---|---|---|
| 完成品ルート | `M_ITEM` | `SUB_ITEM_CD_01`〜`05` を含むルート集合 |
| 階層1外注 | `M_PS` + `M_ITEM` | `OUTSIDE_TYP = '2'`、`LEVEL = 1`、BOM 基準日で有効な構成 |
| 仕入先 | `M_PUCH_UNIT_COST_H` + `M_VEND_CTRL` | 品目ごとの仕入先コード・略称（5年9組 SICODE_GET2 相当。**最終行を採用**） |
| 最終入荷日 | `T_PAST_INSPC_ACPT` | `(ITEM_CD, VEND_CD)` ごとの `MAX(ACPT_DATE)` |

**最終入荷日の行への反映**（`resolve_last_incoming_for_finished`）:

- 完成品に紐づく各ルート・階層1品目について、仕入先コードが有効（空・`?` 以外）なものを走査する。
- 入荷実績がある組み合わせのうち **最も新しい入荷日** を採用する。
- 入荷実績が 1 件もない場合でも、最初に見つかった有効な **階層1品番・仕入先** を表示する（最終入荷日は空）。

#### 7.1.3 出荷集計

| 項目 | 条件 | 集計 |
|---|---|---|
| 最終出荷日 | `DEL_FLG != 1`、対象 `CUST_CD`・`ITEM_CD` | `MAX(SHIP_DATE)` |
| 最終入荷日以降の出荷回数 | 上記 + `SHIP_DATE > 最終入荷日`（最終入荷日空のとき条件なし） | `COUNT(*)` |
| 最終入荷日以降の出荷数合計 | 同上 | `SUM(NVL(SHIP_QTY, 0))` |

#### 7.1.4 得意先名

`M_CUST` から `CUST_CD` → `CUST_NAME` の辞書を構築し、各行に付与する。

### 7.2 SLIMS 在庫・集計スナップショット（PostgreSQL）

| 処理 | 内容 |
|---|---|
| 取込 | CSV 2 行ヘッダをスキップし、3 行目以降をパース。`WSHOCD` / `WLOCCD` / `WKATQT`（または `WRSOQT`）を抽出（`WLOCCD` 形式フィルタ適用）し `SlimsStockSnapshot` に **ロケーション行単位** で保存 |
| **集計（取込時）** | Oracle から **全件**（`alertOnly=false`）を取得し SLIMS 在庫・確認状態・アラート判定を適用。結果を `InventoryOrderAlertSummarySnapshot.rows`（JSON）に保存 |
| 一覧・メニュー表示 | **スナップショットを読み出し**表示。確認状態のみ `InventoryOrderAlertConfirmation` から都度上書き |
| 品番合計 | 同一 `WSHOCD` の `WKATQT` を **SUM** → 一覧 `stock_qty`（集計時に確定） |
| 在庫内訳 | CSV 行単位（`WKATQT` / `WNYUDT`）→ ポップアップ |
| 突合 | 一覧行の `item_cd` と `TRIM(WSHOCD)` を **完全一致** で LEFT JOIN（集計時） |
| 在庫時点 | `SlimsStockImport.imported_at` の **暦日** から `YYYY年M月D日時点の在庫` ラベルを生成 |
| 未一致 | `stock_qty` / `stock_location_summary` / `stock_as_of_label` を空表示。行自体は Oracle データとして表示を継続 |

> **補足**: SLIMS の `WSHOCD` と Oracle `item_cd` は **おそらく一致** する前提。末尾 `-00` 等の表記差で未一致が多発する場合は、正規化ルールを別途追加する。

## 8. API 仕様

### 8.1 `GET /api/inventory-order-alert/summary`

- **認証**: 必須（401）
- **クエリ**: `asOfDate`, `custCode`, `vendCode`, `alertOnly`, `unconfirmedOnly`, `hideConfirmed`, `sort`, `dir`
- **処理**: Oracle 一覧取得 → SLIMS 在庫 JOIN → アラート判定 → PostgreSQL 確認状態 JOIN → JSON 返却
- **成功**:

```json
{
  "ok": true,
  "rows": [{
    "item_cd": "43522-D1020-00",
    "stock_qty": 100,
    "stock_location_summary": "2D0-03-5 他1",
    "stock_locations": [
      { "wloccd": "2D0-03-5", "stock_qty": 90 },
      { "wloccd": "2E1-03-4", "stock_qty": 10 }
    ]
  }],
  "counts": { "total": 0, "alert": 0, "critical": 0, "warning": 0, "unconfirmed": 0 },
  "stockImport": { "importedAt": "ISO", "stockAsOfLabel": "2026年6月17日時点の在庫", "rowCount": 0, "isStale": false }
}
```

- **失敗**: 400（入力不正）、502（Oracle エラー）、503（Oracle 未設定）

### 8.2 `POST /api/inventory-order-alert/stock-import`

- **認証**: 必須
- **入力**: `multipart/form-data` で CSV ファイル 1 件
- **処理**: フォーマット検証 → PostgreSQL スナップショット置換 → 取込履歴 INSERT
- **成功**: `{ "ok": true, "importedAt": "ISO", "rowCount": N }`
- **失敗**: 400（形式不正・必須列欠落）、413（ファイルサイズ超過）

### 8.3 `GET /api/inventory-order-alert/export.csv`

- **認証**: 必須
- **クエリ**: §8.1 と同一
- **応答**: UTF-8 BOM 付き CSV（§4.1.3 の列 + `stock_location_detail`（在庫内訳文字列）+ `alert_level` + 確認関連列）

### 8.3.1 `GET /api/inventory-order-alert/stock-locations`

- **認証**: 必須
- **クエリ**: `itemCd`（必須）
- **処理**: 最新 SLIMS 取込スナップショットから、当該品番の在庫内訳を返却
- **成功**: `{ "ok": true, "itemCd": "...", "stockAsOfLabel": "...", "locations": [{ "wloccd": "2D0-03-5", "stock_qty": 90 }] }`
- **用途**: 在庫内訳ポップアップの非同期取得（SSR で内訳を同梱する場合は省略可）

### 8.4 `PUT /api/inventory-order-alert/confirmation`

- **認証**: 必須
- **入力 JSON**:

```json
{
  "custCode": "string",
  "itemCd": "string",
  "status": "unconfirmed|in_progress|confirmed",
  "custCodeFilter": "string (optional)",
  "custChrgPsnCdFilter": "string (optional)"
}
```

- **処理**: PostgreSQL に upsert（**確認状態のみ**）。`confirmed` / `in_progress` 時は `confirmed_at`, `confirmed_by` を更新
- **成功**:

```json
{
  "ok": true,
  "confirmationStatusKey": "confirmed",
  "alertRowClass": "確認済",
  "counts": {
    "critical": 0,
    "warningShip": 0,
    "warningIncoming": 0,
    "alertNone": 0,
    "unconfirmed": 0,
    "inProgress": 0,
    "confirmed": 0
  }
}
```

- **counts**: 一覧フィルター（`custCodeFilter` / `custChrgPsnCdFilter`）適用後の件数サマリ
- **失敗**: 400, 403

### 8.4c `GET` / `POST /api/inventory-order-alert/confirmation/memos`

- **認証**: 必須
- **GET クエリ**: `custCode`, `itemCd`（必須）
- **GET 成功**: `{ "ok": true, "memos": [{ "createdAt": "YYYY/MM/DD HH:mm", "createdBy": "生産担当", "content": "..." }] }`（**新しい順**。`createdBy` は氏名、未設定時は社員番号）
- **POST 入力 JSON**:

```json
{
  "custCode": "string",
  "itemCd": "string",
  "content": "string (required, max 500)"
}
```

- **POST 処理**: `InventoryOrderAlertConfirmationMemoEntry` に追記。確認レコードが無ければ `未確認` で作成。`confirmation.memo` に最新内容を同期
- **POST 成功**: `{ "ok": true, "memo": { "createdAt", "createdBy", "content" } }`
- **失敗**: 400, 403

### 8.4b `POST /api/inventory-order-alert/confirmation/reset`

- **認証**: 必須
- **入力 JSON**（任意）:

```json
{
  "custCodeFilter": "string (optional)",
  "custChrgPsnCdFilter": "string (optional)"
}
```

- **処理**: PostgreSQL 上の **確認中・確認済み** をすべて **未確認** に戻す（メモ維持、`confirmed_alert_level`・確認者・確認日時をクリア）
- **成功**:

```json
{
  "ok": true,
  "resetCount": 20,
  "counts": { "...": 0 }
}
```

- **resetCount**: 未確認に戻した件数
- **counts**: 一覧フィルター適用後の件数サマリ（画面更新用）
- **UI**: 成功後は一覧を再読込する

### 8.4a `PUT /api/inventory-order-alert/alert-settings`

- **認証**: 必須
- **入力 JSON**:

```json
{
  "warningShipmentMonths": 12,
  "warningIncomingMonths": 12
}
```

- **処理**: PostgreSQL `InventoryOrderAlertSettings` に保存。範囲は **1〜36**
- **成功**: `{ "ok": true }`
- **失敗**: 400
- **反映**: 保存後に一覧を再読込すると、スナップショット行に対して最新月数で警告を再判定する

### 8.5 `GET /api/inventory-order-alert/vendors`

- **認証**: 必須
- **処理**: 一覧フィルタ用の仕入先候補（Oracle `M_VEND_CTRL` 等）
- **成功**: `{ "ok": true, "items": [{ "code", "name" }] }`

### 8.6 設定 API（管理者）

| メソッド | パス | 概要 |

### 8.7 `GET /api/inventory-order-alert/dashboard-summary`

- **認証**: 必須（401）

    "importedAt": "ISO",
