# 在庫発注アラート 機能仕様書

本書は、検証スクリプト `scripts/verify_post_receipt_shipment_count.py` を **業務支援ポータル上の生産管理 Web アプリ** として実装するための要件を定義する。  
5年9組と同じ Oracle テーブル・BOM 展開ロジックを用い、**最終仕入れ（入荷）が古い、または入荷実績がない品目について、在庫出荷が継続していないかを一覧し、仕入先への確認体制を支援する**。  
在庫数量は基幹 Oracle の値を **信用せず**、丸栄ニューウェーブが管理する **SLIMS** からエクスポートした CSV を取り込んで表示する。

## 2. 背景・業務目的

### 2.1 背景

客先からの注文があったが社内在庫がなく仕入先へ発注しようとしたところ、部品を作る設備や金型が既に存在しなかった事例が発生した。  
本来は一定期間の在庫保管が必要だが、仕入先への最終発注から長期間（例: 8 年）経過しており、発注がないため仕入先側で設備を廃棄していた。社内は在庫で一定期間対応できていたため、問題が表面化しにくかった。

### 2.2 本機能の目的

| 目的 | 内容 |
|------|------|
| リスクの可視化 | **最終入荷日** が古い、または **入荷実績がない** 品目について、**最終入荷日以降に得意先向け出荷が継続している** 行を一覧する |
| 在庫の提示 | SLIMS から取り込んだ **最新在庫** を同一行に表示し、在庫のみで出荷している状況を判断しやすくする |
| アラート | 上記条件を満たす行を画面上で強調表示し、生産管理担当者の注意を促す |
| 仕入先確認 | 仕入先への確認状況（未確認／確認中／確認済み）を PostgreSQL に記録し、再確認の漏れを防ぐ |
| 判断材料の提供 | 最終入荷日・最終出荷日・出荷回数・出荷数合計・在庫数を同一行で提示し、入荷発注の要否判断を支援する |

## 3. システム境界・前提

| 区分 | 内容 |
|------|------|
| 基幹 Oracle | **参照のみ**（SELECT）。5年9組と同一スキーマ・同一接続方針。入荷・出荷・BOM・仕入先マスタを取得する。**在庫数量は Oracle から取得しない** |
| SLIMS 在庫 | ユーザーが SLIMS からエクスポートした CSV をアップロードし、PostgreSQL に **最新取込スナップショット** として保存する |
| ポータル PostgreSQL | SLIMS 取込履歴・在庫スナップショット、アラート閾値設定、行単位の仕入先確認状態、確認メモ、確認日時・確認者を保存する |
| 認証 | Django 認証（ログイン必須）。未ログインは `/login` へ遷移、API は 401 |
| 権限 | **生産管理** メニューグループを持つ一般ユーザーおよび管理者が利用可能（§9） |
| 複数会社 | 5年9組と同様、`GONENKUKUMI_COMPANY_CD` または `MARI_COMPANY_CD` による会社コード条件を Oracle クエリに付与する（未設定時は条件なし） |
| データ鮮度（Oracle） | **画面表示の都度** Oracle を参照する（初版）。定期バッチは将来拡張 |
| データ鮮度（在庫） | SLIMS CSV **最終取込日** を **「YYYY年M月D日時点の在庫」** 形式で表示する |

#### 4.1.2 SLIMS 在庫取込エリア

一覧画面上部（検索条件の下）に **SLIMS 在庫 CSV 取込** ブロックを配置する。

| 項目 | 内容 |
|---|---|
| ファイル選択 | `.csv` のみ受け付ける。ドラッグ&ドロップまたはファイル選択 |
| 取込ボタン | 選択ファイルを検証・パースし PostgreSQL に保存。成功時は取込日時・件数を表示 |
| 在庫時点表示 | 最終取込日を **「YYYY年M月D日時点の在庫」** と表示する（例: `2026年6月17日時点の在庫`）。取込日時（時分）は一覧上部の取込情報として別途表示してよい |
| 最終取込情報 | **最終取込日時**、**取込件数**、**取込実行者**（社員番号）を常時表示 |
| 取込警告 | 最終取込から **`stockStaleDays` 日超** 経過している場合、画面上部に黄色バナー「SLIMS 在庫データが古い可能性があります（最終取込: YYYY/MM/DD）」を表示 |
| 在庫未取込警告 | 在庫データが 1 件もない状態で一覧表示した場合、在庫列は空とし、画面上部に「SLIMS 在庫 CSV を取り込んでください」と表示 |

**SLIMS CSV フォーマット（業務サンプル確定）**

実ファイル `SISJB000100B000108839220.csv`（SLIMS 在庫エクスポート）に基づく。

| 項目 | 内容 |
|---|---|
| 文字コード | **Shift_JIS（CP932）** を第一候補。UTF-8（BOM あり/なし）も自動判別して受け付ける |
| ヘッダー行 | **2 行**。1 行目は英字フィールドコード、2 行目は日本語ラベル。**データは 3 行目から** |
| 品番列 | **`WSHOCD`（商品コード）**。一覧の `item_cd` と **TRIM 後完全一致** で突合 |
| 在庫数列 | **`WSOJQT`（実在庫総バラ数）** を採用する（理論在庫 `WRSOQT` は使用しない） |
| 集計 | 同一 `WSHOCD` が複数行（ロケーション・ロット違い）ある場合、**`WSOJQT` を合算** する |
| 在庫基準日 | CSV 内の日付列は行単位の入荷日等であり、在庫スナップショット基準日としては **取込日（暦日）** を用いる |

**主要列（1 行目フィールドコード）**

| フィールド | 日本語（2 行目） | 本機能での利用 |
|---|---|---|
| `WSHOCD` | 商品コード | 突合キー → `item_cd` |
| `WSOJQT` | 実在庫総バラ数 | 在庫数 `stock_qty` |
| `WSHOIG` | 商品名１ | 取込時は保存不要（参照用） |
| `WLOCCD` | ロケーション | 集計前の行識別のみ |

- 1 行目に `WSHOCD` / `WSOJQT` が存在することを必須とする。欠落時は 400 エラー。
- 取込成功時、**前回の在庫スナップショットは置き換え** する（履歴は `SlimsStockImport` にメタデータのみ保持）。

#### 4.1.3 一覧列（出力項目）

検証スクリプト `SUMMARY_COLUMNS` と同一の 10 列に、在庫列と Web 専用列を追加する。

| # | 列キー | 表示名 | 型 | データソース | 備考 |
|---|---|---|---|---|---|
| 1 | `cust_code` | 得意先コード | string | Oracle | `T_SHIP.CUST_CD` |
| 2 | `cust_name` | 得意先名 | string | Oracle | `M_CUST.CUST_NAME` |
| 3 | `item_cd` | 品番 | string | Oracle | 完成品 `T_SHIP.ITEM_CD` |
| 4 | `level1_item_cd` | 階層1品番 | string | Oracle | BOM 階層1 外注構成子 |
| 5 | `level1_vend_cd` | 仕入先コード | string | Oracle | `M_PUCH_UNIT_COST_H` 相当 |
| 6 | `level1_vend_name` | 仕入先名 | string | Oracle | `M_VEND_CTRL.VEND_ANAME` |
| 7 | `last_incoming_date` | 最終入荷日 | date / 空 | Oracle | `T_PAST_INSPC_ACPT` の `MAX(ACPT_DATE)` |
| 8 | `last_ship_date` | 最終出荷日 | date / 空 | Oracle | `T_SHIP` の `MAX(SHIP_DATE)` |
| 9 | `post_shipment_count` | 最終入荷日以降の出荷回数 | integer | Oracle | §7.3 参照 |
| 10 | `post_shipment_total_qty` | 最終入荷日以降の出荷数合計 | integer | Oracle | §7.3 参照 |
| 11 | `stock_qty` | 在庫数 | decimal / 空 | **SLIMS CSV** | `WSHOCD` = `item_cd` で LEFT JOIN。未取込・未一致時は空 |
| 12 | `stock_as_of_label` | 在庫時点 | string / 空 | **取込日** | 例: `2026年6月17日時点の在庫`。全行同一（最終取込日） |

**Web 専用列**

| 列キー | 表示名 | 備考 |
|---|---|---|

#### 4.1.4 一覧 UI 仕様

- テーブルヘッダは **sticky** とし、本体のみ縦スクロールする。
- 列見出しクリックで **昇順／降順** を切り替える（`sort`, `dir` クエリ）。
- 初期表示時のソート: **`alert_level` 降順（重点→警告→なし）**、同順位内は **`post_shipment_total_qty` 降順**。
- 数量・在庫は **3 桁カンマ区切り**、日付は **`YYYY/MM/DD`**。
- **アラート行の背景色**（§6.2）:
  - **重点**: 薄赤（例: `#fde8e8`）
  - **警告**: 薄黄（例: `#fff8e1`）
  - **なし**: 通常背景
- 行クリックまたは行内「確認」ボタンで **確認状態更新ポップアップ** を開く（§4.1.5）。
- 画面上部に **件数サマリ** を表示: 全件数、アラート件数（重点／警告内訳）、未確認件数。
- 在庫列ヘッダまたは一覧上部に **在庫時点ラベル**（`YYYY年M月D日時点の在庫`）を表示する。
- **CSV 出力** ボタン: 現在の検索条件・ソート順で表示中の行（在庫列・アラート列・確認列を含む）を UTF-8 BOM 付き CSV でダウンロードする。

#### 4.1.5 確認状態更新ポップアップ（処置フラグ）

仕入先確認等の **処置を完了した行** にフラグを立て、再確認の対象から外せるようにする。

| 項目 | 必須 | 内容 |
|---|---|---|
| 確認状態 | 必須 | `未確認` / `確認中` / `確認済み` のいずれか |
| メモ | 任意 | 仕入先への確認内容、回答概要、発注可否等（最大 500 文字） |

- 保存キー: **`cust_code` + `item_cd`**（同一得意先・品番を一意とする）。
- 保存時に **確認者**（ログインユーザーの社員番号）と **確認日時**（サーバ時刻）を記録する。
- `確認済み` にした行は `hideConfirmed=false` 時も一覧に残るが、背景色は通常とし、確認状態列で識別する。
- `hideConfirmed=true` のとき **確認済み行は一覧から除外** する（`unconfirmedOnly` 等と AND）。
- `未確認` に戻した場合も上書き保存する（監査ログは将来拡張可）。

#### 4.1.6 操作フロー

1. 担当者が SLIMS から在庫 CSV をエクスポートし、一覧画面で **取込** する。
2. ユーザーが BOM 基準日等の条件を入力し **表示** を実行する。
3. サーバーが Oracle から一覧データを都度取得し、SLIMS 在庫・PostgreSQL 確認状態を LEFT JOIN する。
4. アラート判定（§6.2）をサーバー側で行い、一覧を描画する。
5. 担当者がアラート行を確認し、仕入先へ連絡後、ポップアップで **確認済み** 等を登録する。
6. 必要に応じ CSV を出力し、社内共有・記録に用いる。

### 4.2 設定画面（SCR-02）

アラート条件は **管理者が設定画面で変更可能** とする。変更は即時に一覧・ダッシュボード帯へ反映する。

| 項目 | キー | 型 | 既定値 | 備考 |
|---|---|---|---|---|
| 警告アラート閾値（日数） | `warningDays` | integer | **365**（1 年） | 最終入荷日からの経過日数 ≥ この値 かつ 出荷あり → **警告** |
| 重点アラート | `criticalEnabled` | boolean | **true** | ON: 入荷なし＋出荷ありを **重点**。OFF: 重点判定を行わない |
| SLIMS 取込警告日数 | `stockStaleDays` | integer | **7** | 最終 SLIMS 取込からこの日数超で警告バナー |

- **管理者のみ** アクセス可能。一般ユーザーが直接 URL を開いた場合は 403。
- 設定変更は PostgreSQL に保持する。

## 6. アラート判定

### 6.1 共通前提

- 対象行は Oracle から取得した **得意先 × 品番** ごとの 1 行とする。
- **最終入荷日以降の出荷** とは、`T_SHIP` において `DEL_FLG != 1` かつ `SHIP_DATE > 最終入荷日` の明細を指す。
- **最終入荷日が空**（入荷実績なし）の場合、**すべての出荷** を「最終入荷日以降の出荷」として集計する（検証スクリプト `aggregate_shipment_stats` と同一）。
- 在庫数（`stock_qty`）は **アラート判定には使用しない**（判断材料として表示のみ）。将来、在庫 0 かつ出荷ありを重点条件に加える拡張は可能。

### 6.2 アラートレベル

| レベル | 条件 | 業務上の意味 |
|---|---|---|
| **重点** | `criticalEnabled=true` **かつ** `last_incoming_date` が空 **かつ** `post_shipment_count > 0` | 階層1仕入先への入荷実績がなく、在庫のみで出荷している |
| **警告** | `last_incoming_date` があり、基準日から見て **経過日数 ≥ warningDays** **かつ** `post_shipment_count > 0` | 最終入荷から長期間（例: 1 年以上）経過後も出荷が継続している |
| **なし** | 上記以外 | アラート対象外（`alertOnly=true` 時は非表示） |

- 経過日数 = `asOfDate` − `last_incoming_date`（暦日）。
- **重点** は **警告** より優先する。

**代表例（warningDays=365）**

| 最終入荷日 | 最終入荷以降出荷 | 在庫（SLIMS） | アラート |
|---|---|---|---|
| 空 | あり | 90 | **重点** |
| 2024/06/01（1 年超経過） | あり | 50 | **警告** |
| 2026/01/16（1 年未満） | あり | 150 | なし |
| 2026/06/16 | なし | 任意 | なし |

### 6.3 フィルタとの関係

| フィルタ | 動作 |
|---|---|
| `alertOnly=true` | `alert_level` が **重点** または **警告** の行のみ表示 |
| `alertOnly=false` | 全行表示（出荷実績のある得意先×品番ペア） |
| `unconfirmedOnly=true` | PostgreSQL 上 `confirmation_status = 未確認` の行のみ（他条件と AND） |
| `hideConfirmed=true` | PostgreSQL 上 `confirmation_status = 確認済み` の行を **除外**（他条件と AND） |

## 7. データ取得ロジック

### 7.1 Oracle（入荷・出荷・BOM）

検証スクリプト `scripts/verify_post_receipt_shipment_count.py` の `build_summary_rows` を **正** とする。Web 実装では当該ロジックを domain / application 層に移し、スクリプトと Web で同一結果になるよう共通化する。

#### 7.1.1 対象ペアの抽出

```sql
SELECT DISTINCT TRIM(CUST_CD), TRIM(ITEM_CD)
  FROM T_SHIP
 WHERE DEL_FLG != 1
 ORDER BY CUST_CD, ITEM_CD
```

#### 7.1.2 BOM・仕入先・最終入荷日

| 処理 | テーブル | 内容 |
|---|---|---|
| 完成品ルート | `M_ITEM` | `SUB_ITEM_CD_01`〜`05` を含むルート集合 |
| 階層1外注 | `M_PS` + `M_ITEM` | `OUTSIDE_TYP = '2'`、`LEVEL = 1`、BOM 基準日で有効な構成 |
| 仕入先 | `M_PUCH_UNIT_COST_H` + `M_VEND_CTRL` | 品目ごとの仕入先コード・略称（5年9組 SICODE_GET2 相当。**最終行を採用**） |
| 最終入荷日 | `T_PAST_INSPC_ACPT` | `(ITEM_CD, VEND_CD)` ごとの `MAX(ACPT_DATE)` |

**最終入荷日の行への反映**（`resolve_last_incoming_for_finished`）:

- 完成品に紐づく各ルート・階層1品目について、仕入先コードが有効（空・`?` 以外）なものを走査する。
- 入荷実績がある組み合わせのうち **最も新しい入荷日** を採用する。
- 入荷実績が 1 件もない場合でも、最初に見つかった有効な **階層1品番・仕入先** を表示する（最終入荷日は空）。

#### 7.1.3 出荷集計

| 項目 | 条件 | 集計 |
|---|---|---|
| 最終出荷日 | `DEL_FLG != 1`、対象 `CUST_CD`・`ITEM_CD` | `MAX(SHIP_DATE)` |
| 最終入荷日以降の出荷回数 | 上記 + `SHIP_DATE > 最終入荷日`（最終入荷日空のとき条件なし） | `COUNT(*)` |
| 最終入荷日以降の出荷数合計 | 同上 | `SUM(NVL(SHIP_QTY, 0))` |

#### 7.1.4 得意先名

`M_CUST` から `CUST_CD` → `CUST_NAME` の辞書を構築し、各行に付与する。

### 7.2 SLIMS 在庫（PostgreSQL）

| 処理 | 内容 |
|---|---|
| 取込 | CSV 2 行ヘッダをスキップし、3 行目以降をパース。`WSHOCD` / `WSOJQT` を抽出し `SlimsStockSnapshot` に保存 |
| 集計 | 同一 `WSHOCD` の `WSOJQT` を **SUM** して 1 品番 1 在庫数とする |
| 突合 | 一覧行の `item_cd` と `TRIM(WSHOCD)` を **完全一致** で LEFT JOIN |
| 在庫時点 | `SlimsStockImport.imported_at` の **暦日** から `YYYY年M月D日時点の在庫` ラベルを生成 |
| 未一致 | `stock_qty` / `stock_as_of_label` を空表示。行自体は Oracle データとして表示を継続 |

> **補足**: SLIMS の `WSHOCD` と Oracle `item_cd` は **おそらく一致** する前提。末尾 `-00` 等の表記差で未一致が多発する場合は、正規化ルールを別途追加する。

## 8. API 仕様

### 8.1 `GET /api/inventory-order-alert/summary`

- **認証**: 必須（401）
- **クエリ**: `asOfDate`, `custCode`, `vendCode`, `alertOnly`, `unconfirmedOnly`, `hideConfirmed`, `sort`, `dir`
- **処理**: Oracle 一覧取得 → SLIMS 在庫 JOIN → アラート判定 → PostgreSQL 確認状態 JOIN → JSON 返却
- **成功**: `{ "ok": true, "rows": [...], "counts": { "total", "alert", "critical", "warning", "unconfirmed }, "stockImport": { "importedAt", "stockAsOfLabel", "rowCount", "isStale" } }`
- **失敗**: 400（入力不正）、502（Oracle エラー）、503（Oracle 未設定）

### 8.2 `POST /api/inventory-order-alert/stock-import`

- **認証**: 必須
- **入力**: `multipart/form-data` で CSV ファイル 1 件
- **処理**: フォーマット検証 → PostgreSQL スナップショット置換 → 取込履歴 INSERT
- **成功**: `{ "ok": true, "importedAt": "ISO", "rowCount": N }`
- **失敗**: 400（形式不正・必須列欠落）、413（ファイルサイズ超過）

### 8.3 `GET /api/inventory-order-alert/export.csv`

- **認証**: 必須
- **クエリ**: §8.1 と同一
- **応答**: UTF-8 BOM 付き CSV（§4.1.3 の列 + `alert_level` + 確認関連列）

### 8.4 `PUT /api/inventory-order-alert/confirmation`

- **認証**: 必須
- **入力 JSON**:

```json
{
  "custCode": "string",
  "itemCd": "string",
  "status": "unconfirmed|in_progress|confirmed",
  "memo": "string (optional, max 500)"
}
```

- **処理**: PostgreSQL に upsert。`confirmed` / `in_progress` 時は `confirmed_at`, `confirmed_by` を更新
- **成功**: `{ "ok": true }`
- **失敗**: 400, 403

### 8.5 `GET /api/inventory-order-alert/vendors`

- **認証**: 必須
- **処理**: 一覧フィルタ用の仕入先候補（Oracle `M_VEND_CTRL` 等）
- **成功**: `{ "ok": true, "items": [{ "code", "name" }] }`

### 8.6 設定 API（管理者）

| メソッド | パス | 概要 |
|---|---|---|
| `GET` | `/api/inventory-order-alert/settings` | 閾値取得 |
| `PUT` | `/api/inventory-order-alert/settings` | 閾値更新（`warningDays`, `criticalEnabled`, `stockStaleDays`） |

### 8.7 `GET /api/inventory-order-alert/dashboard-summary`

- **認証**: 必須（401）
- **認可**: **生産管理** グループを持つユーザーのみ（403）
- **処理**: 画面表示都度、Oracle からアラート件数サマリを取得。SLIMS 取込状態を併せて返却
- **成功**:

```json
{
  "ok": true,
  "counts": { "critical": 3, "warning": 12, "unconfirmed": 8 },
  "stockImport": {
    "importedAt": "ISO",
    "stockAsOfLabel": "2026年6月17日時点の在庫",
    "isStale": false,
    "hasData": true
  }
}
```

- **用途**: メニュー画面アラート帯（§5.2）
