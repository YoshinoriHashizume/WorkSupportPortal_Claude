# 出荷トレンド一覧 機能仕様書

本書は **出荷トレンド一覧**（`applications/shipment_trend/`）の要件を定義する。  
得意先×品番ごとの出荷推移を可視化し、客先アクションの優先判断を支援する。

## 2. 背景・目的

出荷の増減トレンドから、営業担当が客先へアクションすべき品番を素早く見つける。  
在庫発注アラート（生産管理）とは別アプリとし、営業部門のメニューに配置する。

## 3. 機能一覧

| # | 機能 | 概要 |
|---|------|------|
| 1 | 一覧表示 | 得意先×品番の出荷合計（初年度・前年度・今年度+予測）・変動率・変動数を表形式で表示 |
| 2 | グラフ | **行クリック**でモーダル表示。月次出荷合計の折れ線＋**当年度残月**の予測（破線） |
| 3 | フィルタ | 担当者コード・得意先コード・得意先品番（前方一致・オートコンプリート） |
| 4 | 並べ替え | ポータル共通一覧エンジン（複数列ソート対応） |
| 5 | 警告色 | 変動率に応じた4段階の行背景色 |
| 6 | CSV出力 | フィルタ適用後の一覧を UTF-8 BOM 付き CSV で出力 |
| 7 | データ更新 | Oracle から全出荷を再集計し PostgreSQL スナップショットを更新（処理中はスピナーオーバーレイ表示） |

## 4. データ・集計ロジック

### 4.1 データソース

| 区分 | 内容 |
|------|------|
| Oracle | `T_SHIP`（`DEL_FLG != 1`）、品番 `ITEM_CD`、読取のみ |
| PostgreSQL | 集計スナップショット、警告閾値設定 |

### 4.2 集計年（暦年）

- **1月〜12月**（西暦年）で合計する
- ラベルは西暦年（例: 2025-01〜2025-12 → **2025年**）

### 4.3 変動指標（一覧）

| 項目 | 定義 |
|------|------|
| 初年度 | 当該得意先×品番で **最初に出荷があった年**（一覧列として表示） |
| 初年度出荷合計 | 初年度（暦年）の月次出荷数量合計 |
| 前年度出荷合計 | **集計基準日の年 − 1** の暦年の月次出荷数量合計 |
| 今年度出荷+予測 | 今年度（暦年）の集計基準日までの出荷実績合計 ＋ **当年度残月**の予測合計（**当年1月〜基準月の出荷合計 ÷ 経過月数**を切り上げた月次予測） |
| 今年度（変動数用） | **集計基準日の暦年** の出荷合計に **当年度残月の予測** を加えた合計（`current_fy_with_forecast_total`） |
| 変動数 | `今年度（予測込み） − 初年度合計` |
| 変動率 | `(変動数 / 初年度合計) × 100`（初年度0かつ今年度>0は `—` 表示） |

一覧表示時はスナップショット行の `monthly` から `hydrate_row_metrics` で指標を再計算する（旧スナップショット互換・暦年変更の即時反映）。

### 4.4 月次データ・予測（グラフ）

- 横軸: **月単位**（最初の出荷月から予測最終月まで連続。出荷のない月は 0 として表示）
- 横軸ラベル: **1月・7月**（半年ごと）および系列の**最初・最後**の月に `YYYY/M` 形式で表示
- 横軸目盛: 月ごとに等幅。**ダイアログ幅いっぱいに収める**（横スクロールなし）
- 縦軸: 月次出荷数量合計
- 実績: 折れ線（緑・実線）＋各月のマーカー。**マーカーにカーソルを合わせると月・実績/予測・数量を表示**
- 予測: **当年1月〜基準月の出荷合計 ÷ 経過月数**（出荷のない月は 0 として合計に含める）を **切り上げ** し、集計基準日の**翌月から当該年12月まで**折れ線（青・破線）で表示（`kind=forecast`）。最終実績月から予測線を接続する
- 縦軸: 左端に出荷数量の目盛（約5段）。**データ最大値がグラフ上端付近に来る**よう、最小のきりの良い上限値を採用。縦線と短い横線（目盛）＋数値ラベルを表示

### 4.5 スナップショット

1. 「データ更新」POST → Oracle 集計
2. `ShipmentTrendSummarySnapshot.rows` に JSON 保存（行ごとに `monthly` を含む）
3. 一覧・グラフ・CSV はスナップショットを参照
4. 警告閾値変更は **再集計不要**（表示時に再判定）

## 5. 警告色

閾値は `ShipmentTrendSettings`（pk=1）に保存。UI から変更可（既定 20% / 20%）。

| 条件 | 背景色 | CSS クラス | 在庫発注アラート対応色 |
|------|--------|------------|------------------------|
| 変動率 ≤ −減少閾値 | 薄い赤（`#fde8e8`） | `st-row-decrease-strong` | 重点 |
| −減少閾値 ＜ 変動率 ＜ 0% | 薄い黄（`#fff8e1`） | `st-row-decrease-mild` | 警告（出荷なし） |
| 変動率 ≥ ＋増加閾値 | 薄い緑（`#dcfce7`） | `st-row-increase-strong` | 確認済 |
| 0% ≤ 変動率 ＜ ＋増加閾値、または率なし | 白 | `st-row-neutral` | アラート無し |

一覧行・警告条件ダイアログの行背景色は、在庫発注アラートと同一パレット（`.alert-row--*`）を共有する。

警告条件ダイアログの閾値セレクトは、在庫発注アラートと共通クラス（`.portal-alert-rules-select` / `.portal-alert-rules-setting`）で同一見た目とする。

## 6. 画面仕様

### 6.1 一覧列

担当者コード、得意先コード、得意先名、得意先品番、**初年度**、初年度出荷合計、前年度出荷合計、今年度出荷+予測、変動率、変動数

### 6.1.1 一覧レイアウト

在庫発注アラート（`inventory_order_alert`）と同一のポータル一覧表レイアウトを採用する。

| 要素 | 内容 |
|------|------|
| カード | フレックス縦並び（`.st-table-card`）、画面内スクロール |
| フィルタ | グレー背景パネル、ラベル上・コントロール下。得意先品番はテキスト入力＋`datalist` オートコンプリート（前方一致・600ms デバウンス・Enter 即時反映） |
| 表 | 枠線付きラップ、sticky ヘッダー、12px フォント、列見出しリンク。**横スクロールなし**（`table-layout: fixed`・`max-width: 0` によるセル折り返し・親 flex の `min-width: 0`）。縦方向のみスクロール |
| 件数 | ツールバー右側（`.st-table-counts-left`） |
| フッタ | 表示件数・ページネーション |
| JS 読込 | テンプレート末尾（`portal-list-core.js` → `portal-list-prefix-filter.js` → `portal-list-dependent-cust-filter.js` → `portal-list-sort-dialog.js` → 画面別 JS） |

### 6.1.2 担当者コード・得意先コードフィルタ

| 項目 | 内容 |
|------|------|
| 連動 | **担当者コード → 得意先コード** のみ。担当者「すべて」時は全得意先候補 |
| 共通 | `applications/portal/domain/dependent_cust_filter.py` / `PortalListDependentCustFilter` |
| 担当者候補の並び | **数値として昇順**（非数字は末尾）。`applications/portal/domain/code_sort.py` |
| 無効な組み合わせ | URL に `cust_chrg_psn_cd` と矛盾する `cust_code` がある場合、得意先は破棄 |
| 担当者コード変更時 | 得意先コードは **常に「すべて」にリセット**（[ポータル一覧表_共通仕様.md](../共通/ポータル一覧表_共通仕様.md) §3.1.2） |
| 品番フィルタのクリア | **担当者コード・得意先コード** 変更時に `item_cd` 入力を空にリセット |

### 6.1.3 得意先品番フィルタ

| 項目 | 内容 |
|------|------|
| クエリ名 | `item_cd` |
| 表示名 | **得意先品番**（一覧列・CSV・フィルタラベルで統一） |
| 一致方式 | 得意先品番の **前方一致**（TRIM 後。資産棚卸結果の資産番号フィルタと同様） |
| 候補 | 集計結果の品番を昇順で重複除去し `datalist` に SSR 出力。`PortalListPrefixFilter.createPrefixColumnFilter` で前方一致絞り込み |
| 空欄 | 絞り込みなし |

### 6.2 詳細モーダル

**行クリック**で `<dialog id="st-detail-dialog">` を開く（`.st-table-wrap` へのイベント委譲）。ポップアップ内に **年度別出荷テーブル** と **出荷推移グラフ** を表示する。

| 要素 | 内容 |
|------|------|
| タイトル | `得意先コード - 得意先名`（例: `101 - テスト得意先`） |
| サブ情報 | 得意先品番・担当者コード |
| 年度別出荷 | 初年度から集計基準年までの各暦年について、出荷合計・予測込み合計（当年のみ予測加算）・**初年度比**変動数・変動率を表示。今年度行のみ予測込み合計で初年度との比較を行う |
| 出荷推移 | 折れ線グラフ（`.st-chart-canvas-wrap` に SVG。実績=実線、予測=破線） |
| 閉じる | 右上 **×**（`.dialog-close-button`） |
| サイズ | 幅 **画面幅 − 16px**（最大 **1920px**）。グラフ高さ **440px** 固定、横スクロールなし |

データは `GET /api/shipment-trend/chart` の `fiscalYears` および `points` を使用する（`monthly` から表示時に再計算）。

### 6.2.1 データ更新中の表示

「データ更新」POST 送信時、在庫発注アラートの SLIMS CSV 取込と同様に全画面スピナーオーバーレイ（`#st-refresh-overlay`）を表示する。メッセージは「Oracle から出荷データを集計中...」。

### 6.3 デフォルトソート

変動率 **昇順**（マイナス幅が大きい順: −50% → −10% → 0% → +10%）。同率時は変動数昇順。

### 6.4 API

| メソッド | パス | 用途 |
|----------|------|------|
| GET/POST | `/app/sales/shipment-trend` | 一覧・データ更新 |
| GET | `/api/shipment-trend/chart` | 詳細データ（`custCode`, `itemCd`。`fiscalYears`・`points`） |
| PUT | `/api/shipment-trend/alert-settings` | 警告閾値保存 |
| GET | `/app/sales/shipment-trend/export.csv` | CSV 出力（一覧表示と異なる月次形式。§6.5） |

### 6.5 CSV 出力

一覧とは異なり、**月次出荷数量**を列として出力する。

| 列 | 内容 |
|----|------|
| 担当者コード〜変動数 | 一覧と同じ（初年度出荷合計・前年度・今年度+予測の **3列は含めない**） |
| `YYYY-MM` 列 | 出力対象行全体の **最小月〜最大月** まで連続。当該月の出荷合計（実績のみ）。出荷がない月は **空欄** |

- フィルタ適用後の行を対象とする
- 月次データは行の `monthly`（スナップショット）を使用
- UTF-8 BOM 付き

## 7. 権限

- メニューグループ **営業**（`sales`）へのアクセスが必要
- `applications/portal/middleware.py` でパスガード
