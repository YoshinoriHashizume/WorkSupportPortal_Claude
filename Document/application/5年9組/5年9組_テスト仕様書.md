# 5年9組 テスト仕様書（方針・設計・ケース統合版）

本書は **5年9組（gonenkukumi）** に関する **自動テストの方針・設計・詳細テストケース** を一つにまとめたものである。単体・結合は `pytest`、**ブラウザ E2E** は Playwright。**実行手順は §5.1** を参照する。

**機能要件の正**は [5年9組_機能仕様書.md](./5年9組_機能仕様書.md) とする。本書は機能仕様の代替ではない。

## 3. 現状と前提

| 項目 | 現状（本書更新時点） |
|------|----------------------|
| リポジトリ全体 | **pytest**（`pytest`）＋ **Playwright**。Django のテスト設定は実装時に定義 |

| 外部依存 | Oracle（`python-oracledb`）、PostgreSQL（履歴）、Django 認証（セッション）。**自動テストは原則としてこれらに接続しない** |

テストは上記を踏まえ、**外部 I/O を避けた単体テストを最優先**とする。

## 4. テスト戦略（原則）

### 4.1 テストピラミッド

1. **単体テスト（最優先）** … 純関数、検索条件スキーマ、URL／クエリ変換、色・行順など **入力が決まれば出力が決まる** 処理
2. **結合テスト（限定的）** … Django views / API endpoints に対し **Oracle / DB をモック**したリクエスト／レスポンス検証
3. **E2E（任意・後段）** … ログイン済みブラウザでの画面操作。コストが高いため **クリティカルパスのみ**

### 4.2 共通原則

| 原則 | 内容 |
|------|------|
| 決定性 | 同一コミットでは **同じ結果** になること。`today_ym()` 等は **日付を引数化**するか、テスト内で固定時刻を注入できる設計に寄せる |
| 秘密情報 | `ORACLE_*`、本番接続文字列、認証シークレットを **リポジトリ・ログ・スナップショットに含めない** |
| 本番 Oracle 非依存 | CI では原則 **実 Oracle に接続しない**。接続が必要な検証は **ステージング手動**または **別ジョブ**で明示 |
| 保守コスト | Excel バイナリの **バイト完全一致**は行わない。セル値・行数・シート名など **意味のあるアサーション**に留める |

## 5. 推奨ツールチェーン（実装時の目安）

本リポジトリは Python + Django で実装するため、実装フェーズでは次を **推奨**とする（最終選定はチーム判断でよい）。

| 区分 | 推奨 | 理由 |
|------|------|------|
| 単体・結合（Python） | **pytest** | Python / Django との相性がよく、fixture で依存差し替えがしやすい |
| Django views / templates | **pytest-django** | Django のテストクライアント、URL、テンプレート検証に向く |
| E2E（任意） | **Playwright** | ブラウザ操作と認証フローに対し再現性が取りやすい |

`pytest` のような **1 コマンドでドメイン中心のスイートが通る** 状態を最初のゴールとする。

### 5.1 テストの実行方法

リポジトリ **ルート**（`manage.py` があるディレクトリ。例: `WorkSupportPortal`）で実行する。

**前提**

| 項目 | 内容 |
|------|------|
| Python / pip | プロジェクトが想定するバージョンでよい（開発メンバーは `.python-version` 等があればそれに従う） |
| 依存パッケージ | 初回または `requirements.txt` 変更後は `pip install -r requirements.txt` |

**テストコマンド**

| コマンド | 説明 |
|----------|------|
| `pytest` | **pytest** を 1 回だけ実行する。CI や PR 前の確認に向く |
| `pytest -k <名前>` | テスト名を絞って実行する |
| `python -m pytest e2e` | **Playwright** ベースの E2E を実行する（構成は実装時に定義） |

**E2E（Playwright）**

| 項目 | 内容 |
|------|------|
| 設定 | pytest-playwright を利用し、`pytest.ini` と `e2e/conftest.py` で既定 URL・起動方法を管理する |
| 既定 URL | `http://127.0.0.1:3000`（環境変数 `PLAYWRIGHT_BASE_URL` で上書き可） |
| 開発サーバ | 既定では **`python manage.py runserver 0.0.0.0:3000`** を自動起動、または事前に起動済みのサーバを利用する |
| 初回のみ | ブラウザバイナリ取得: `python -m playwright install chromium` |

**実行対象（ファイルパターン）**

`pytest.ini` 等の設定に従い、**`tests/`** または各パッケージ配下の `test_*.py` が対象。5年9組関連の例は次のとおり。

| ファイル（例） | 主な内容 |
|----------------|----------|
| `tests/gonenkukumi/test_year_month_nav.py` | 検索年月・URL 組み立て（§12.3・§12.6） |
| `tests/gonenkukumi/test_schemas.py` | 検索条件バリデーション（§12.4） |
| `tests/gonenkukumi/test_search_params_from_url.py` | クエリフラット化（§12.5） |
| `tests/gonenkukumi/test_parse_search_post.py` | POST 解析・Oracle 失敗レスポンス（§12.7・§12.8） |
| `tests/gonenkukumi/test_kaiso_color.py` 他 | §6.2 優先度 B（色・行定義・セグメント・見出し等） |
| `tests/gonenkukumi/test_excel_export.py` | §6.4 Excel バッファ・ファイル名 |
| `tests/gonenkukumi/test_history_view.py` 等 | §6.3 API モック結合 |
| `tests/gonenkukumi/test_sql_fragments.py` | §6.3 SQL 断片 |
| `e2e/test_gonenkukumi_smoke.py` | §6.4 ログイン画面スモーク |

**ファイル・パターンを絞って実行する**

```bash
pytest tests/gonenkukumi/test_year_month_nav.py
```

```bash
pytest -k "TC_YM_001"
```

（`-k` はテスト名に部分一致するケースだけ実行する。pytest のオプションは `pytest --help` で確認できる。）

**外部システムについて**

pytest スイートは **Oracle・PostgreSQL・ブラウザログインを不要**とする構成を中心にする（認証は fixture / monkeypatch 等で置き換え）。**Playwright** はブラウザを起動し `/login` 等にアクセスする。本番接続や `.env` の秘密情報をテストに埋め込まないこと（**§4.2**）。

## 6. テスト対象の優先度（モジュール単位）

### 6.1 優先度 A（最初に入れる価値が高い）

| 対象（実装パス） | 検証内容の例 | 機能仕様書との対応（参考） |
|------------------|--------------|---------------------------|
| `gonenkukumi/domain/year_month_nav.py` | `compare_ym` / `clamp_ym` / `year_month_bounds` / `ym_options_list` / `max_ym_from_as_of`、月加算、ISO 変換 | §3.1.1 |
| `gonenkukumi/domain/schemas.py` | 検索条件スキーマの正常系・形式エラー | §3.1.1、§4 |
| `gonenkukumi/domain/search_params_from_url.py` | クエリから検索条件へのマッピング、欠損・不正値 | §3.2 |
| `gonenkukumi/views/parse_search_post.py` | POST ボディの JSON／入力エラー分岐 | §4.1 |

### 6.2 優先度 B（ドメインが安定したら拡張）

実装対象: `kaiso_color`・`block_rows`・`panel_segments`・`cust_headline`・`supplier_banner_text` の pytest。

| 対象 | 検証内容の例 |
|------|----------------|
| `gonenkukumi/domain/kaiso_color.py` | 同一入力に対する色文字列の安定性（アルゴリズム固定） |
| `gonenkukumi/domain/block_rows.py` | 区分行の並び定数と仕様の一致 |
| `gonenkukumi/domain/panel_segments.py` | セグメント順序ロジック（モック JSON 入力） |
| `gonenkukumi/domain/cust_headline.py` / `supplier_banner_text.py` | 表示文字列の組み立て |

### 6.3 優先度 C（モック設計が固まってから）

実装対象: `GET history`・`POST search` の Django view テスト（Django ORM / Oracle 検索 / 認証をモック）、`sql_fragments` の定数検証。他ルート・`list_customers` 等の **python-oracledb 直結**は未着手でもよい。

| 対象 | 注意 |
|------|------|
| Django views / API endpoints | 認証および Oracle 呼び出しを **モック**し、HTTP ステータスと JSON 形のみ検証 |
| Oracle infrastructure | 実 DB なしでは **バインド配列・分岐**（`COMPANY_CD` 有無等）をスタブで検証する設計が現実的 |

### 6.4 優先度 D（任意・コスト見合いで判断）

実装対象: Excel 出力のバッファ読み戻し・ファイル名、`e2e/test_gonenkukumi_smoke.py`（ログイン画面見出し）。**5年9組画面の本番フロー E2E**は今後拡張可。

| 対象 | 備考 |
|------|------|
| Excel 出力処理 | openpyxl 等で生成した **ワークブック構造**（シート名、特定セル）を検証。ファイル丸ごとスナップショットは非推奨 |
| Playwright による画面 E2E | ログイン・セッションに依存。**「検索→結果タブ」1 本** など最小から |

## 7. モック・スタブ方針

| 依存 | 方針 |
|------|------|
| **Oracle（`python-oracledb`）** | 単体では **import をモック**するか、リポジトリパターンで「偽実装」を差し替え。SQL の正しさは **レビュー + ステージング**と併用 |
| **Django 認証** | API テストでは認証済みユーザー fixture を使い、未ログイン時 401・ログイン時 200 の分岐のみを検証 |
| **Django ORM（履歴）** | 履歴 API の結合テストでは **テスト用 DB** またはリポジトリのモック（チーム方針に合わせる） |
| **日付（現在時刻）** | `today_ym` 等を直接アサートに使うテストは **フレーク**になりやすい。現在日付を差し替え可能にするか、境界は **固定日付を引数に取る関数** に分離してテストする |

## 11. 明示的に「やらない／本書の範囲外」とするもの

| 項目 | 理由 |
|------|------|
| 本番 Oracle への常時接続テスト | データ・権限・ネットワーク依存で再現性が低い |
| 仕様書の全条文の機械的なトレーサビリティ | 運用コストが高い。重要箇所は **§12.10** のサマリでカバー |
| 画面デザインのピクセル完全一致 | デザイン変更で破綻しやすい |

## 12. 詳細テストケース

実装コードの詳細はリポジトリの現行版に準拠する。以下の **TC-ID** は本書内で一意とする。

### 12.1 記載ルール

| 項目 | ルール |
|------|--------|
| **TC-ID** | 本書内で一意。プレフィックスは §12.2 参照。 |
| **種別** | `単体` … 外部 I/O なし。`結合` … 認証／HTTP／モック DB 等を含む。`手動` … 自動範囲外。 |
| **優先度** | `P0` … 初回スイート必須。`P1` … 次サイクル。`P2` … 余力時。 |
| **期待結果** | **観測可能な事実**（戻り値、HTTP ステータス、JSON キー）に限定する。 |

### 12.2 TC-ID プレフィックス

| プレフィックス | 対象モジュール／観点 |
