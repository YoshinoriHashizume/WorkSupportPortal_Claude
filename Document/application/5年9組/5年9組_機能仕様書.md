## 2. システム境界・前提

| 区分 | 内容 |
|------|------|
| 基幹 Oracle | **参照のみ**（SELECT）。接続はサーバ側のみ。接続パラメータは環境変数（`ORACLE_*`）。値はリポジトリに含めない。 |

## 3. 画面（ルーティング）

| 画面 ID | 画面 | ルート | 概要 |
|---|---|---|---|
| SCR-01 | 検索画面 | `/app/production/five-year-nine` | 検索条件入力、検索実行、履歴（直近20件・表形式）表示 |
| SCR-02 | 結果画面 | `/app/production/five-year-nine/result` | クエリ（検索条件）で Oracle 再検索→結果表示。履歴 ID は用いない |

### 3.1 検索画面（SCR-01）

#### 3.1.1 入力項目（実装固定）

- **画面レイアウト順**（上から）: 得意先コード → 得意先品目 → 品目任意変換値 → **検索年月と対象日付を同一行**（狭い幅では縦積み）→ **検索ボタン** → **エラー表示**（発生時のみ、ボタンの直下）。

| 項目 | キー | 型/形式 | 必須 | 既定値 | 備考 |
|---|---|---|---|---|---|
| 得意先コード | `custCode` | string | 必須 | なし | Oracle `M_CUST` から `GET /api/gonenkukumi/customers` で一覧取得し、**コンボボックス**（入力・▼一覧・キーボード）で指定。一覧取得失敗時も**手入力可**。候補は **数字3桁コードのみ**。候補表示は **コード → 名称** |
| 得意先品目 | `custItem` | string | 必須 | なし | **得意先コード未入力では入力不可（disabled）**。得意先コードが変わったら自動でクリア（履歴反映時はクリアしない）。オートコンプリートは §3.1.4 |
| 品目任意変換値 | `optionChange` | string | 任意 | `*` | 空のとき `*` 扱い |
| 検索年月 | `yearMonth` | `yyyy/mm` | 必須 | 注記参照 | `schemas.ts` バリデーション（形式のみ。選択肢の上下限は別途） |
| 対象日付 | `asOfDate` | `yyyy/mm/dd` | 必須 | 当日（サーバ基準の暦日をクライアントで生成） | UI は `type=date`（`yyyy-MM-dd`）に変換し、API では `yyyy/mm/dd` に戻す |

**検索年月の UI 仕様（実装固定）**

- 入力は **`<select>` ドロップダウン**（自由入力不可）。選択肢は暦月の一覧で、**下限 `2022/01`、上限は「対象日付の暦月から 6 か月後の暦月」**（`year-month-nav.ts` の `yearMonthBounds` / `ymOptionsList`）。
- 初期表示時、既定の検索年月は **「今日の暦月」**を、上記 min〜max の範囲に **クランプ**した値（`clampYm(todayYm(), min, max)`）。
- **対象日付を変更**すると min/max が変わるため、現在の検索年月が範囲外になった場合は **自動で範囲内にクランプ**する。

#### 3.1.2 操作（実装固定）

- **検索ボタン**: `/api/gonenkukumi/search` に POST。成功時、**同一の検索条件をクエリ文字列に載せて**新規タブで `SCR-02`（`/app/production/five-year-nine/result?...`）を開く。検索画面側は **履歴の再取得のためページを refresh** する（Next.js 実装）。
- **履歴クリック**: 履歴をクリックすると、検索条件にその内容を反映する（即時検索は行わない）。対象日付は履歴からは変更しない（画面左の入力のまま）。

#### 3.1.3 履歴表示（実装固定）

- SSR で **条件セット（得意先コード/得意先品目/品目任意変換値/検索年月）ごとに最新1件**を取得し、最大**20件**を初期表示する（同一条件は検索日時が新しいもののみ表示）。
- 画面上は **表（テーブル）** で表示する。列は **得意先コード／得意先品目／品目任意変換値／検索年月／検索日時**（対象日付列は置かない。行クリックでも対象日付は変更しない。スラッシュ等で1行に連結したテキスト表示もしない）。**lg 以上では各列を均等幅（各 20%）**とする。
- 履歴一覧は **約8〜9行分（max-height 20rem）で縦スクロール**し、テーブルヘッダ（列名行）は **スクロールしても固定（sticky）**する。
- API `/api/gonenkukumi/history` も提供（最大50件）。

#### 3.1.4 得意先品目オートコンプリート（実装固定）

- **プリフェッチ方式**: 得意先コードが確定した瞬間に `GET /api/gonenkukumi/cust-items?custCode=&asOfDate=` を 1 回呼び、当該得意先の「得意先品目」全件をクライアントメモリにキャッシュする。
- **入力ごとの候補表示**: 入力 **1文字目から**、キャッシュを **先頭一致（startsWith）**で絞り込み、候補を表示する（入力のたびに API は呼ばない）。
- **候補表示上限**: UI 表示は最大 **1000件**（1社1000件想定）。
- **取得中の扱い**: キャッシュ取得完了前は「一致する得意先品目がありません。」は表示しない。
- **一致なしメッセージ**: 取得完了後に候補が 0 件のとき、赤文字で **「一致する得意先品目がありません。」** を表示する。

### 3.2 結果画面（SCR-02）

- **クエリパラメータ**（`custCode`, `custItem`, `optionChange`, `yearMonth`, `asOfDate`）を検証し、**Oracle へ再問い合わせ**して描画する（スナップショット保持なし）。履歴テーブルは参照しない。
- 検索条件ブロックの **得意先**は、Oracle 結果の略称名とクエリのコードから **`得意先名(得意先コード)`** で表示する（名が取れないときはコードのみ）。
- ブラウザタイトルは **`得意先名(得意先コード)：得意先品目`** とする（`generateMetadata` とページ本体で同一 Oracle 呼び出しを `cache` で共有）。
- **結果の縦積み（階層ブロック単位）**: 画面は **得意先 出荷**／**仕入先 入荷（BOM 階層ごと）** のブロックに分割する。**Web 結果画面では複数得意先の「ＴＯＴＡＬ」合計表は表示しない**（Oracle JSON には集計が残る場合があるが §6 参照。Excel にも TOTAL 専用ブロックは出さない）。**「前月を追加／次月を追加」は検索条件ブロックにのみ置き、押下すると表示中の全ブロック（得意先・全仕入階層）に同じ暦月の Oracle 結果がまとめて追加**される（新規タブは開かない）。追加の基準は「画面全体で読み込み済みの月のうち最も古い月の前月」「最も新しい月の次月」。同一月の二重追加は不可。検索画面と同じ範囲（**2022/01**〜**対象日付から6か月後の暦月**）外へは出せず、該当ボタンは無効。追加データは **`POST /api/gonenkukumi/oracle-result`** で取得する（履歴テーブルには記録しない）。**各月は折りたたみ可能**（`<details>` 相当）。`<summary>` には **検索年月** と **その月の代表行**（得意先ブロックは先頭得意先の見出し相当、仕入ブロックは該当階層の先頭仕入の見出し相当）を載せ、**当該行をクリックして開閉**する。表ブロックの外に **重複する別帯タイトル行**は置かない（代表見出しは `<summary>` に集約）。
- **日次列（Web 表示）**: 表の日次列は **常に 31 列**（1日〜31日）。当月に存在しない日付列は **空白**とし、**背景はその表ブロックの階層テーマ色**（見出しは `cssLightBg`、データ部は `cssVeryLightBg` 相当の系統色。7.1／7.2 の色割当）で示す。
- **`<summary>` 補助文**: 折りたたみ見出し行に、折りたたみ中は「クリックで展開」、展開中は「クリックで折りたたみ」という **小さな補助テキスト**を表示してよい（実装有り）。
- Excel 出力ボタン「Excelで出力」を表示する。
  - **単月のみ**読み込まれている状態: **URL の検索年月（基準月）**に対応する Oracle 結果のみから 1 ブックを生成する。
  - **「前月を追加／次月を追加」で複数暦月を読み込んだ状態**: **読み込み済みの全暦月**の Oracle 結果を、後述の **セグメント順**で縦に連結し **1 シート**に出力する。URL の検索年月は **基準月**（条件欄の「検索年月（基準）」、セグメント並びの基準）として用い、帯見出し等に反映する。

## 4. API 仕様（Next.js Route Handlers）

### 4.1 `POST /api/gonenkukumi/search`

- **認証**: 必須（未ログインは 401）
- **入力**: JSON

```json
{
  "custCode": "string",
  "custItem": "string",
  "optionChange": "*",
  "yearMonth": "yyyy/mm",
  "asOfDate": "yyyy/mm/dd"
}
```

- **バリデーション**: `src/domains/gonenkukumi/schemas.ts`（Zod）
- **処理**:
  - Oracle 一括検索 `runGonenKukumiOracleSearch`
  - 成功時のみ履歴 INSERT（**対象日付・`custName` は PostgreSQL に保存しない**）
- **成功応答**:

```json
{ "ok": true }
```

- **失敗応答（代表）**:
  - 400: JSON 解析失敗（例: `JSON が不正です`）／Zod 入力エラー（`入力エラー` + `details`）
  - 404: 内作品番未解決（`NAISAK_NOT_FOUND`）
  - 502: Oracle 実行例外（`ORACLE_ERROR`）またはその他の Oracle 失敗
  - 503: Oracle 未設定（`ORACLE_NOT_CONFIGURED`）

### 4.2 `GET /api/gonenkukumi/customers`

- **認証**: 必須（未ログインは 401）
- **処理**: Oracle `M_CUST` から得意先コード・略称名を取得（最大 500 行）。**数字3桁コードのみ**を対象にする。未設定時は空配列。
- **成功応答**:

```json
{
  "items": [{ "custCode": "string", "custName": "string" }]
}
```

- 取得例外時は HTTP 200 で `items: []` と `loadError`（文字列）を返し、画面は手入力にフォールバックする。

### 4.3 `GET /api/gonenkukumi/history`

- **認証**: 必須（未ログインは 401）
- **応答**: 最大50件、新しい順

```json
{
  "items": [
    {
      "id": "string",
      "executedAt": "ISO",
      "custCode": "string",
      "custItem": "string",
      "optionChange": "string",
      "yearMonth": "yyyy/mm"
    }
  ]
}
```

※ `optionChange` は DB に保存されており、履歴反映時にフォームへ戻すために必須。

### 4.4 `POST /api/gonenkukumi/oracle-result`

- **認証**: 必須（未ログインは 401）
- **目的**: 結果画面で「前月／次月を追加」したときに、同一検索条件・別 `yearMonth` の Oracle 結果を JSON で返す（**履歴 INSERT は行わない**）。
- **入力**: `POST /api/gonenkukumi/search` と同じ JSON 本体（`schemas.ts`）
- **成功応答**: `{ "ok": true, "oracle": { ... } }`（`oracle` は `GonenKukumiOracleSuccess` 相当）
- **失敗応答**: `POST /api/gonenkukumi/search` と同様（400 / 404 / 502 / 503）

### 4.5 `GET /api/gonenkukumi/cust-items`

- **認証**: 必須（未ログインは 401）
- **目的**: 得意先品目のオートコンプリート用に、得意先コード確定時に **全件プリフェッチ**する。
- **入力**: `custCode`（必須）, `asOfDate`（`yyyy/mm/dd` 必須）
- **成功応答**:

```json
{ "items": ["string"] }
```

- **備考**: サーバ側で Oracle 未設定時は `items: []` を返す。

### 4.6 `GET /api/gonenkukumi/cust-item-suggestions`（補助 API）

- **認証**: 必須（未ログインは 401）
- **目的**: クエリ `q` が **3 文字以上**のとき、Oracle から得意先品目の前方一致候補を返す（サーバ都度検索型）。
- **現行 UI**: 得意先品目は **§3.1.4 のプリフェッチ方式**（`GET /api/gonenkukumi/cust-items`）のみ使用しており、本 API は **画面からは呼ばれない**。互換・将来拡張用にルートが存在する場合があるため、ベンダーは **未使用で削除しても業務要件上は差し支えない**（要確認）と捉えてよい。

## 6. Oracle 参照（論理）

### 6.1 一括検索

- 入口: `runGonenKukumiOracleSearch`（`src/infrastructure/oracle/gonenkukumi/run-search.ts`）
- 取得する結果（概念）:
  - **内作品番**（`internalItemCd`）
  - **休日一覧**（`holidayDays`：1〜31 の日番号）
  - **得意先ブロック**（出荷側）
  - **TOTAL**（得意先複数時、集計データは Oracle JSON に保持しうるが、**Web / Excel では専用ブロックとして表示しない**）
  - **仕入先ブロック**（入荷側、BOM 展開）

### 6.1.1 内作品番の解決（`NAISAK_NOT_FOUND` の判定）

- `M_CUST_ITEM` を `CUST_CD`・`DLV_LOC_CD = '*'`・`CUST_ITEM_CD`・`ITEM_CD_OPTION_CHANGE_VALUE`（空は `*`）で検索し、`ITEM_CD` を 1 件取得。
- 有効期間は `sql-fragments.ts` の `SQL_CUST_ITEM_EFF_RANGE`（`EFF_PHASE_IN_DATE` / `EFF_PHASE_OUT_DATE` と `:asOf`）で **`asOfDate` 時点で有効**な行に限定。`list-cust-items`（得意先品目プリフェッチ）も **同一条件**。

### 6.1.2 得意先ブロック（出荷側）

- `M_CUST_ITEM` と `M_CUST` を結合し、解決した **内作品番 `ITEM_CD`** に紐づく **全得意先行**を取得（`ITEM_CD_OPTION_CHANGE_VALUE`・有効期間・任意 `COMPANY_CD`）。
- 行が **0 件**のときは、入力された `custCode` で **フォールバック行**を 1 件合成し、その得意先コードで日次系列のみ取得する（名寄せ行が無いケースの表示継続）。

### 6.1.3 得意先側の日次系列（ソース表の対応）

| 区分ラベル（画面・Excel） | 概要（Oracle 側） |
|---------------------------|-------------------|
| 内示受注 | `T_UNCNFM_ODR`（`UNCNFM_REQUIRED_DATE` × `UNCNFM_REQUIRED_QTY`、削除フラグ除外） |
| 確定受注（前月残） | `T_ODR` で検索月 1 日より前の納期かつ未完了の残 |
| 確定受注（日次） | `T_ODR`（`DESINATED_DLV_DATE` × `ODR_QTY`） |
| 統合受注 | `T_UNITE_ODR`（`SHIP_PLAN_DATE` × `REQUIRED_QTY`） |
| 出荷実績 | `T_SHIP` |
| 売上実績 | `T_SALES_TEMP`（`ONEROUS_CONS_SALES_TYP = 1` は除外） |
| 本日在庫（行計のみ） | `T_ITEM_STOCK` の **内作品番**に対する `STOCK_ON_HAND_QTY` 合計（日次列は空） |

### 6.1.4 仕入先ブロック（BOM・外注）

- `M_PS` を `CONNECT BY` で展開。親は内作品番、**有効期間は `asOfDate` で挟み込み**。
- 同一 `COMP_ITEM_CD` は **先頭のみ採用**（重複スキップ）。
- 構成子 `M_ITEM` の **`OUTSIDE_TYP` が `'2'`（外注）** の品目のみ対象。
- 仕入先は `M_PUCH_UNIT_COST_H` を `PUCH_PRIORITY_REF_NO`・`VEND_CD` 昇順で並べ **先頭 1 件**の取引先。保管区は `M_ITEM_RCV_WH` の左結合（無ければ `?`）。
- **手配区分**（帯表示用）: `M_ITEM.PROCESS_REQUEST_ISS_TYP = '1'` →「加工依頼」、`KANBAN_FLG = '1'` →「かんばん」、それ以外は空。

### 6.1.5 仕入先側の日次系列

| 区分ラベル | 概要 |
|------------|------|
| 月初発注 | `T_U_MONTHLY_ODR_WORK`（管理年月・`TRIM(VENDOR_CD)`・`TRIM(ARRIVAL_ITEM_CD)`一致。`DAY_01`/`QTY_01`…`DAY_26`/`QTY_26` を日番号へ展開して集約） |
| 所要量 | `T_OD`（`OD_TYP = 2`、取消されていない `T_RLSD_PUCH_ODR` と左結合） |
| 確定発注（前月残） | `T_RLSD_PUCH_ODR` と `T_PAST_INSPC_ACPT`、納期が検索月 1 日より前・ステータス条件あり |
| 確定発注（日次） | `T_RLSD_PUCH_ODR` |
| 入荷実績 | `T_PAST_INSPC_ACPT` |
| 本日在庫 | 構成子品目の `T_ITEM_STOCK` 合計（日次列は空） |

### 6.1.6 休日（`M_CAL`）

- `HOLIDAY_FLG` を Trim し **`'0'` 以外または Null** を休日とみなす（VBA 相当の前提）。
- `CAL_DATE` は `YYYYMMDD` / `yyyy/mm/dd` / `yyyy-mm-dd` 等の揺れを吸収。取得に失敗した場合は **ログ出力のうえ空配列**（休日セル強調なしで継続）。

### 6.2 仕入先ブロックで使用する `M_PS` 列

- `LEVEL`（CONNECT BY の階層）を `kaiso` として保持する。
- `CONS_TYP` を保持し、表示上「支給区分」に変換して表示する。
  - 0: 非
  - 1: 有償支給
  - 2: 無償支給

## 7. 表示仕様（Web/Excel 共通）

### 7.1 セクション共通テーマ（見た目の固定）

結果表は「セクション」単位にテーマ色を割り当て、以下を**共通仕様**として適用する。

- **Web / Excel 共通の日次グリッド**: 日列は **31 列固定**（`GONEN_REPORT_GRID_DAYS = 31`）。当月に無い日は、**Web** は当該セクションの階層テーマ色で空白セル化、**Excel** はパディング列として **固定色**（実装: `#b8c4d0` 相当）で塗り、数値は空欄（§8）。
- **外枠**: 濃い色（テーマ色）
- **台タイトル行**: 背景=基準色、枠=やや薄い色（テーマ色）
- **日付行（区分/行計/前月残/1日…）**: 背景=基準色、枠=やや薄い色（テーマ色）
- **休日列（M_CAL）**: 背景=基準色（データ部の日次セル）
- **左の区分セル（内示受注、月初発注等）**: 背景=すごく薄い色（テーマ色）
- **その他枠（グリッド）**: `#E2E8F0` 固定

### 7.2 基準色の割当（実装固定）

- 得意先セクション: index=1
- **TOTAL**: Oracle 結果 JSON に `customerTotals` として保持される場合があるが、**Web / Excel いずれも TOTAL 専用の表セクションは出さない**（テーマ index=2 の割当は実装上残存しうるが画面非表示）
- 仕入先セクション: index=2+`kaiso`（**同一階層は同一色**）

色生成のアルゴリズムは `src/domains/gonenkukumi/kaiso-color.ts` に準拠（黄金角 + HSL）。

## 8. Excel 出力仕様（実装固定）

### 8.1 出力方法

- 結果画面のボタン「Excelで出力」で、ブラウザ内で xlsx を生成しダウンロードする。
- 実装: `src/domains/gonenkukumi/excel-export.ts`
- **単月**: URL の検索年月（基準月）に対応する Oracle 結果のみを出力する。
- **複数月を追加表示した場合**: **読み込み済みの全暦月**の Oracle 結果を **昇順（暦月）**で用い、**セグメント**（基準月に存在する得意先ブロック／仕入ブロックの並びを先頭とし、他月にのみ現れるブロックを末尾に追加）ごとに、各月の表を **縦に連結**して 1 シートにまとめる（`groupSegmentsFromCache` の順序）。

### 8.2 ブック/シート/ファイル名

- シート名: `5年9組`
- 1行目タイトル（全列結合）: **`5年9組`**（サブタイトル「検索結果」は付与しない）
- ファイル名（単月）: `{custCode}_{custItem}_{yyyyMM}_{yyyyMMddHHmmss}.xlsx`（東京時刻、禁止文字は `_` 置換）
- ファイル名（複数月）: `{custCode}_{custItem}_{最初の月yyyyMM}[-{最後の月yyyyMM}]_{yyyyMMddHHmmss}.xlsx`（月が 1 つなら `-` 区切りは出ない）
- フォント: **MS PGothic（ＭＳ Ｐゴシック）**
- 数値: 千区切り `#,##0`

### 8.3 先頭（検索条件ブロック）

- 2〜5行目に検索条件を配置（A〜C 列のみ枠線、D 列以降は塗り無し）
- 表示内容の例: 得意先コード／得意先品目／品目任意変換値、検索年月（基準）／対象日付／**内作品番**（基準月の Oracle 結果から）

### 8.4 セクション出力

各セクションは以下の順で出力する（各セクションに日付行を持つ）。

1. 台タイトル（全列結合 1 行）
2. 日付行（`区分/行計/前月残／在庫/1日…31日` の 1 行。列数は常に 31 日分）
3. データ行（複数行）

**得意先ブロックの行順**（左の区分列）: 内示受注 → 確定受注 → 統合受注 → 出荷実績 → 売上実績 → 本日在庫（`block-rows.ts` の `CUSTOMER_ROW_SPECS`）。

**仕入先ブロックの行順**: 月初発注 → 所要量 → 確定発注 → 入荷実績 → 本日在庫（`SUPPLIER_ROW_SPECS`）。

### 8.5 色・罫線

7.1 の共通仕様を Excel に適用する（外枠・台タイトル・日付行・休日列・左区分セル・固定グリッド色）。

### 8.6 表示上のその他

- **ウィンドウ枠の固定**: 条件ブロックの下の行からスクロール領域とし、先頭の検索条件は常に見える位置に固定（Excel の freeze panes 相当）。
- **列幅**: 区分列・行計列を広め、日次列は狭めの固定幅（実装値に準拠）。

## 10. ベンダー納品時の確認観点（チェックリスト）

同等機能を **別実装**する場合に、受入側が検証しやすいよう列挙する。

| No | 観点 |
|----|------|
| C-01 | ログイン必須（未ログインで画面・API ともに拒否） |
| C-02 | 検索条件・履歴・API の入出力が本章 §3〜§5・§4 と整合 |
| C-03 | Oracle は SELECT のみ、接続情報はサーバ環境変数管理（§2・§9） |
| C-04 | `GONENKUKUMI_COMPANY_CD` / `MARI_COMPANY_CD` 設定時、全 SQL で会社コードが一貫 |
| C-05 | 内作品番が解決できない場合は 404（`NAISAK_NOT_FOUND`）でユーザーに分かるメッセージ |
| C-06 | 日次列 31 本・当月外日の扱いが Web／Excel で本章どおり |
| C-07 | 複数月追加後の Excel が **全読込月**を含むこと、ファイル名が単月／複数月で切替わること |
| C-08 | 休日・数値（カンマ区切り数量等）の Oracle 揺れ吸収が実装済み相当であること |
