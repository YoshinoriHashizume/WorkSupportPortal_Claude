## 3. 画面（ルーティング）

| 画面 ID | 画面 | ルート | 概要 |
|---|---|---|---|
| SCR-01 | 検索画面 | `/app/production/five-year-nine` | 検索条件入力、検索実行、履歴（直近20件・表形式）表示 |
| SCR-02 | 結果画面 | `/app/production/five-year-nine/result` | クエリ（検索条件）で Oracle 再検索→結果表示。履歴 ID は用いない |

### 3.1 検索画面（SCR-01）

#### 3.1.1 入力項目（実装固定）

- **画面レイアウト順**（上から）: 得意先 → 得意先品目 → 品目任意変換値 → **検索年月と対象日付を同一行**（狭い幅では縦積み）→ **検索ボタン** → **エラー表示**（発生時のみ、ボタンの直下）。

| 項目 | キー | 型/形式 | 必須 | 既定値 | 備考 |
|---|---|---|---|---|---|
| 得意先 | `custCode` | string | 必須 | なし | 共通部品 `includes/customer_select.html` を使用。Oracle `M_CUST` から **サーバー側で候補を描画**し、`GET /api/gonenkukumi/customers` で再取得して更新する（`portal-customer-select.js`）。`<select>` 表示は **`コード - 名称`**（名称は `NVL(CUST_ANAME, CUST_NAME)`） |
| 得意先品目 | `custItem` | string | 必須 | なし | **得意先未入力では入力不可（disabled）**。得意先が変わったら自動でクリア（履歴反映時はクリアしない）。オートコンプリートは §3.1.4 |
| 品目任意変換値 | `optionChange` | string | 任意 | `*` | 空のとき `*` 扱い |
| 検索年月 | `yearMonth` | `yyyy/mm` | 必須 | 注記参照 | 検索条件バリデーション（形式のみ。選択肢の上下限は別途） |
| 対象日付 | `asOfDate` | `yyyy/mm/dd` | 必須 | 当日（サーバ基準の暦日をクライアントで生成） | UI は `type=date`（`yyyy-MM-dd`）に変換し、API では `yyyy/mm/dd` に戻す |

**検索年月の UI 仕様（実装固定）**

- 入力は月選択 UI（自由入力不可）。選択肢は暦月の一覧で、**下限 `2022/01`、上限は「対象日付の暦月から 6 か月後の暦月」**（Django 実装の年月ユーティリティ）。画面表示は `YYYY/MM` とし、API 内部値は正規化して扱う。
- 初期表示時、既定の検索年月は **「今日の暦月」**を、上記 min〜max の範囲に **クランプ**した値。
- **対象日付を変更**すると min/max が変わるため、現在の検索年月が範囲外になった場合は **自動で範囲内にクランプ**する。

**ブラウザ保存済み候補の抑止（実装固定）**

- 検索フォーム全体、得意先コード、得意先品目は `autocomplete="off"` を指定し、ブラウザが保存した過去入力候補を表示しないようにする。
- 得意先コード・得意先品目の候補表示は、ブラウザ保存データではなく、アプリ側で取得・キャッシュした Oracle 候補を優先する。

#### 3.1.2 操作（実装固定）

- **検索ボタン**: `/api/gonenkukumi/search` に POST。成功時、**同一の検索条件をクエリ文字列に載せて**新規タブで `SCR-02`（`/app/production/five-year-nine/result?...`）を開く。検索画面側は **履歴の再取得のためページを refresh** する（Django 実装）。
- **履歴クリック**: 履歴をクリックすると、検索条件にその内容を反映する（即時検索は行わない）。対象日付は履歴からは変更しない（画面左の入力のまま）。
- **検索画面タイトル**: `portal-section-head` にタイトル「5年9組」・お気に入り・説明文を表示する（検収書比較 設定画面と同構成）。
- **検索画面レイアウト**: 検収書比較 設定画面と同様に、上段に `portal-section-head`、下段に **2列グリッド**（`gonen-search-body`）。左列は `gonen-search-sidebar` に検索条件フォーム（`gonen-search-card`）、右列は `db-table-card gonen-history-list-card` に検索履歴表。左列幅は **最大 380px**、右列は残り幅・縦いっぱい。履歴表は `.db-table-wrap` 内で縦スクロールし、列見出しは固定（`position: sticky`）。検索履歴カードの下には **16px** の余白（`--gonen-history-bottom-gap`）を設ける。入力欄高は 40px（`--portal-control-height`）。

#### 3.1.3 履歴表示（実装固定）

- SSR で **条件セット（得意先コード/得意先品目/品目任意変換値/検索年月）ごとに最新1件**を取得し、最大**20件**を初期表示する（同一条件は検索日時が新しいもののみ表示）。
- 画面上は **表（テーブル）** で表示する。列は **得意先／得意先品目／品目任意変換値／検索年月／検索日時**（得意先列は **`コード - 名称`** 形式。対象日付列は置かない。行クリックでも対象日付は変更しない。スラッシュ等で1行に連結したテキスト表示もしない）。**lg 以上では各列を均等幅（各 20%）**とする。
- 履歴一覧は **`.db-table-wrap` 内で縦スクロール**し、テーブルヘッダ（列名行）は **スクロールしても固定（sticky）**する。
- API `/api/gonenkukumi/history` も提供（最大50件）。

#### 3.1.4 得意先品目オートコンプリート（実装固定）

- **プリフェッチ方式**: 得意先コードが確定した瞬間に `GET /api/gonenkukumi/cust-items?custCode=&asOfDate=` を 1 回呼び、当該得意先の「得意先品目」全件をクライアントメモリにキャッシュする。
- **入力ごとの候補表示**: 入力 **1文字目から**、キャッシュを **先頭一致（startsWith）**で絞り込み、候補を表示する（入力のたびに API は呼ばない）。
- **候補表示上限**: UI 表示は最大 **1000件**（1社1000件想定）。
- **取得中の扱い**: キャッシュ取得完了前は「一致する得意先品目がありません。」は表示しない。
- **一致なしメッセージ**: 取得完了後に候補が 0 件のとき、赤文字で **「一致する得意先品目がありません。」** を表示する。

### 3.2 結果画面（SCR-02）

- **クエリパラメータ**（`custCode`, `custItem`, `optionChange`, `yearMonth`, `asOfDate`）を検証し、**Oracle へ再問い合わせ**して描画する（スナップショット保持なし）。履歴テーブルは参照しない。
- 検索条件ブロックの **得意先**は、Oracle 結果の略称名とクエリのコードから **`得意先名(得意先コード)`** で表示する（名が取れないときはコードのみ）。
- ブラウザタイトルは **`得意先名(得意先コード)：得意先品目`** とする。Django 実装では、結果画面の view で取得した Oracle 結果からタイトル用文字列を組み立て、テンプレートの `<title>` とページ本体の表示に同じ値を渡す。
- **結果の縦積み（階層ブロック単位）**: 画面は **得意先 出荷**／**仕入先 入荷（BOM 階層ごと）** のブロックに分割する。**Web 結果画面では複数得意先の「ＴＯＴＡＬ」合計表は表示しない**（Oracle JSON に集計が残る場合があるが §6 参照。Excel にも TOTAL 専用ブロックは出さない）。
- **前月・次月の追加表示**: 初期表示では URL の `yearMonth` を **基準月**として、基準月のみを表示する。検索条件ブロックに **「前月を追加」「次月を追加」** ボタンを表示し、押下すると別ページや別タブを開かず、同じ結果ページ内に対象月の月パネルを追加する。追加の基準は、表示中の月のうち最も古い月の前月、または最も新しい月の次月とする。
- **月パネルの配置**: 追加した月は、月ごとに画面全体へ並べるのではなく、**得意先ブロックごと**、および **仕入先ブロック（階層・品目番号・仕入先コードごと）** の中に月パネルとして表示する。得意先ブロックは `custCode + custItem`、仕入先ブロックは `kaiso + itemCd + vendCd` を同一ブロック判定キーとする。月パネル順は暦月昇順とする。月パネルの年月表示は `YYYY/MM` とする。基準月は `（基準）` を表示せず、前後1か月は **前月／次月**、前後2か月は **前々月／次々月**、前後3か月以降は **3か月前／3か月後** のように数字付きで表示する。
- **対象日付の扱い**: 前月・次月を追加しても、検索画面から渡された `asOfDate` はすべての表示月で同じ値を使い、マスタ有効判定の基準を固定する。画面・Excelでテキスト表示する対象日付は `YYYY/MM/DD` 表記にする。
- **月パネルの開閉**: 各月パネルは折りたたみ可能（`<details>` 相当）とし、`<summary>` には **検索年月** と **前月／次月等** の区分を表示する。ただし基準月は `（基準）` を表示せず検索年月のみとする。折りたたみ見出し行に、折りたたみ中は「クリックで展開」、展開中は「クリックで折りたたみ」という小さな補助テキストを表示してよい（実装有り）。
- **日次列（Web / Excel 表示）**: 表の日次列は **常に 31 列**（1日〜31日）。当月に存在しない日付列は **空白**とし、Web と同じ `#b8c4d0` の背景で示す。休日の日別データセルはその表ブロックの基準色（`block.theme.bg`）で示す。
- **結果表の行高**: `.next-report-grid` のセルは **最小 26px**（`--gonen-result-row-height`）、本文 **13px**、数量 **12px** とし、区分名・数値が縦に潰れないよう表に合わせた高さで表示する。
- **結果画面のスクロール**: 結果画面（`bare-result-page`）は **ページ全体の縦スクロール**を許可する。`portal-app-page` のビューポート固定は結果画面では無効化し、得意先／仕入先ブロックと月パネル内の表は **内容に応じた高さ**で表示する（ブロック内で表を縦圧縮しない）。
- **数量表示**: 行計・前月残・日別数量は、値が `0` の場合は空欄で表示し、非ゼロの数値は **3桁ごとのカンマ区切り**（例: `1,234`）で表示する。確定受注・確定発注などの行計は VBA の `SUM(F:AK)` 相当とし、前月残列の値も含めて計算する。一方、在庫行の在庫数は対象日時点で残っている値であり、前月残でも当月日別値でもないため、行計列に固定表示し、前月残列および1日〜31日列には表示しない。API 内部値は数値のまま保持し、表示時のみ変換する。
- Excel 出力ボタン「Excelで出力」を表示する。
  - **現行実装**: Web 画面で表示中の月パネル（基準月のみ、または前月／次月を追加した表示月リスト）を 1 ブックに出力する。Excel 出力リンクには `months` クエリを付与し、結果画面と同じ表示月をサーバー側で再取得する。

## 4. API 仕様（Django views / API endpoints）

### 4.1 `POST /api/gonenkukumi/search`

- **認証**: 必須（未ログインは 401）
- **入力**: JSON

```json
{
  "custCode": "string",
  "custItem": "string",
  "optionChange": "*",
  "yearMonth": "yyyy/mm",
  "asOfDate": "yyyy/mm/dd"
}
```

- **バリデーション**: Django form / serializer またはドメイン層の検索条件スキーマ
- **処理**:
  - Oracle 一括検索ユースケース `run_gonenkukumi_oracle_search`
  - 成功時のみ履歴 INSERT（**対象日付・`custName` は PostgreSQL に保存しない**）
- **成功応答**:

```json
{ "ok": true }
```

- **失敗応答（代表）**:
  - 400: JSON 解析失敗（例: `JSON が不正です`）／入力バリデーションエラー（`入力エラー` + `details`）
  - 404: 内作品番未解決（`NAISAK_NOT_FOUND`）
  - 502: Oracle 実行例外（`ORACLE_ERROR`）またはその他の Oracle 失敗
  - 503: Oracle 未設定（`ORACLE_NOT_CONFIGURED`）

### 4.2 `GET /api/gonenkukumi/customers`

- **認証**: 必須（未ログインは 401）
- **処理**: Oracle `M_CUST` から得意先コード・略称名を取得（最大 500 行）。**数字3桁コードのみ**を対象にする。未設定時は空配列。
- **成功応答**:

```json
{
  "items": [{ "custCode": "string", "custName": "string" }]
}
```

- 取得例外時は HTTP 200 で `items: []` と `loadError`（文字列）を返し、画面は手入力にフォールバックする。

### 4.3 `GET /api/gonenkukumi/history`

- **認証**: 必須（未ログインは 401）
- **応答**: 最大50件、新しい順

```json
{
  "items": [
    {
      "id": "string",
      "executedAt": "ISO",
      "custCode": "string",
      "custItem": "string",
      "optionChange": "string",
      "yearMonth": "yyyy/mm"
    }
  ]
}
```

※ `optionChange` は DB に保存されており、履歴反映時にフォームへ戻すために必須。

### 4.4 `POST /api/gonenkukumi/oracle-result`

- **認証**: 必須（未ログインは 401）
- **目的**: 同一検索条件・指定 `yearMonth` の Oracle 結果を JSON で返す補助 API（**履歴 INSERT は行わない**）。
- **現行結果画面での扱い**: SCR-02 の「前月を追加」「次月を追加」は、同じ結果ページの URL に表示月リストを保持して再描画する方式とする。再描画時にサーバー側で表示対象月を取得するため、本 API は補助 API（将来の非同期追加等に利用可能）として扱う。
- **入力**: `POST /api/gonenkukumi/search` と同じ JSON 本体（検索条件バリデーションを適用）
- **成功応答**: `{ "ok": true, "oracle": { ... } }`（`oracle` は §6 の取得結果を表す辞書構造）
- **失敗応答**: `POST /api/gonenkukumi/search` と同様（400 / 404 / 502 / 503）

### 4.5 `GET /api/gonenkukumi/cust-items`

- **認証**: 必須（未ログインは 401）
- **目的**: 得意先品目のオートコンプリート用に、得意先コード確定時に **全件プリフェッチ**する。
- **入力**: `custCode`（必須）, `asOfDate`（`yyyy/mm/dd` 必須）
- **成功応答**:

```json
{ "items": ["string"] }
```

- **備考**: サーバ側で Oracle 未設定時は `items: []` を返す。

### 4.6 `GET /api/gonenkukumi/cust-item-suggestions`（補助 API）

- **認証**: 必須（未ログインは 401）
- **目的**: クエリ `q` が **3 文字以上**のとき、Oracle から得意先品目の前方一致候補を返す（サーバ都度検索型）。
- **現行 UI**: 得意先品目は **§3.1.4 のプリフェッチ方式**（`GET /api/gonenkukumi/cust-items`）のみ使用する。本 API は画面から呼ばないため、Django 版では **実装任意** とする。実装しない場合でも業務要件は満たす。

## 5. 検索履歴（PostgreSQL / Django ORM）

### 5.1 エンティティ（実装固定）

Django ORM の `GonenKukumiSearchHistory` モデルとして定義する。

| 列 | 型 | 説明 |
|---|---|---|
| id | UUIDField | 主キー（`uuid.uuid4`） |
| user | ForeignKey | Django のログインユーザー（`settings.AUTH_USER_MODEL`） |
| executed_at | DateTimeField | 実行日時（`auto_now_add=True` 相当） |
| cust_code | CharField | 入力 `custCode` |
| cust_item | CharField | 入力 `custItem` |
| option_change | CharField | 入力 `optionChange` |
| year_month | CharField | 入力 `yearMonth` |

※対象日付（`asOfDate`）は **PostgreSQL には保存しない**（検索 API の入力としてのみ使用）。

API 応答では既存の契約に合わせ、Django モデルの snake_case を `id` / `executedAt` / `custCode` / `custItem` / `optionChange` / `yearMonth` に変換して返す。

## 6. Oracle 参照（論理）

### 6.1 一括検索

- 入口: Oracle 検索ユースケース（Django 側の infrastructure / application 層に配置）
- 取得する結果（概念）:
  - **内作品番**（`internalItemCd`）
  - **休日一覧**（`holidayDays`：1〜31 の日番号）
  - **得意先ブロック**（出荷側）
  - **TOTAL**（得意先複数時、集計データは Oracle JSON に保持しうるが、**Web / Excel では専用ブロックとして表示しない**）
  - **仕入先ブロック**（入荷側、BOM 展開）

### 6.1.1 内作品番の解決（`NAISAK_NOT_FOUND` の判定）

- `M_CUST_ITEM` を `CUST_CD`・`DLV_LOC_CD = '*'`・`CUST_ITEM_CD`・`ITEM_CD_OPTION_CHANGE_VALUE`（空は `*`）で検索し、`ITEM_CD` を取得。
- VBA `NAISAK_GET` に準拠し、該当行が複数ある場合は Recordset を最後まで走査した **最後の `ITEM_CD`** を採用する（`ORDER BY` や `ROWNUM = 1` による先頭採用はしない）。
- 有効期間は VBA と同じく `EFF_PHASE_IN_DATE <= :asOfDate` かつ `:asOfDate <= EFF_PHASE_OUT_DATE` とし、NULL を有効扱いにはしない。得意先品目プリフェッチも **同一条件**。

### 6.1.2 得意先ブロック（出荷側）

- `M_CUST_ITEM` と `M_CUST` を結合し、解決した **内作品番 `ITEM_CD`** に紐づく **全得意先行**を取得（`ITEM_CD_OPTION_CHANGE_VALUE`・有効期間・任意 `COMPANY_CD`）。
- 行が **0 件**のときは、入力された `custCode` で **フォールバック行**を 1 件合成し、その得意先コードで日次系列のみ取得する（名寄せ行が無いケースの表示継続）。

### 6.1.3 得意先側の日次系列（ソース表の対応）

| 区分ラベル（画面・Excel） | 概要（Oracle 側） |
|---------------------------|-------------------|
| 内示受注 | VBA `NAIJI_GET1` 準拠。`T_UNCNFM_ODR`（`UNCNFM_REQUIRED_DATE` × `UNCNFM_REQUIRED_QTY`）、`DEL_FLG = '0'` |
| 確定受注（前月残） | VBA `JUCHUZAN_GET` に準拠。`SUM(ODR_QTY) - SUM(TOTAL_SHIP_QTY)` を残数として集計し、`ODR_CMPLT_FLG != '1'`・`DEL_FLG != '1'` を対象にする。VBA と同じく基準日は `2022/10/01` 以前 |
| 確定受注（日次） | VBA `KAKUTEI_GET1` 準拠。`T_ODR.DESINATED_DLV_DATE` × `ODR_QTY`、`DEL_FLG != '1'` |
| 統合受注 | VBA `TOUGOU_GET1` 準拠。`T_UNITE_ODR.SHIP_PLAN_DATE` × `REQUIRED_QTY`、`DEL_FLG = '0'` |
| 出荷実績 | VBA `SKDATA_GET` 準拠。`T_SHIP.SHIP_DATE` × `SHIP_QTY`、`DEL_FLG != 1` |
| 売上実績 | VBA `URIAGE_GET` 準拠。`T_SALES_TEMP.SALES_DATE` × `SALES_QTY`、`DEL_FLG != '1'` かつ `ONEROUS_CONS_SALES_TYP != '1'` |
| 本日在庫（行計のみ） | `T_ITEM_STOCK` の **内作品番**に対する `STOCK_ON_HAND_QTY` 合計（日次列は空） |

### 6.1.4 仕入先ブロック（BOM・外注）

- VBA `HINBAN_list` / `KOTEI_GET2` に準拠し、BOM 展開の起点は **内作品番**に加えて、`M_ITEM.SUB_ITEM_CD_01`〜`SUB_ITEM_CD_05` に設定された関連品番を含める。
- `M_PS` を `CONNECT BY` で展開。親は上記起点品番、**有効期間は `asOfDate` で挟み込み**。
- 同一 `COMP_ITEM_CD` は **先頭のみ採用**（重複スキップ）。
- 構成子 `M_ITEM` の **`OUTSIDE_TYP` が `'2'`（外注）** の品目のみ対象。
- 仕入先は VBA `SICODE_GET2` に準拠し、`M_PUCH_UNIT_COST_H` と `M_VEND_CTRL`（`VEND_CD`）、`M_ITEM_RCV_WH`（`ITEM_CD`）を左結合し、Recordset を最後まで走査した **最後の行**を採用する。`ORDER BY` による優先順位先頭採用はしない。保管区は `M_ITEM_RCV_WH.WH_CD`、無ければ `?`。
- **手配区分**（帯表示用）: `M_ITEM.PROCESS_REQUEST_ISS_TYP = '1'` →「加工依頼」、`KANBAN_FLG = '1'` →「かんばん」、それ以外は空。

### 6.1.5 仕入先側の日次系列

| 区分ラベル | 概要 |
|------------|------|
| 月初発注 | VBA `NAIJI_GET2` に準拠。`T_U_MONTHLY_ODR_WORK`（管理年月・`VENDOR_CD`・`ARRIVAL_ITEM_CD`一致。`TRIM` や月のゼロ埋め比較は行わない）。`DAY_01`/`QTY_01`…`DAY_26`/`QTY_26` を日番号へ展開し、同一日付が複数回現れた場合は VBA のセル代入と同様に後勝ちで上書きする |
| 所要量 | VBA `SYOYOU_GET` に準拠。`T_OD` を起点に `T_RLSD_PUCH_ODR` を `OD_NO` で左結合し、`T_OD.PRD_DUE_DATE` × `T_OD.ODR_QTY` を日別集計する。`T_OD.OD_TYP = '2'` を対象にし、`T_RLSD_PUCH_ODR.ODR_CANCEL_SLIP_ISS_FLG` が `'0'` または NULL の行のみ集計する。VBA 同様、所要量行では仕入先コードによる絞り込みは行わない |
| 確定発注（前月残） | VBA `CHUZAN_GET` に準拠。`T_RLSD_PUCH_ODR` と `T_PAST_INSPC_ACPT` を `PUCH_ODR_CD` で左結合し、発注番号単位で `MAX(PUCH_ODR_QTY) - SUM(ACPT_QTY)` を算出して集計する。納期が検索月 1 日より前、`PUCH_ODR_STS_TYP = '2'`、`ODR_CANCEL_SLIP_ISS_FLG = '0'` を対象にする |
| 確定発注（日次） | VBA `KAKUTEI_GET2` に準拠。`T_RLSD_PUCH_ODR.PUCH_ODR_DLV_DATE` × `PUCH_ODR_QTY` を日別集計し、`PUCH_ODR_STS_TYP != '1'`、`ODR_CANCEL_SLIP_ISS_FLG = '0'` を対象にする |
| 入荷実績 | VBA `NYDATA_GET` に準拠。`T_PAST_INSPC_ACPT.ACPT_DATE` × `INSPC_ACPT_QTY` を日別集計する |
| 本日在庫 | 構成子品目の `T_ITEM_STOCK` 合計（日次列は空） |

### 6.1.6 休日（`M_CAL`）

- `HOLIDAY_FLG` を Trim し **`'0'` 以外または Null** を休日とみなす（VBA 相当の前提）。
- `CAL_DATE` は `YYYYMMDD` / `yyyy/mm/dd` / `yyyy-mm-dd` 等の揺れを吸収。取得に失敗した場合は **ログ出力のうえ空配列**（休日セル強調なしで継続）。

### 6.2 仕入先ブロックで使用する `M_PS` 列

- `LEVEL`（CONNECT BY の階層）を `kaiso` として保持する。
- `CONS_TYP` を保持し、表示上「支給区分」に変換して表示する。
  - 0: 非
  - 1: 有償支給
  - 2: 無償支給

## 7. 表示仕様（Web/Excel 共通）

### 7.1 セクション共通テーマ（見た目の固定）

結果表は「セクション」単位にテーマ色を割り当て、以下を**共通仕様**として適用する。

- **Web / Excel 共通の日次グリッド**: 日列は **31 列固定**（`GONEN_REPORT_GRID_DAYS = 31`）。当月に無い日は、Web / Excel とも `#b8c4d0` で空白セル化し、数値は空欄（§8）。
- **外枠**: 区分セルの上罫線・左罫線と同じ色（`section-border`）
- **台タイトル行**: 背景=基準色、見出し行全体に外枠を引く。
- **日付行（区分/行計/前月残/1日…）**: 背景=基準色、枠=やや薄い色（テーマ色）
- **休日列（M_CAL）**: 区分セルと同じ背景色・罫線色（`section-bg` / `section-border`）にする。休日セルと隣接する稼働日セルの境界線も `section-border` に合わせる。存在しない日付列は Web と同じ `#b8c4d0`。
- **左の区分セル（内示受注、月初発注等）**: 背景=すごく薄い色（テーマ色）
- **その他枠（グリッド）**: `#E2E8F0` 固定
- **Web データ部の下外枠**: 表データ最終行の下外枠は、存在しない日付列を含めて固定グレーではなく、区分セルの上罫線・左罫線と同じ当該セクション色（`section-border`）に合わせる。

### 7.2 基準色の割当（実装固定）

- 得意先セクション: index=1
- **TOTAL**: Oracle 結果 JSON に `customerTotals` として保持される場合があるが、**Web / Excel いずれも TOTAL 専用の表セクションは出さない**（テーマ index=2 の割当は実装上残存しうるが画面非表示）
- 仕入先セクション: index=2+`kaiso`（**同一階層は同一色**）

色生成のアルゴリズムは Django 側の `kaiso_color` 相当モジュールに準拠（黄金角 + HSL）。

## 8. Excel 出力仕様（実装固定）

### 8.1 出力方法

- 結果画面のボタン「Excelで出力」で、Django 側の Excel 出力 API にリクエストし、サーバー側で xlsx を生成してダウンロードする。
- 実装: Django 側の Excel 出力処理（openpyxl 等）
- **現行実装**: URL の検索年月（基準月）と `months` クエリに基づき、Web 画面で表示中の月パネルを出力する。初期表示では基準月のみ、前月／次月を追加した状態では追加済みの全月を対象とする。

### 8.2 ブック/シート/ファイル名

- シート名: `検索結果`
- 先頭タイトル行は出力しない。
- ファイル名: `{custCode}_{custItem}_{yyyyMM}_{yyyyMMddHHmmss}.xlsx`（東京時刻、禁止文字は `_` 置換）
- フォント: **MS PGothic（ＭＳ Ｐゴシック）**
- 数値: 千区切り `#,##0`。値が `0` のセルは空欄として出力する。

### 8.3 先頭（検索条件ブロック）

- A列に項目名、B列に検索条件値を縦に配置する。
- 表示内容の例: 得意先コード／得意先品目／品目任意変換値、検索年月（基準月のみ、`YYYY/MM` 表記）／対象日付／**内作品番**（基準月の Oracle 結果から）

### 8.4 セクション出力

各セクションは以下の順で出力する。複数月表示時は、Web 結果画面と同様に同一得意先／仕入先ブロック内へ月パネルを暦月昇順で縦に出力する。

1. 台タイトル（1 行）。1行全体を結合し、同一セル内にスペース区切りで表示する。得意先ブロックは「得意先：名称（コード） 出荷 得意先品目 手番 安全在庫」を表示する。仕入先ブロックは「仕入先：名称（コード） 入荷 品目番号 手番 安全在庫 手配区分 保管区 階層(n)」を表示する。
2. 月パネル見出し（前月／次月などは `YYYY/MM（前月）` / `YYYY/MM（次月）` 等。基準月は `YYYY/MM` のみで、`（基準）` は表示しない）
3. 日付行（`区分/行計/前月残/1日…31日` の 1 行。`対象` 列は出力しない。列数は常に 31 日分）
4. データ行（複数行）

**得意先ブロックの行順**（左の区分列）: 内示受注 → 確定受注 → 統合受注 → 出荷実績 → 売上実績 → 本日在庫（`block_rows` 相当の `CUSTOMER_ROW_SPECS`）。

**仕入先ブロックの行順**: 月初発注 → 所要量 → 確定発注 → 入荷実績 → 本日在庫（`SUPPLIER_ROW_SPECS`）。

### 8.5 色・罫線

7.1 の共通仕様を Excel に適用する。台タイトル・月パネル見出し・日付行・データ行は Web 結果画面の `block.theme`（`bg` / `lightBg` / `veryLightBg`）と同じ色を使う。休日の日別データセルは `block.theme.bg`、存在しない日付列は Web と同じ `#b8c4d0` とする。台タイトル行と月パネル範囲には外枠を引き、月表示行と区分行の間は濃いグレー系の細線にする。明細表の内側罫線は残す。得意先／仕入先など各セクション間の空白行には罫線を引かない。Web 側が HSL の場合は Excel 用 RGB に変換して出力する。

### 8.6 表示上のその他

- **ウィンドウ枠の固定**: 7行目と8行目の間で固定する（Excel の freeze panes は `A8` 相当）。
- **列幅**: 使用範囲の全列に VBA の `Range.AutoFit` 相当の自動調整を適用する。Excel 側の `bestFit` を有効化し、生成時にもセル内容から列幅を算出する。日本語など全角文字は半角より広い幅として扱い、結合セルは列幅計算から除外する。
